## Preserved report reviews/transformations.md

## Key Findings

1. The earlier run tested **selection more than invention**: all three primary arms chose the same model-best actions, and their open answers overlapped. A novelty investigation must require agents to generate mechanisms before seeing a candidate menu. Source: `runs/2026-10-08-execute-all/SYNTHESIS.md`, “Executed experiments” and “Limits.”
2. Evidence generation, decision rights, work removal, and bounded rules are already in the local baseline. Renaming delegation “distributed intelligence,” for example, cannot count as a new mechanism. Source: synthesis, “Inversion and destructive-to-creative results.”
3. An attack becomes generative when it exposes a **changeable dependency**, not merely an error to repair. Source: `ANALYSIS-LENSES.md`, “Attack to expand.”
4. Distill must follow expansion and preserve enough structure for testing. The earlier reduction lost owner, expiry, consumer, and unresolved evidence. Source: synthesis, “Actual observed findings”; lenses, “Composition.”

## Gaps

The prior case set does not establish what conditions make inversion generative, whether generated candidates differ causally from existing ones, or whether novelty survives feasibility checking. No source establishes global originality for the proposals below.

Use a local novelty fingerprint:

`preserved outcome / function performed / function carrier / causal relationship / timing / needed resource / decisive observable`

Compare fingerprints against the frozen catalog. A changed title, role name, or prompt sequence is insufficient. Count novelty separately from usefulness and feasibility; a new but infeasible hypothesis can still reveal a useful boundary.

## Local Tensions

- Preserving every implementation assumption prevents invention; changing the stakeholder outcome covertly invalidates comparison.
- Early feasibility rejection can erase unfamiliar candidates; indefinite exemption from constraints produces fiction.
- Distillation can clarify a new mechanism or collapse it back into the incumbent vocabulary.
- Known mechanism families can contain locally new implementations. Record the level of difference explicitly rather than awarding a single “novel” label.

## Questions for Synthesis

Which objects must remain fixed: the outcome, its current measure, or the current service contract? Which assumptions have identified owners who could change them? Is the target new questions, new mechanisms, or demonstrably useful interventions? These can be resolved through an explicit working contract without reopening permission.

## Six strategy proposals

### N1 — Move the function into an unexpected carrier

**Question:** “What else could perform the function before the familiar tool arrives?”

**Changed assumption:** The existing tool or specialist must carry the necessary function.

**Hammer example:** Preserve secure attachment, but make the receiving material or component geometry provide the grip. Self-locking geometry is a candidate mechanism; “use glue” without examining the function is merely a substitution.

**Review example:** Let a proposed change carry a checkable assurance package bound to its exact contents. Review effort then targets claims the package cannot establish, rather than rebuilding the complete assurance argument every time.

**Fingerprint:** Function carrier and where assurance/attachment is established change.

**Probe:** Compare two otherwise matched objects: one with the relocated function and one without. Test the required attachment load or assurance claims, including adversarial failures.

**Constraint:** Required strength and assurance remain fixed. Whether either can actually be relocated is empirical.

**Pseudonovelty check:** Delegating the same work unchanged to another agent does not qualify.

### N2 — Investigate whether the solution manufactures its demand

**Question:** “Which problems would stop appearing if the current solution stopped shaping the environment?”

**Changed assumption:** Demand is independent of the incumbent intervention.

**Hammer example:** A factory standardizes components around nail holes because it makes hammers. The apparent necessity of nails could be downstream of that standard.

**Review example:** Exhaustive approval requirements may encourage oversized submission batches and deferred clarification, which create the complexity used to justify exhaustive approval.

**Fingerprint:** Add and test a feedback path from intervention to demand, rather than accepting one-way problem → solution causation.

**Probe:** In a simulation or historical comparison, hold essential assurance constant while varying batching or intake rules; observe complexity, rework, and exception generation.

**Constraint:** Do not infer that removing review removes underlying risk.

**Pseudonovelty check:** “Bureaucracy causes bureaucracy” is rhetoric until a specific feedback edge and observable prediction exist.

### N3 — Remove the intermediate need by changing an interface

**Question:** “What would have to fit differently for this function to become unnecessary?”

**Changed assumption:** Achieving the stakeholder outcome requires the currently named intermediate task.

**Hammer example:** If the outcome is stable furniture, manufacture interlocking components so the assembly no longer needs a separate fastening operation.

**Review example:** If a review repeatedly resolves incompatibilities between teams, redesign the boundary so each party can change independently within an explicit compatibility contract. Some coordination reviews may then disappear.

**Fingerprint:** A dependency edge is removed; the outcome persists without completing the original intermediate task.

**Probe:** Enumerate the cases formerly handled by the task, then challenge the redesigned interface with those cases and boundary violations.

**Constraint:** Merely relabeling a required approval as “compatibility” is forbidden. Non-negotiable approvals remain.

**Pseudonovelty check:** Skipping work without removing the reason for it is not need elimination.

### N4 — Turn the attack into a functional input

**Question:** “Can the force that defeats the design become information, energy, or control for a different design?”

**Changed assumption:** Disturbance is exclusively a cost to resist.

**Hammer example:** Investigate a joint where load increases gripping action. The threatening load becomes part of the attachment mechanism, within material limits.

**Review example:** Treat independently discovered disagreement as a routing signal: cases with concentrated, evidenced disagreement receive specialist attention; routine agreement alone is insufficient to establish correctness.

**Fingerprint:** A harmful input gains a specified causal contribution to the desired function.

**Probe:** Apply controlled disturbances and measure both contribution and failure boundary. For reviews, inject known consequential disagreements and innocuous differences; test routing sensitivity and false positives.

**Constraint:** Do not create real harm to acquire a signal; use fixtures or simulation.

**Pseudonovelty check:** “Learn from failure” is too vague. Name the conversion mechanism and its measurable output.

### N5 — Invent from a deliberately missing dependency

**Question:** “If one presumed prerequisite were unavailable, what different physical or organizational arrangement could still produce the outcome?”

**Changed assumption:** A particular resource, timing condition, or central actor is indispensable.

**Hammer example:** Secure components when impact is prohibited. Generate mechanisms from tension, geometry, expansion, or external compression, then inspect what new dependencies they introduce.

**Review example:** Produce a bounded, auditable decision when the central reviewer is unavailable and authority cannot simply be delegated. Candidates might include precommitted conditional decisions or limiting the proposed change until its effects lie inside an already authorized envelope.

**Fingerprint:** The original dependency disappears and an explicit replacement mechanism/dependency appears.

**Probe:** Remove the dependency in a sandbox and test the complete outcome contract.

**Constraint:** If the unavailable actor’s live consent is a hard requirement, this operator must report infeasibility or propose an explicitly separate reframing.

**Pseudonovelty check:** Secretly restoring the missing resource through another actor fails.

### N6 — Change the unit of the problem, then translate back

**Question:** “What becomes visible when the problem is represented as a relation, trajectory, or maintained condition instead of an object or task?”

**Changed assumption:** The current unit of analysis is causally sufficient.

**Hammer example:** Replace “drive this nail” with “maintain this relationship between components through changing loads.” That opens adjustable, reversible, or self-correcting connections rather than merely alternative fasteners.

**Review example:** Replace “approve each submission” with “maintain justified operating permission as evidence changes.” Explore permissions that narrow or expire when specified evidence changes, subject to the organization’s actual authority rules.

**Fingerprint:** State variable, time horizon, and intervention trigger change.

**Probe:** Translate the proposed representation into concrete actions for three contrasting cases, including evidence degradation. Check whether it makes a different, testable prediction.

**Constraint:** A changed stakeholder outcome is labeled an exploratory reframing and assessed separately.

**Pseudonovelty check:** A metaphor that cannot translate back into operations generates no candidate.

## Shared preparation

Freeze the incumbent and earlier proposals as graphs: components, actors, resources, state transitions, dependencies, timing, and constraints. Give every candidate a **novelty fingerprint**:

> baseline → changed relationship → resulting capability → preserved constraints

Novelty is relative to this declared corpus, not a claim of worldwide originality. “A better process” and renamed nodes do not qualify. A strategy may legitimately produce zero novel candidates.

Use two stores: feasible candidates satisfying hard constraints, and speculative branches that explicitly name relaxed premises. Only feasible candidates compete for immediate adoption.

## 1. Transfer a distant mechanism through a constraint map

**Operator:** Find an unlike domain with a useful relationship; transfer that relationship through an explicit correspondence.

**Example:** For joining two boards, explore lacing: alternating attachment points distribute tension through a flexible member. The transferred idea is a load path, not “woodworking is like sewing.”

**Structural change:** Concentrated penetrating fasteners become distributed tension connections.

**Fingerprint:** `local penetration → distributed tension path`; compare with all existing joining alternatives before accepting novelty.

**Smallest unit:** One source mechanism, a target mapping, one failed correspondence, and one candidate joint.

**Probe:** Make a small mock-up under the same load, assembly-time, reversibility, and material constraints as the baseline. Reject if the required load cannot be held.

**Failure conditions:** Similar vocabulary without a transferable relationship; unmapped material assumptions; an attractive source mechanism whose prerequisites are unavailable.

**Composition:** Robot Talks assigns source-mechanism, target-constraint, and transfer-breakpoint concerns. Lane Z develops the incumbent; Lane A develops the mapped mechanism. Distill only after the breakpoint report; preserve the correspondence that makes the transfer different.

## 2. Recombine mechanisms at their interfaces

**Operator:** Cross components from different candidate families, but require the combination to create a capability neither parent supplies alone.

**Example:** Combine a temporary alignment fixture with a reversible interlocking joint. The fixture establishes geometry; the interlock carries the final load. Their interface allows accurate assembly without leaving the fixture installed.

**Structural change:** Alignment and load retention become separate cooperating mechanisms.

**Fingerprint:** `one component aligns and retains → temporary alignment hands geometry to persistent retention`.

**Smallest unit:** Two parent mechanisms, the interface contract, and one predicted interaction benefit.

**Probe:** Compare the hybrid against each parent alone on assembly error, retention, and disassembly. The hybrid must demonstrate its proposed interaction, not merely add both costs.

**Failure conditions:** Feature bundles without interaction; incompatible tolerances; a simpler parent already provides the entire capability.

**Composition:** Robot Talks investigates parent capabilities and interface failures independently. Lane Z tests the stronger parent; Lane A tests the hybrid. Distill must retain the interface and interaction hypothesis, rather than compressing the proposal to “combine both.”

## 3. Search for unused affordances and by-products

**Operator:** Inventory properties and traces already present but unused; ask what additional operation each makes possible.

**Example:** A review queue already contains successive versions and rejection annotations. Instead of merely generating another summary, propose a comparator that locates which changed dependency invalidated an earlier accepted claim.

**Structural change:** Historical records become inputs to selective invalidation rather than passive archives.

**Fingerprint:** `archive → dependency-sensitive validity update`. If the earlier corpus already contains this mechanism, record reuse rather than novelty.

**Smallest unit:** One available trace, one inferred affordance, and one proposed operation.

**Probe:** Seed revisions with known invalidated and unaffected claims. Test whether the comparator identifies both correctly without silently reusing stale assurance.

**Failure conditions:** The required trace does not exist; timestamps are mistaken for causal evidence; the proposal is simply “measure more” with additional terminology.

**Composition:** Robot Talks separates artifact inventory, plausible affordances, and evidence limits. Lane Z uses the existing records conventionally; Lane A activates one latent affordance. Distill after the provenance check, preserving the exact input-to-operation relationship.

## 4. Change time, scale, or boundary while preserving the outcome

**Operator:** Re-express the same problem at another temporal resolution, unit size, or system boundary. Change one dimension at a time before recombining.

**Example:** A queue treats a revised submission as an entirely new object. Explore reviewed subclaims with explicit dependencies: only affected subclaims reopen when the submission changes. Final approval still satisfies the original assurance requirement.

**Structural change:** Whole-request reset becomes dependency-governed state transitions.

**Fingerprint:** `request-level restart → subclaim validity and explicit recomposition`.

**Smallest unit:** One changed unit of analysis, its recomposition rule, and a case where decomposition is forbidden.

**Probe:** Introduce a cross-cutting revision. Does the system reopen every dependent claim and still block approval when required?

**Failure conditions:** Hidden coupling defeats decomposition; atomic obligations are split illegally; coordination costs exceed saved work.

**Composition:** Robot Talks assigns temporal, granularity, and boundary concerns. Lane Z retains the original unit; Lane A changes one unit. Distill only after recomposition demonstrates that the original outcome remains intact.

## 5. Protect anomalies long enough to generate a new mechanism

**Operator:** Retain a stubborn outlier instead of averaging it away or immediately patching it. Generate mechanisms that explain both ordinary and anomalous cases.

**Example:** Suppose a fastened joint holds static loads but loosens under repeated expansion. The anomaly opens a joint that retains against separation while permitting movement along another axis.

**Structural change:** Rigid restraint becomes selective restraint across different directions.

**Fingerprint:** `all-direction fixation → direction-specific movement and retention`.

**Smallest unit:** One documented anomaly, competing explanations, and one candidate discriminating between them.

**Probe:** Compare ordinary and cyclic conditions. Test both desired movement and forbidden separation.

**Failure conditions:** A hypothetical anomaly is presented as observed; noise is mistaken for structure; the candidate merely relocates the failure.

**Composition:** Robot Talks preserves independent explanations. Lane Z attempts the best ordinary repair; Lane A develops an anomaly-led mechanism. Delay Distill until both explanations have faced the same counterexample. Preserve unresolved anomalies as residue.

## 6. Describe a future object, then derive its missing capabilities

**Operator:** Describe a concrete object performing an apparently unavailable capability; work backward to required operations and present-day partial implementations.

**Example:** “A joint that tells the assembler which part of its load path is failing.” Derive sensing, localization, interpretation, and a usable signal. A present-day candidate might provide only a visible deformation indicator.

**Structural change:** Passive retention gains an observable state tied to a specific failure mode.

**Fingerprint:** `unobserved deterioration → localized, interpretable indication`.

**Smallest unit:** One future-object scene, a capability dependency chain, and one presently testable capability.

**Probe:** Induce the targeted failure in a mock-up. Does the proposed indicator appear early enough and distinguish failure from harmless variation?

**Failure conditions:** Magical capabilities conceal missing dependencies; the indicator adds unacceptable weakness; speculative resources silently enter the feasible branch.

**Composition:** Robot Talks separates desired capability, dependency feasibility, and user interpretation. Lane Z offers the best present object; Lane A works backward from the future object. Distill the dependency chain after identifying the smallest testable capability—not into a slogan that conceals the missing technology.

# Independent measurement design report

Role: Balancer and evaluation designer. Status: preparation only; no trials or live interventions executed. This report uses the prior run's SYNTHESIS.md and audit/experiment-review.json, followed by the parent's common-scaffold and resource refinements. It is not a literature review or a global-originality assessment.

## Concern and evidence

The previous study tested selecting appropriate actions more than inventing new possibilities. Its twelve fixed-choice cases produced identical selections, and its two open cases produced overlapping mechanism families. The audit also records single outputs per condition, authored cases, a single runtime family, and a capability-first control that already permits changing approaches when evidence warrants it. Those results support no local selection advantage. They do not establish equivalence or an absence of generative benefit.

A new question, explanation, system boundary, or previously unavailable intervention could disappear under an evaluator that checks selected action IDs. The next investigation must distinguish a substantive opening from a familiar alternative described attractively.

## Core tension: preservation and invention

Completely fixing the framing can exclude inventions that change what the problem means. Unrestricted reframing makes novelty cheap by permitting abandonment of the user's outcome.

Classify a commitment-preserving opening separately from an explicit frame branch. The first retains the beneficiary, valued outcome, and hard constraints. The second questions a metric, boundary, presumed need, or necessary step; it names each change and whose interests survive. A branch requiring relaxation of a hard constraint remains conditional, not a solution to the original task. Changing a premise is not evidence for that premise.

Attack-to-expand may finish without a new alternative. Invalid attacks, unchanged evidence, and immovable obligations are legitimate dispositions.

## Define substantive local novelty

Local novelty is a mechanism, causal hypothesis, discriminating question, or explicit frame branch absent from a frozen comparison archive. Freeze the archive from the old run and case briefing before treatment outputs exist. Keep it evaluator-only when showing it would supply a menu. An incomplete archive supports 'absent from this archive', never 'never previously imagined'. Worldwide originality requires a separate scoped investigation.

Also compare treatments against concurrent controls. A possibility can be new relative to the historical archive but appear under every condition. That does not establish an operator benefit.

Represent a mechanism by actor, changed operation, target, causal connection, operating condition, expected observation, and assumptions. 'Distributed approval' and 'qualified deputies with bounded approval rights' usually express one family. Better evidence packets and protected approver time can express different families: one changes reconstruction work; the other changes available attention. A combination counts separately only when an interaction or sequence changes expected behavior. Parameter changes can be useful without establishing a new family. Embedding distance alone is not a mechanism-identity test.

Questions count when they expose a new observable distinction. 'Why is review slow?' and 'Where is the bottleneck?' can express one diagnostic request. Asking whether mandatory approval causes batching before entry into the measured queue changes the boundary and predicts a different pattern. It can add novelty without supplying an immediate solution. These examples are evaluator calibration; exclude them and parent-generated clever sentences from generation packets.

## Assessment dimensions

Record a vector rather than one creativity score:

- Local novelty and the named comparison set.
- Potential usefulness, linked to an outcome or next decision.
- Constraint fit: preserving commitments, uncertain, explicitly conditional, or violating a hard constraint.
- Observability: the observation that would distinguish the proposal from its nearest rival.
- Evidence status: supplied evidence, inference, or untested possibility.
- Generation, review, and prospective implementation burden.
- Preservation through Distill.

A useful familiar idea remains useful. A novel unsupported idea remains a hypothesis. A proposed test is not an observed benefit. Anchored categories and reasons are appropriate; multiplying ordinal judgments into a precise-looking creativity score is not.

## Distill as a potential loss mechanism

Save raw exploration first and assign stable candidate IDs. Distill maps every candidate to retained, merged with constituent IDs, dropped with a reason, or parked. Assess whether the causal distinction, uncertainty, beneficiary, and next observation survive. Keeping a candidate's name while deleting its mechanism loses the idea.

Novelty retention is the number of accepted distinct local ideas intelligibly represented after Distill divided by the corresponding number before Distill. A zero denominator is undefined. Also report unsupported additions, increased certainty, missing beneficiaries, and minority ideas erased by merging.

A generator can contribute novelty while compression deletes it. A verbose exploration can become more useful after compression. Keep these outcomes distinct.

## Bounded comparative protocol

1. Freeze six open-response cases: two discovery cases, two untouched related-domain cases, and two untouched transfer cases from different domains. Include a case where the incumbent remains useful and one where a questionable boundary could matter. Supply evidence and constraints without answer menus or model-best keys. The case author should not tailor cases to favor operators. Freeze archives and criteria before treatment outputs exist.
2. Hold three generation roles constant: independent Lane Z ordinary incumbent/outcome analysis; independent Lane A alternative generation; and one common neutral Distill. Only Lane A's operator instruction changes. The lanes receive identical case evidence and cannot see sibling outputs before both are saved. This estimates operator effects conditional on the shared scaffold, not the scaffold's superiority. Strategies needing different role counts require a bounded Lane A adaptation or a separate workflow comparison.
3. Include ordinary-analysis and generic-creativity controls. The latter explicitly asks for unusual useful alternatives. Give controls the same schema, resource opportunity, and evidence as specific-operator treatments. This distinguishes a particular operator from simply requesting creativity.
4. Screen twelve operators and two controls on two discovery cases with two fresh repetitions: 56 scored runs. Use them to expose feasibility issues, equivalent mechanisms, constraint failures, and sampling variability. Freeze at most two distinct finalists; zero is valid. Prefer non-dominated contributions instead of a forced overall winner.
5. Compare finalists and both controls on four untouched cases with three fresh repetitions: at most 48 additional scored runs. Keep transfer cases sealed until prompts and selection rules are frozen. The ceiling is 104 scored runs. These are bounded discovery and repetition counts, not a power calculation or a population-level efficacy claim. Screening findings do not become confirmation evidence.
6. Use an identical three-call generation envelope: 900 output tokens for each lane and 600 for Distill, totaling 2,400 per scored run. Corresponding roles have equal prompt-token ceilings, tools, runtime settings, and candidate slots. At most 104 scored runs imply 312 generation calls and 249,600 allocated generated tokens before review. Declare preflights, retries, and review budgets separately. Count costs across all roles, including shared context. Equal allocations do not imply equal actual use. Where the runtime cannot enforce caps or expose usage, explicitly report matched instructions and soft ceilings, not equal compute. Word counts cannot establish equal computational effort.
7. Request up to four substantive openings per run, allowing fewer or zero. An opening can be a mechanism, question, hypothesis, or frame branch. Deduplicate mechanism families within each case/run. Preserve everything, and separately compare a fixed number of strongest candidates so longer lists do not automatically win.
8. Use fresh isolated contexts per case and repetition. Exclude sibling outputs, parent examples, prior rankings, and holdout contents. Randomize condition execution order with recorded seeds. Log missing runtime controls instead of implying perfect reproducibility. Generation evidence remains identical; the operator slot is the intended difference.
9. Present method-anonymous submissions in a common schema with randomized presentation order. Remove condition names and rhetorical flourishes while preserving meaning and uncertainty. A normalizer cannot repair a weak proposal. Prefer deterministic presentation transformations and retain the raw text plus reversible mappings. Two independent judges first classify mechanism identity and novelty against the archive, then assess the remaining dimensions and Distill lineage. Lock judgments before revealing conditions or the other judge's opinion. Retain disagreements; unresolved ambiguity remains uncertain. At the scored ceiling, two judges assess 208 raw/post-Distill pairs, plus separately bounded adjudication.

Distill timing stays fixed in this study. Test earlier versus later compression in a separate ablation. Similarly, compare complete bundles only in a later experiment; an observed bundle advantage cannot identify the helpful ingredient.

## Interpretation and completion

Report per-case distributions, repeated appearances, paired differences, family overlap, counterexamples, disagreements, and transfer failures. A finalist that repeatedly adds an assessable, potentially useful opening on untouched cases merits a later focused test. That is an advancement decision, not proof of superiority. Preserve control ties and absent effects. If generation helps but Distill deletes the contribution, investigate compression.

Each route should emit frozen evidence references, raw openings, assumption and branch labels, a blinded packet, Distill lineage, assessments, and a bounded next decision. Distinguish prepared, generated, independently assessed, and tested in the world. A useful unanswered question can complete an investigation stage without being confirmed.

Run two coupled investigations: which operators expand defensible possibilities, and which selection or compression practices preserve valuable expansion. The prior evidence supports judging what new mechanism, observation, or question becomes available. It supplies no reason to expect a particular operator to win.
