# Source boundaries and current policy checks

Status: candidate; qualification pending. Authority effect: none.

The real Session observation expired immediately after opening. The existing
source profile measured repeated full source and package validation as the
dominant cost. This successor composes the two independent obligations directly.

1. Run the full original source guard and each independently selected package
   checker before copying facts.
2. Construct the unchanged original `ReadScope` and `ExactSources` copy. Retain
   all original byte, schema, identity, version, witness and privacy validation.
3. Register that exact scope in the original thread-local registry. Invoke the
   real channel guard. Every policy byte, revocation flag, Actor, clock and budget
   is checked again; only the already guarded source selection may be borrowed.
4. Execute the synchronous pure calculation. The original registry consumers
   still reject foreign sources, hosts, threads, nested dispatch and effects.
5. Unregister the scope. Check the copy and run full original source and package
   exit guards. Recheck the same sealed copy after those full guards.
6. Register it only for the final real policy check, then unregister and close
   the copy. A failure at any boundary prevents return to the next writer.

This changes the v1 composition order: source validation and live permission
validation are proven separately at entry and exit. Channel guards borrow sealed
source selection during those checks; permissions are never cached. Original
callbacks, functions, schemas, fixed periods and deadlines remain unchanged.
The v1 implementation, evidence and registration protocol remain frozen.

The successor intentionally uses the original private registry so existing
consumers and dispatch prohibitions see the same scope. This coupling is explicit
and hash bound. It supplies no new public operation, governing role or grant.

Qualification requires all eighteen original checks, actual current API channel
checks for this composition, and the complete integrated successor suites. This
helper alone cannot qualify an Agent lifecycle or complete the plan.
