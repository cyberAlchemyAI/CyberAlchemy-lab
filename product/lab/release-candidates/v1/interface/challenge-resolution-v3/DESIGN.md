# Exact challenge resolution preparation

This candidate implements consequence preparation for `challenge.resolve`.
It returns a Change Proposal after exact source and prospective validation.
Canonical admission remains a separate operation and owner boundary.

## Independent authority

The private host policy selects original routing and method bindings. Routing
selects a current Principal and its independently recognized Ed25519 public key,
an exact signed gate, a Challenge, Contract, subject, Decision, response and
consequence proposals. The signed payload binds all selections, source cut,
scope, evidence, response obligations, effect mappings and expiry. A public
Decision body or an unsigned request cannot provide permission.

Development signers are ephemeral and owned by the isolated episode. The
verifier creates no signer, restores no original disposed key and extends no
source, policy or Session lifetime. A controlled development gate supplies no
R08 owner admission outcome.

## Response obligations

The original Contract declares challenger kinds, challengeable subjects,
grounds, required evidence kinds, response modes and owner/policy/gate/residue
routes. A private exact interpretation maps its response-period reference to
bounded seconds. The original response binds exact Challenge, Contract,
subject, owner, mode, evidence and timestamp. Source evidence bodies and their
kinds are verified through the original current-source resolver; vault bytes
alone cannot establish source membership. The Decision's evidence basis must
include this exact response.

## Distinct consequence axes

Semantic and governance proposals retain separate original bindings. The
result contains their ordered targets and their complete connections, schemas
and evidence, with shared entries deduplicated without rewriting values. Actor,
scope, source cut, source profile, workspace, key and challenge route agree.
Each signed route maps a declared Effect to an exact target and Decision Scope;
Effect references and target version references are different types.

The challenged version is retained unchanged. A proposed semantic successor
may retain its identity only with a new version and the exact challenged
predecessor. Validation uses the original bytes of every axis proposal, then
validates the composed proposal. Source checks run before and after the pure
calculation. Evidence staging uses the original guarded writer; completed,
failed and uncertain retries remain governed by the original journal.

## Evidence ceiling

The component tests exercise signatures, declared response obligations and
composition in isolation. Their Principal/header values are fixture inputs,
not current signed source records. They do not qualify the public handler,
transport, journal, source adapter, authority recognition or full Lab.

A positive public qualification requires a freshly owned signed source episode
with the exact Challenge, Principal, Contract, Decision, Effects, Scopes and
evidence. Current Source5 does not contain that complete closure. Frozen
predecessors and their failed observations remain preserved.

## Exact gate object selection

The gate is an independently selected immutable workspace object. Putting it
in the manifest input list would make its signature depend on proposals whose
workspace binding includes that same gate hash, a circular content identity.
The private routing binds the exact gate object namespace and digest; its
signature still binds the recognized Principal and every selected proposal.
Only this selected gate is read through object_read. Arbitrary request fields
cannot expand input-material access. Version1 and its evidence remain frozen.
