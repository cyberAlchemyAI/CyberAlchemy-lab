# Exact original body scope routes

The independently selected 0276 inventory has 363 original members. Exactly 230
bodies retain scopes outside the original Project store: 220 private O06 metadata
carriers, six W06 bodies, and four other bodies. Their six distinct scope strings,
member identities, original target/origin bindings, original preparation, carrier,
schema, descriptor and body digests remain separate and unchanged.

The 220 private carriers are 131 Source, 50 OntologyEdge, 38 OntologyNode and one
GeneratedOutput. This component opens none of those bodies. It also opens none
of the other ten original bodies. It uses already selected inert metadata and
preparation/postimage references; it never searches missing counterparts, scans
private source bodies, copies payloads, changes a body scope or exports a body.

`routing.py` supplies exact per-member selection and six grouped domain consumer
candidates. Review packaging code is bound as current selected preparation code,
not asserted as proof of historical generator execution. The full original
target/origin binding chains remain available without importing their bodies.
Changed scopes/digests, omitted or duplicate members, false current grants,
invented owner assignments and public body delivery refuse.

The original reviewed correction profile permits only exact Typed Relation
revisions in `scope:cyberalchemy-lab-first-agent-episode`. These 230 members are
Artifact instance admissions in other scopes. That existing profile cannot grant
their routes. Its original declared members, descriptor/schema requirements and
approval mechanism are retained; no profile or allowlist is widened.

`original_consumer.py` calls the unmodified original `O.prepare` with its original
historical Project configuration and a minimal literal scope witness. For every
member it checks both failures: a Project proposal carrying the original domain
scope is refused as a target outside authorized scope, and a domain proposal is
refused as outside the provisioned Project scope. The original function supplies
the causal error location before carrier/body access; neither source configuration
nor projection is mutated. These probes prove the scope gate, not full body
validation, schema compatibility, signed authorization or a successful consumer.

Repository promotion is also not a bypass: its original preparation requires
previously locally committed target versions and prepares public record material.
These bodies lack a valid Project-store commit, and their original private body
export exclusion remains binding. A different legitimate consumer/design needs
explicit selection and its own reviewed scope/access contract.

All six proposed routes still require independently grounded domain provisioning
or an explicitly reviewed compatible consumer, current governing owner assignments
and periods, exact member response, protected private access, current source cut,
and full original-byte/schema/preimage validation. Historical fixture configuration,
scope names, proposed role labels and route metadata grant none of these. The
component therefore refuses operational preflight and original-body export.

The final checks audit every original body path against actual Python open events,
including route construction, and exercise original consumer refusals and route
mutation negatives. `noBodyCopyPrivate` and private export counters remain zero.
No RoleAssignment, actual owner response, private key, live store change, canonical
admission or shared API17 route selection is created here. T11 remains incomplete
until the independent authorization/access and actual per-body consumer criteria
are met.
