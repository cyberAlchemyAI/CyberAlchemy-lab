# Same signed source cut for future operator context

This candidate adapter connects fresh participation preflight to the actual API
reader's independently selected signed branch. The C12 context fixture remains a
different branch. Neither its Project State nor its native fixture is substituted
for an API source cut.

The trusted factory opens the immutable API reader, which verifies original
configuration, signatures, Decision cores, consequences and projection. The
adapter selects only current domain instances under an explicit carrier list.
It retains API Artifact References and original bytes without rewriting bodies.
An embedded legacy record uses its already declared inherited JSON encoding;
its enclosing transaction hash, selector and encoding stay separate provenance.
This encoding is not the incoming-file original-byte protocol needed by future
admission.apply and materialization.

Schema bytes come from the same captured baseline and exact contract. Catalog
descriptors, historical instances, protected Session memory, incompatible schemas
and bodies are accounted for as exclusions. Exclusions never become fabricated
current records. Source guards check the selected archives, expected replay,
configuration, original transaction byte map, captured projection, executable
guards and baseline material currentness before each consumption. A closed reader
or any changed binding invalidates the adapter.

The adapter exposes bounded metadata and an ExactSources resolver for trusted
host integration. It creates no Context/Ontology View, Agent, Session, permission,
admission or native mapping. Its closure report identifies missing current Goal,
Coordination Context and Project State independently from an old eligible Agent
instance. Missing participation must be supplied in a separately constructed
owned candidate branch before operational context can be ready.

Protocol syntax, real host authentication, absolute period resolution, fresh
identity/classification, native ontology cut mapping, delivery custody and public
API dispatch remain separate requirements. Review this adapter and its source
encoding/protection policy as explicit S02/R08 members.

Product Identity/v2 explicitly uses the independently verified source revision
witness rule. Both its signed reference and original body version are retained.
All other selected carrier kinds keep body-version/reference equality.
