# Catalog representation and endpoint correction successor

Candidate development only. Four of the original 34 API operations are implemented. Prior reader packages, original domain schemas, admitted source bodies and Decisions remain bound to their original bytes.

## Independent contracts

The new API call/reply discriminator is `v2-candidate`. `artifact.inspect` returns a versioned result with either the original domain instance envelope or a separate, exact catalog representation envelope. The latter is a closed representation of the 143 captured catalog versions, including seven declarations embedded in Artifact Type/v1. It is not a general schema that admits future descriptors.

The host independently selects `contract-profile.json` by its SHA at process startup. It binds actual code, wire/result schemas, exact representation map and original 790-file schema closure. Every call selects this profile. Only `lab.status` permits a null profile for discovery; replies expose the actual binding. Prior wire versions are refused explicitly.

## Declared catalog representation

A root or standalone descriptor retains its original whole-file body bytes. An embedded declaration uses its exact `/registered_types/N` entry, original parent file binding and the inherited canonical JSON encoding. Its catalog identity is the stem of its represented carrier version; the original containing descriptor identity and bytes are preserved separately. The represented instance contract and the classification metatype remain distinct.

The source-specific schema binds the exact body, represented version, metatype, selected byte identity, enclosing source binding and selector. Domain instance schema conformance is evaluated independently. All 133 prior domain-body mismatches remain failures under their original contracts; declaring an honest metadata representation does not erase them or manufacture an instance.

Canonical and disposable SQLite reads use the same declared identities, byte references, selected structural digests and source locators. Correcting the seven embedded entries removes the prior false current-head collision. Admission, runtime observations and outcomes remain separate facets. The original captured subjects are unchanged. Returned catalog and domain bodies are copied so consumer mutations cannot change the verified in-memory source.

## Ten connection correction candidates

Each member in `connection-corrections/` contains an exact postimage and an independent review record. It binds the old admitted source bytes, predecessor, new candidate version, changed endpoint version selectors, exact endpoint bytes, original admission overlay, semantic kind, Relation Kind signature and instance schema.

The change replaces an absent `@candidate.1` endpoint with its originally admitted `@foundation.1` or `@bootstrap.1` revision. It preserves authored identity, kind, qualifier, domain scope and every other field. It does not point a past connection at the current Project merely to satisfy a write guard.

All ten corrections validate as historical connections. Three Project endpoints are historical in the selected signed cut and fail the existing current-write guard. Historical validation proves endpoint closure, not authority to apply a revision. The exact domain scope, a declared historical correction write profile, independently scoped owner outcomes, signed application and recovery evidence are still required. No alias, source rewrite or transaction application occurs here. Original query traversal continues to report the ten unclosed connections until approved corrections are actually applied.

## Validation and scope

Inherited authentication, framing, budgets, actor, source freshness, cursor, original byte identity, SQLite integrity and cold reconstruction guards are retained. New checks cover protocol selection, exact metadata/instance separation, embedded selectors, parent bindings, corrected SQL identities and the ten preserved-original correction records. Actual child-process examples exercise both full descriptors and embedded declarations.

This successor leaves thirty handlers, complete persistent projection/ontology/workflow integration, Agent/session and human pilot requirements, S02/R08 and admission/operation/release boundaries outstanding.
