# Fresh source input capture — T03 candidate

This separately selected kernel verifies every input byte and SHA in the original manifest order. Within one synchronous complete table scan it retains no-follow ancestor descriptors so repeated inputs under the same directories reuse path traversal. Each leaf remains a fresh open, read, SHA and before/after identity check. All retained leaf and ancestor attachments are checked again before the result returns. A complete table scan streams bytes for hashing; an individual capture returns the same checked bytes. Neither operation retains a byte or trust cache after its invocation.

Only an independently selected captured loader can initialize this module. Its real source origin and `selected_source_sha256` must be provided by the caller's verified loader. Each operation requires the caller's explicit code SHA. There is no self-digest fallback. Kernel bytes, callback identities and directory attachments are checked at operation boundaries. A changed callback cannot disable its own check: the kernel uses direct rejection before and after its code check, and the scope retains original check, read, directory and close functions. The staged Source caller independently binds the module and entry function identities outside this module and checks them before and after invocation.

The five staged producer-chain postimages belong to a prospective distinct Source8 family. They do not change the frozen diagnostic family. Source and mapper verification, reader guard, Context preflight and mapped-package preparation retain every existing domain check and every signed/native replay. Their complete table loops use this kernel. Metadata selection captures the independently pinned manifest once and parses precisely those returned bytes. All original permission, UTC, nonce, source cut, schema, read-only calculation and effect boundary checks remain obligations in their original callers. This byte-table scope supplies no permission, expiry, Actor, role, or full-history proof and accepts no effect callback.

Focused evidence contains 29 input/kernel/entry/callback/nested/exception controls and five exact staged metadata-prefix controls. New owned kernel clones and inert metadata were deliberately changed; original producer/API callbacks were never replaced. An unchanged real Source verifier and the successor kernel each checked all 1,263 actual source rows on three unprofiled runs. Warm full original guard runs were roughly 0.55 seconds; successor file-table runs were roughly 0.36–0.38 seconds. These scopes differ because the old guard also checks metadata and environment. They do not prove whole-path speed, a remaining lease margin, complete Context generation, Session learning or operational readiness.

Before execution the coordinator must select the helper and five postimages by exact digest, construct a distinct complete Source8 family, retain every original source/history/schema/profile row, and capture new real source/profile/schema-execution origins. Independent review and actual unprofiled context/open/select/apply/assess/inspect/close qualification remain required. No frozen code, old period, private state or Session RAM is modified by this component.
