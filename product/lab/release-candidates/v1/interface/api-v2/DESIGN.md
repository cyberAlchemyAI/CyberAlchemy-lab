# Successor exact artifact reader

This private candidate extends the original authenticated reader with `artifact.inspect` and `artifact.query`. Four of the original 34 API operations are implemented. The preceding package and its immutable receipt remain unchanged.

## Exact identity and scope

The artifact reference names the selected archive read namespace, identity, exact version, carrier and encoded byte SHA. The archive namespace grants read access to its captured dependency closure; the body retains its independent authored domain scope. No authentication or query grants canonical owner authority.

Whole-file subjects retain original file bytes and SHA. Values selected from original signed transactions use the inherited canonical JSON encoding and disclose their containing original file separately. Structural digests remain distinct. Carrier resolution uses captured instance metadata, exact authored classification, or the one independently captured Relation Kind discriminator.

## Inspection

The handler checks every requested header field against the exact signed cut. It exposes only requested body, contract, authority, relations, provenance, evidence and gap sections. Required status facets are independent and do not infer runtime observation or outcome from admission. Omitted authority has no nested admission evidence bindings in a body envelope.

Every included body validates the original exact domain dispatcher. Some Artifact Type descriptors classify under a root whose schema accepts only its own root record. Those exact bytes remain inspectable through the existing CLI, and metadata remains queryable. This API returns an explicit contract error for their body instead of asserting conformance. Descriptor-envelope coverage remains an unfinished R03 schema obligation.

Signature lookup keys and Relation Kind subject identities are distinct. A projected connection resolves the exact captured signature bytes and its actual subject revision, validates the original endpoint-pair/qualifier schema and preserves directed raw semantic endpoint kinds alongside their carrier references. Unclosed connections are reported as gaps and confer no permission.

## Query semantics

Carrier and identity selectors choose exact seed revisions. `max_depth` controls incident-edge breadth-first expansion over the requested closed Relation Kinds. Connections preserve their original source/target direction; traversal creates no inverse semantic relation. Neighbor references can have other carriers. A page returns sorted exact revision references and incident selected edges for that page.

The reader enforces one authenticated archive scope, at most 143 carrier selectors, 100 identity selectors, depth four, 1,000 result/edge items and 256 cursors. Paging binds the full query selectors, Principal/context/scope, applied cut, read basis, freshness and exact generation. Changing any bound selector invalidates the cursor.

`current` requires the independently selected saved HEAD and unchanged captured repository material. `exact-historical` selects an earlier verified prefix with unchanged original materials. `allow-stale` permits metadata reads from a verified captured prefix after source material drift; it never substitutes changed source bytes or grants current operational authority. Unknown prefixes remain refused. Requested and applied cuts, freshness and basis are disclosed separately.

## Disposable SQLite

The projector uses the original exact SQL DDL in a newly owned temporary generation. It inserts captured revisions, independent status facets, exact contract bindings, validated global Typed Relations, available original-byte cache entries, stream watermarks and gaps. Source package and entry locators remain explicit. Missing authority facts, reference-resolution rows and ontology joins are not fabricated.

Admission posture does not select a unique current head. A head row requires exactly one captured current revision for its identity; ambiguous current identities remain explicit gaps with every revision retained.

The host captures expected generation metadata, rows and file SHA outside the database. Reads verify source/projector/DDL compatibility, exact cut/watermarks, row digest, active pointer, SQLite integrity and foreign keys. The ready label is insufficient. SQL results are also compared to canonical selection from signed replay. SQL values are parameterized and client text never becomes SQL syntax.

`projection` refuses missing/corrupt/inconsistent generations. `prefer-projection` discloses a fallback to canonical reads. Closing the connection deletes its generation; cold reconstruction uses fresh original signature replay and a new generation identity. This local generation proves no general ontology join, complete persistent query service, workload advantage or SLA. The `projection.refresh` API remains unfinished.
