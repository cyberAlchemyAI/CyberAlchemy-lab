# Isolated authenticated Action integration

This additive package implements public `action.evaluate`, `action.dispatch`, and `action.reconcile` against the unchanged original API operation catalog and v2 envelopes selected by frozen `api-integration-v6`. Its separate Action contract profile names the three implemented operations and binds that frozen reader profile. The Source5 reader Profile and its empty Tool classes remain unchanged.

`fixture.OwnedActor` provisions a new `/tmp` fixture with a separately signed original-byte Action source, an independent mode-0600 scoped grant, and a mode-0600 channel policy. It creates a fresh `SessionLease` using `time.time`; the signed Instance and Session carriers bind that actual lease's instance and session handles. Role, Assignment, Delegation and grant resolve only this fresh owned scope and UTC period. The Action Profile permits only Agent Action output and the bounded counter Tool class. All credential keys are newly generated in memory, and none are written into this package or exported in receipts.

`runtime.ActionChannel` verifies a one-use Ed25519 nonce tied to host, connection, policy hash and expiry. Authentication returns the original trusted-context contract with the exact independently selected Actor, RoleAssignment, Instance, Session and Assignment. Every public operation rereads the current private policy, signed source, grant and current authority status. Dispatch rechecks actual current authority through W02 under the effect lock, and again after the durable pending checkpoint. Message Actor fields are comparisons against authenticated host state, never grants.

`service.ActionService` requires independent `source_sha256` and `profile_sha256` pins at construction. It checks the original API call and result schemas, exact source cut, Assignment, Delegation, Tool bytes, input/output contracts, original input material, local filesystem scope, empty network scope, caller budgets, and the strictest live call/message/grant/session deadline. Its JCS idempotency namespaces include authenticated Principal, delegated authority scope, exact selected scope, operation and key. Exact retries return original recorded domain bytes after fresh current authorization; conflicting semantics refuse. An evaluation does not permit a later dispatch.

The actual Tool is the qualified W02 local counter. It can only write its closed state file in the newly owned ledger. The W02 pending journal is fsynced before effect, and an independent private checkpoint stores its exact pins. API pending metadata is also persisted before dispatch. Observed outputs and schema-valid Agent Action records are original-byte bound in owned materials. An uncertain key never invokes the Tool again. Recovery requires the exact recorded Action receipt, original observed residue, qualified dispatch recovery code binding and independent current recovery authority; it only observes the counter state and preserves committed journal history.

`bridge.IntegrationService(base_service, action_service)` is one public `.call(raw)` entrypoint routing the three Action names to the independently authenticated Action channel and other names to an actual frozen `Service`. Both handlers must share one exact `Schemas` object. The caller context/profile selects the applicable authority channel. Hosts integrating additional additive operations can use the same ActionService `.call(raw)` route without giving the reader action authority. Closing the common dispatcher closes both runtime channels.

The focused tests execute authenticated public messages and actual counter effects. Separate OS child processes terminate after the durable pending checkpoint or after the actual counter commit, preserving real on-disk uncertainty. Subsequent public dispatch returns the pending result without executing the tool; public reconciliation observes completion or failure. Interruption wrappers exist only inside the test child process. Production request bytes expose no interruption hook, arbitrary path, command, callback, network access or external effect.

These are isolated development authority records seeded from the admitted artifact carrier schemas and adapted to a fresh scope. They are not admitted canonical identities, a persisted operational actor, a human R08 outcome, or proof of whole API qualification. No canonical/live store, live credential, service activation, publication or deployment is used. The separately signed source and grant are fixture resources; a real deployment must supply its independently selected action actor and grant rather than call fixture provisioning.

`EXECUTION-DEPENDENCIES.json` separates execution selection from historical qualification closure. It binds the exact frozen parent manifest/profile, gives a reason for every mandatory file, and records actual schema/dependency imports and original file-read witnesses from selector construction. Every call/effect hashes selected files afresh through anchored filesystem reads. Unselected repository code imports refuse, including imports from unselected wheel archives. The unchanged original `Schemas.guard` still checks its full schema/profile closure per public call. Complete 21,670-file frozen history verification runs at qualification entry/exit; the preserved first smoke run also checked that broad history at each effect boundary. No cross-call source, digest, clock or permission cache is introduced.

The v2 successor accepts an optional constructor-only `integration_profile_binding`. It must equal the shared `Schemas.profile_binding`, declare the three contributed action operations, preserve the exact original operation catalog and protocol URI mapping, and be bound into the Action channel policy and cryptographic nonce before authentication. Every call/effect rereads its selected original profile bytes. Replies carry that same selected shared binding; request bytes and their original hashes are preserved. Existing Reader or Action channels cannot be rebound after authentication.

The shared qualification adapter uses the actual API7 `Schemas` object and its unchanged registry/validators with an independently selected 29-operation profile (API7's 26 plus Action3). This proves schema compatibility and common profile selection only. The parent's final common successor may pass its own shared 34-operation `Schemas` object directly; this package does not claim final all-34 integration.

The independently granted original `operation.inspect` reads this owned Action journal by action operation/key or exact original call binding. It rechecks the actual Actor, source, UTC lease, current role/delegation/grant and read budget, then reads the independently checkpointed ledger without Tool execution or reconciliation. It can observe recorded evaluation/recovery results, pending effects and completed actions. A recovered ledger completion is reported from its actual recovery receipt while preserving the original uncertain public receipt. Unknown keys and foreign Actors refuse. The common parent facade can route with `ActionService.owns_inspection(message)` and then call the same public dispatcher; it need not use the legacy bridge's frozen type restriction.


Action3 is a fresh successor for original early transport conformance. It preserves the original 19 qualification methods, adding three actual unauthenticated/malformed/invalid-envelope boundary tests. Each refusal validates the original transport-error schema, exact original input digest, required safe public message, no private controlled marker in output, and unchanged counter/ledger bytes. No Action2 qualification is transferred. Actual new source/profile pins and full historical entry/exit guards govern its own run.
