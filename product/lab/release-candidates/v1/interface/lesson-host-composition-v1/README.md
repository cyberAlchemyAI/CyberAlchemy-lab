# Lesson selection host composition

Candidate implementation for the original `lesson.select` contract. Qualification
of the actual public empty and nonempty signed-source paths remains pending.

An independently provisioned successor policy selects a closed host plan before
the Session opens. The plan selects exact source facts, scoped instructions,
domain profile values and complete per-Lesson review/applicability/retention and
exclusion witnesses. It grants read permission only. It supplies no current
Session identity, review truth, Application or owner outcome by itself.

The handler requires the actual API51 Service and authenticated MachinePeer,
selected parent host, its current signed reader and its real live Session resource.
It verifies original participation eligibility, exact Assignment/Work/Coordination
bindings and current instruction policy. Session-specific internal routing and
fact witnesses are generated only after those joins succeed. Caller dataclasses
or reconstructed Session metadata cannot replace the resource.

Current inventory comes from both declared carrier semantics and projected kinds.
Unknown current Lessons block closure; routing covers the whole ordered inventory.
Review effective state is taken from the actual signed subject; independently
selected controlled-use disposition and fixture posture must match exact original
review bytes. They provide no genuine semantic owner review. Evidence and
counterevidence resolve through current original subjects or selected material.

The v2 pure evaluator processes explicit request exclusions before eligible
conflict pairs. All56 v1 tests are retained. Candidate computation uses the
declared sealed read scope with original callbacks and full source guards at exit.
Derived check/selection evidence is written only to the owned Vault after that
exit. No operation claim, domain admission, Application or external effect occurs.

All transient original/routing working maps are cleared after the call. Disposal
remains owned by the actual Session and MachinePeer; no second disposal hook or
restoration path is introduced. Durable continuity remains Project State through
Context and Ontology Views. Nonempty actual signed source, generic context/ontology
composition and the full public regression remain verification obligations.
