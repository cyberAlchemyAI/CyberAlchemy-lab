# Exact resolution reference roles

Candidate implementation for one independently selected Source8 resolution
episode. Existing construction authorization covers development and isolated
validation. Admission remains the final R08 owner checkpoint.

| Reference | Meaning | Required proof |
| --- | --- | --- |
| Work project, goals and inputs | Current artifact references | Unique current original at the exact prospective cut; Goal Project scope additionally requires its independently selected exact current member-of Typed Relation |
| Work output `protocol:R03-fresh-context-delivery` | Expected output protocol declaration | Exact independently selected context-delivery schema, pending Work, original Work Definition |
| Challenge subject version | Exact version challenged | Original header, retained signed bytes, original current cut; historical after prospective revision is eligible only for this role |
| Challenge Contract and challenger | Current governed references | Exact selected original Contract and Principal, kinds and scope |
| Challenge evidence | Exact evidence inventory | Independently selected original bindings and artifact headers |
| Resolution Decision | Current exact Decision | Signed gate, exact consequences and Decision Scopes, independently selected current Decision |
| Challenge response/residue | Transition and obligations | Responded unresolved predecessor, verified response, resolved-for-revision successor, explicit empty residue |

## Example

Work revision 2 still expects a context-delivery protocol. This does not assert
that a Context View was delivered or that Work is completed. Its output
declaration is excluded from the artifact-revision report slot and resolved by
a separate protocol-declaration check, with its exact schema binding in evidence.

A Challenge revision 2 keeps `subject_version_ref` pointing to Work revision 1.
When Work revision 2 is prospective, revision 1 becomes historical. Its original
bytes are still eligible as the challenged version. This grants no current
participation or effect permission and creates no Typed Relation for revision 2.

## Selection and validation

The closed private policy v3 independently binds both resolver code and the
exact reference-role contract. The signed Source8 gate and proposals remain
unchanged. The resolver is installed only around their three native validation
calls and removed on every exit. Public input cannot install it. Other carriers,
proposals, cuts, outcomes, Work completion states and historical-reference roles
retain their original eligibility checks or refusal.

API91 retains all 323 inherited test method ASTs. Full inherited qualification,
new Agent context, lesson applicability and all remaining plan criteria are still
required; this package supplies no admission or whole Lab completion.

Goal/v1 has no scope_ref field. Its Project scope is proven by the exact current
member-of Typed Relation from that Goal version to the selected current Project
version, with original bytes retained. Source custody scope alone is insufficient.
