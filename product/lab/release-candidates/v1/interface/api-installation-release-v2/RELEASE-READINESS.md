# Exact release readiness contract

This successor can prepare a `ready` proposal-review once independently selected actual evidence closes the exact candidate. Returning `ready` prepares final review; it does not approve release, publish, install, activate services, admit canonical artifacts, create a human response or create the final R08 Decision.

The private installation/release custody plan selects a `lab-release-readiness-contract/v1-candidate` binding independently of the public ReleaseManifest. That contract selects the exact manifest/cut, actual predeclared `release-scope.json`, all thirteen AC01–AC13 obligations, the six evidence classes, reviewer public keys/current active person RoleAssignments, and prior owner prerequisites where required. No new reviewer trust or role is inferred from the public request.

Each evidence requirement selects exact `lab-release-readiness-evidence/v1-candidate` bytes and a separate Ed25519 attestation. The signed payload binds the evidence, candidate manifest, source cut, named obligations, evidence class, Principal and exact current RoleAssignment. Both material bytes and independent key/role selection are checked afresh. Unknown, inactive, expired, mismatched or missing reviewers block the affected condition. Actual cryptography does not by itself establish the factual truth of an observation; the independently assigned reviewer attests the bound original observations.

Required classes:

- API qualification: exact current API source/profile; all original34operations implemented; all323original cases retained; a complete PASS aggregate with every case passing; actual successful terminal records; actual schema-valid public calls covering all34operations. Full frozen source guard remains required.
- Human pilot: exact predeclared R05 protocol and episode/permission records; actual enrollment and usefulness responses with their custody source; genuine engineering, research and fresh-Session attempts; real start/end/duration, questions, criteria, answers, operation bindings and negative findings. Fixture evidence is refused. Missing baseline prohibits an improvement claim.
- Acceptance: independently reviewed actual measurements for every named AC condition, preserving candidate operation scope.
- Privacy: exact manifest privacy-review binding, complete implementation/package material coverage and explicit absence of private credential/Session memory export. Candidate preparation grants no publication permission.
- Installation: actual original-schema installation/rollback receipts, exact selected environment, complete verified postimage/evidence bindings and zero service activation.
- Review closure: exact complete candidate member list, no unresolved selected gaps, reviewed acyclic digest graph and resolved prior owner prerequisites. The final R08 release Decision is still required after preparation.

Readiness is dynamic: missing inputs produce blocking gaps; complete valid actual inputs can produce `ready-for-final-review`. Current fixture obligations remain missing. The tests create no positive whole-Lab readiness, human pilot or owner outcome.

The implementation uses the already qualified `guarded_candidate.selection` only to group pure preflight reads. Full original signed-source checks occur at scope entry/exit, grants use real clocks, and no durable installation/evidence publication occurs inside that scope. Actual Vault.guard already performs the selected ReaderChannel.guard. Publication, active-descriptor commit, recording and exit retain actual source/permission callbacks outside the pure scope.
