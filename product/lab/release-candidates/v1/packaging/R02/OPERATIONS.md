# Candidate installation and recovery runbook

Use the independently reviewed `packages/0001/selection.json` digest and exact source-manifest digest. Verify the selected Python binary, Python/SQLite versions, architecture and libc before any installation. Never substitute current global dependency versions for the eight selected wheel versions.

1. Supply an explicit `OwnedScope` for an already created isolated candidate parent directory. Call `install(package, digest, destination, scope)` for a new destination. The installer validates all source and wheel hashes, preserves canonical relative paths, extracts only selected wheel bytes, rechecks every staged byte, and publishes with Linux `RENAME_NOREPLACE`. It creates no store, key, authority configuration or service.
2. Start selected installed entrypoints with the selected interpreter's `-I -S` flags and installed `repo/product/lab/release-candidates/v1/packaging/R02/installed.py`. Global site packages and Session memory are absent. Current entrypoints are the actual lifecycle proof and frozen transition regression; full product entrypoints require the R03/S02 successor payload.
3. An interrupted installation preserves `.destination.install-DIGEST`. Retry the same package. A complete exact stage is published; a complete exact destination returns idempotently. An incomplete or foreign stage is retained and rejected. Investigate it; select a fresh destination rather than deleting evidence automatically.
4. Create candidate operator keys outside code/package material with restrictive permissions. Upgrade uses the existing exact C05 D74 parent, independently pinned replay, reviewed D75 profile, explicit carry/exclude members and new signed candidate transition. Never edit parent transactions or copy old signatures to grant successor admission. Interruptions at transition stage/publish resume through the existing cold-verifying transition procedure.
5. `export_legacy` first performs full replay, selects only config, exact baseline, committed HEAD and transactions up to the selected cut, checks privacy and rechecks the same cut. `export_successor` performs exact cold successor replay and exports its closed selected files. Public verification keys and exact signed candidate effects are evidence; private keys and uncommitted Session notes are excluded. Persist the returned archive digest independently with the original replay/profile/code pins.
6. `restore` accepts the independent archive digest and a new owned destination, verifies all original byte hashes and privacy, durably stages and publishes without replacement. Existing unrelated state is rejected. Interrupted complete recovery stages can resume; incomplete ones remain for investigation. Perform cold full replay after restore using the original independent pins. Do not restore Session memory or trust a derived cache as history.
7. Keep the old exact code/dependencies, committed history, independent pins and archive after upgrade. Rollback selects that old reader/code and branch and verifies it fully; retain the successor separately. Missing old code/dependency bytes block rollback. Rollback never rewinds a branch HEAD, deletes later signed history or changes permanent activation.

Only the exact local Linux environment in the receipt has been demonstrated. This preparation is candidate work. Final Product interfaces, human journeys, owner permission and actual admitted release remain S02/R08/A01-A04 obligations.
