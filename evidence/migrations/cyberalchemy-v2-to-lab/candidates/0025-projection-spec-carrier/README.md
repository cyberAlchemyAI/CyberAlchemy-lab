# Projection Specification carrier

Exact source -> selected or explicitly omitted fields -> deterministic derived view -> fidelity check.

A Projection Specification defines deterministic generation of a non-authoritative view. This candidate preserves the source-qualified Projection Specification meaning and the normalized D10, D42 and D44 selectors without restoring a dropped Definition Tower as an authoritative concept.

The example creates a compact view of the preceding Receipt: receipt identity, reported result and exit code. Every other source field has an explicit omission reason directing readers to the exact source. The view contains source and specification hashes, a derived-non-authoritative status and authority_effect none.

The generator supports top-level field selection and renaming. Every source field must be selected or omitted exactly once. Duplicate source selections, output names and omissions are rejected. Source values retain their JSON structure. The checker compares the supplied view against deterministic generated bytes, rejecting edits, authority injection and stale content.

Generation is one-way. It does not write back into the source, activate a view or make a candidate source authoritative. The view remains distinct from both source and specification. Source and specification hash bindings retain the continuation path to the full record.

This profile does not implement arbitrary templates, derived calculations, joins, nested selection, live synchronization or semantic-fidelity proofs. Omission reasons and the declared scope remain owner assertions. Regenerating a view is not evidence that omitted information is irrelevant.
