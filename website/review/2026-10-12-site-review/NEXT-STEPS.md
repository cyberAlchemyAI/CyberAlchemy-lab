# Recommended changes

## 1. Reduce loading cost and startup movement

- Supply optimized variants for the six homepage medallions. Their original PNGs account for roughly 10.7 MB while displayed as small icons. Keep their visual character and inspect quality at ordinary and enlarged sizes.
- Reserve stable space for the homepage illustration and navigation.
- Investigate first-paint route enhancement in the guide and Craft. Five local samples each recorded substantial startup layout shifts. Render the initial chapter and shell without a visible intermediate layout while retaining the no-JavaScript reading path.
- Repeat controlled local measurements and inspect a loading trace. A local result does not establish hosted field performance.

## 2. Repair search and connect the whole site

- Give each judged question an independently reviewed exact destination. Stop selecting expected results from the same index that receives the question aliases.
- Correct the destinations for “does Accept reserve capacity?” and “authority versus provenance.” The current best matches concern revising meaning and continuing into contracts, respectively.
- Add robot-series sections to the index and join that page to shared search, navigation and a route back to the homepage or research page.
- Improve ordinary-question tokenization and comparison queries. Keep exact record-title ranking and scope filtering.
- Preserve the original 24 exploratory judgments and four explicit adjudications. Add a separate set of new queries before tuning the implementation. Evaluate actual reader queries when supplied.

## 3. Repair graph sizing and accessibility structure

- Separate interactive map sizing from static illustration minimum widths. Five map views currently retain a 972 px minimum while the Fit control requests 778 px.
- Check Fit, zoom, reset, node selection and relationship-list parity in all ten map layouts at desktop, tablet and phone widths.
- Increase diagram label readability through text and layout changes. Changing only the outer display size leaves small labels and makes fitted views smaller still. Retain the inspector and relationship list.
- Give chapter subheadings the appropriate rendered rank when the chapter title becomes the page's H1. Preserve section IDs and navigation history.
- Repair skip links in the guide, library and Craft. They currently select an entrance topic instead of bypassing navigation into the current topic. Check the next Tab as well as the scroll position.
- Name scrollable tables by their subject. Remove or distinguish duplicate library region names. Add a main landmark to the reader form.
- Repair or remove the unsupported names on the robot page's generic div containers. Keep meaningful section and navigation names.
- Repeat the affected axe and keyboard scenarios. Keep image/SVG contrast and actual screen-reader observations separate.

## 4. Make availability and next actions explicit

- Add a concise current-scope route near the homepage's primary action. Explain the local foundation and ongoing product work without implying a production service.
- Identify the software-design Product's closed-beta scope separately from the Lab foundation and public explanatory site.
- Provide the intended public source/contribution route when its exact destination and audience are selected. There is currently no repository link in the site's external-link inventory.
- Provide a consistent route to the Lab homepage and research pages from the reading surfaces.

## 5. Reduce reference-page cost and prepare sharing

- Evaluate separate static record pages or smaller catalog documents. Keep direct record identities, offline reading, exact bodies and complete search coverage.
- Measure library startup, catalog filtering and first search under a declared mobile/network profile before selecting a split. The current document is 3.02 MB raw, about 291 KB in a theoretical gzip encoding, and builds roughly 27,900 DOM nodes.
- Redirect the duplicate guide alias or select an explicit canonical route. Configure share metadata against the chosen deployed address.
- Restore a favicon for the robot page.
- Repeat root, project-path, file-origin and legacy-link checks on the resulting artifact.

## 6. Observe readers across the whole site

Keep the existing six documentation tasks. Add whole-site tasks before the study begins, or run them as a separately labeled session if readers have already started:

1. Explain who the Lab is intended for and what problem it addresses after reading the homepage.
2. Find what is available to use now and what is still being developed.
3. Find a research question and explain how the Lab provides a setting for investigating it.
4. Find the robot-learning series, then return to the system explanation.
5. Explain why the completeness criterion does or does not require inactive records from another account.
6. Find whether a calculated Accept permits reservation or deployment.

Record the paths, assistance, mistakes and reasoning. Do not tell participants which page or control to select. Observe comprehension before changing explanatory meanings. [NN/g task guidance](https://www.nngroup.com/articles/task-scenarios-usability-testing/).

Use an actual screen reader and Safari/device session for the remaining environment checks. Automated results and an accessibility tree do not replace those observations. [W3C user-involvement guidance](https://www.w3.org/WAI/test-evaluate/involving-users/).
