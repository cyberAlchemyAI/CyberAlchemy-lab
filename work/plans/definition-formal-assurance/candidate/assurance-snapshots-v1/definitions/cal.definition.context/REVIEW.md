The source preserves Context identity through refresh, source-epoch changes, new requests, interfaces and pause/resume when Product, Project, Goal and purpose anchors remain stable. Material anchor changes require a successor Context and supersession of the earlier Context.

The candidate expresses three normative implications: a preserving refresh requires same identity; a material anchor change requires a successor; and that change requires earlier-Context supersession. The antecedent classifications are supplied predicates. Materiality is not computed from changed field Tokens. Required identity stability does not cause actual stability; required successor/supersession does not create records or transitions.

The finite evidence has both required witnesses and countermodels for these separations. **Twenty hypothetical history frames**, ten rejected, check preserving refresh, interface/pause behavior, new immutable Views for changed source epochs or requests, stale View rejection and four material anchor changes. Two distinct supplied Contexts can share the same anchors. Preserving an existing Context during refresh is not a global theorem that anchor tuples uniquely determine Context identity.
