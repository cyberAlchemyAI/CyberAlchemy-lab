## Version introduction and assignment meaning

For a selected `AllowedVersionIntroduction(new, before, after)`:

1. `new` is a Scheme, absent before and present after.
2. Every selected existing assignment whose Scheme version is present before remains present after; the old version remains present.
3. Its exact version, axis, value, subject revision and meaning token retain equality across the step.

A stable assignment label does not suffice. A changed meaning token fails even when version, axis and value remain the same. A separate successor assignment under the new version is permitted while preserving the old record. The draft does not grant a migration permission or enforce a general successor-history policy. Unsupported correction, retirement and challenge actions require separately selected contracts. The frame is scoped normative semantics, not a factual assertion that all production upgrades comply.
