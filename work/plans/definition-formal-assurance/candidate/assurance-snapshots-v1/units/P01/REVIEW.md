# Provider capability and evidence selection review

P01 separates the proposition to establish from the tools currently available. The candidate selector first compiles the exact interpretation and typechecks the actual query AST. It derives logical requirements from declarations and formula nodes, then checks the obligation's fixed evidence strength, declared domain scope, candidate route and selected runtime bindings. Unsupported temporal or unresolved meaning is reported before missing provider availability. A static feature label cannot hide an unsupported operator or an unknown symbol.

The minimum-strength policy is proposition-dependent. A model witness establishes existence of an admissible structure with the selected property. A model-local value establishes truth only in a supplied structure. Exhaustive finite absence concerns the enumerated domains and interpretations. Solver evidence concerns an exact encoding and runtime. A mechanized theorem concerns an exact checked proposition, imports and assumptions. These categories do not form a blanket ranking in which one result can replace every other result.

The A05 policy fixes universal properties to mechanized-theorem evidence. P01 rejects attempts to weaken that requirement in the request or to select the finite evaluator, finite enumeration or SMT solver as a substitute at that strength. A theorem route also needs separate consistency and inhabitation guards where the obligation requires them; routing alone produces no logical verdict.

The inventory observes Python 3.14.4 and jsonschema 4.19.2. It binds the exact executable and non-cache package trees for jsonschema and its active dependencies, including schema resources and the native rpds extension. Dependency versions are recorded. This provides more than an executable name or package label, but it is not a hermetic standard-library or operating-system/linker closure.

The absence statements are deliberately scoped: Lean/lake/elan and z3/cvc5 were not found on the current PATH, and z3/cvc5 modules were not found by the active Python interpreter. This does not assert that every filesystem, container, remote host or private environment lacks those tools. Imported profiles, a pinned Lean toolchain and unrelated proof source remain bound context leads; they are not inherited provider availability or proof of the current 183 definitions.

The policy binds the exact assessment bytes. Changing a route's availability flag does not override that selected inventory. Available runtimes and adapters need explicit file bindings that are rehashed during live selection. An offline caller snapshot remains pending runtime revalidation. The policy carries resource budgets for later adapters—30 seconds, 10,000 interpretations and explicit evaluation/tuple/output/domain limits—but P01 does not claim that unimplemented adapters enforce those budgets.
