## Promotion and regression policy

- Every task consumes current scoped predecessor exports. Acceptance requires concrete proof, witness, transport or workflow evidence appropriate to that task.
- Definitions and required theorem types precede runtime implementations. Schemas project accepted semantic contracts rather than define meaning through shape checks.
- Keep independent source truth, exact graph membership, target kind, target revision, scope and full protected tuple provenance explicit.
- Preserve selected-data compatibility, invariant preservation and model conservativity as separate axes.
- Bind any domain expansion, new initial facts or context interpretation as a separate changed profile. A unchanged-domain rule theorem does not cover them automatically.
- Benchmark exhaustion and missing witnesses remain unknown. Optimization must preserve exact facts, support evidence and completeness boundaries.
- Keep candidate acceptance, machine execution and human use recommendation separate. Original R06/G4 remain pending unless actual feedback addresses those artifacts.

## Deferred layers

General negation, executable arbitrary conditions, function-generated domains, redelegation chains, overrides, fulfillment semantics, authenticated issuers/clocks, a second kernel and live authority transactions are not prerequisite deliverables for the proposed useful release. Each needs its own requirement, semantics, cost decision and proof/evidence profile if selected later.
