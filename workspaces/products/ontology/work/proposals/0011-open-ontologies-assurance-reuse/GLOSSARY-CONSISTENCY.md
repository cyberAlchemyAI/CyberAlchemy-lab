# Meaning consistency check

This design uses explanatory labels, not new canonical term definitions.

| Existing distinction | Where the design preserves it |
| --- | --- |
| Source definition versus selected formal interpretation | Source fidelity is a separate result/readiness dimension. |
| Meaning history versus review history | Complete view/input identity includes exact review references, not only a meaning cursor. |
| Model witness versus universal theorem | Required proposition/quantifiers must match; a Lean existence proof does not discharge a universal obligation. |
| Native checker acceptance versus fresh kernel replay | Separate DA-FOL-ENC1 and DA-FOL-KERNEL1 profiles. |
| Generic rule entailment versus supplied-rule assumptions | Checker kind and verdict retain the exact rule table's role. |
| Currentness versus a fresh proof event | Saved inspection cannot mint a process-local completion event. |
| Proof validity versus original meaning | Semantic bridge and source fidelity remain distinct. |
| Evidence versus owner approval or an effect | All new provider outputs have no authority/application effect. |

Reference: [existing Lab proof comparison](../../research/open-ontologies/2026-11-02/LAB-PROOF-COMPARISON.md),
[proof profiles](PROOF-PROFILES.md), and the exact local source bindings in
[LAB-REUSE-BASELINE.json](LAB-REUSE-BASELINE.json).

Result: consistent at candidate design scope. The richer translation theorem,
actual source-fidelity decisions and future implementation behavior have not
been established by this document check.
