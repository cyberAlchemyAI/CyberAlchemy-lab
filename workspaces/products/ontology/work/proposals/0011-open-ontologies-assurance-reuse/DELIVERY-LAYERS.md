# Delivery layers: design seed

These are coherent delivery boundaries, not an executed work-pack or calendar.

| Layer | Usable result | Reused code | Evidence before moving on |
| --- | --- | --- | --- |
| L0: source and builds | Exact imported source units and reproducible selected build records. | Entire Lean workspace, Rust crate/build files, tests and initial fixtures. | Byte/notice accounting; selected toolchain/build/import identities; original checker positive and hostile controls. |
| L1: definition model proofs | Existing supported model examples can receive backend checks and fresh exact Lean proofs through a separate provider. | Fol evaluator, parser, soundness theorems and witness pattern; Lab capture, obligations, finite search and supervised proof-audit mechanics. | Restricted-profile bridge; concrete witness/required-set/axiom checks; unchanged prior profiles; source-meaning gaps visible. |
| L2: agent views | Per-goal retained/lost/source-unsupported results on exact exported cuts. | Whole Rust preserve workflow, Horn/certificate checkers and existing versioned Lab views. | Exact RDF bridge, subset/profile/fixpoint checks, forged evidence and two-agent controls. |
| L3: change reports | Structural, logical and consequence reports before owner review. | Existing upstream plan/conservativity/closure-diff code. | Exact before/after bindings; additions/removals/unknowns kept distinct; no application or approval effects. |
| L4: selected extensions | Refutations, richer model signatures, shapes or independent Horn checks as separate profiles. | Fo/Lrat/Dl/Shacl and optional Isabelle/Rocq units already selected for reuse. | Each needs its own source/encoding/checker closure, required proof strength and acceptance controls. |

First use the existing partial Provenance/Authority model and its controls.
Do not claim a full definition was proved when only its selected projection
was encoded. The first source-meaning review can remain pending while the
candidate mathematical checking path is exercised and accurately labeled.

The source copy can retain code for later layers early, but a retained file is
not an activated capability. Rust build/compiler selection, resource settings
and each stronger bridge are implementation gates. No proof or performance
result is assumed from this design.
