# Trust boundary qualification

The exact required meanings are defined independently of the implementation. The general bundle includes contextual projection, kind encoding, observation/producer sealing, complete grounding/closure, arbitrary-old-model recursive expansion, lineage, conditions and direct source mappings. Qualification additionally replays countermodel soundness, complete finite reference saturation, preservation of the source-faithful subclass, and the limited stress-certificate statement. Every target is compared to a fixed trusted closed type, with its transitive definition/proof closure reconstructed in a fresh environment of the same pinned Lean kernel.

| Boundary | Current evidence | Claim ceiling |
|---|---|---|
| Source meanings and selected field maps | Independent semantic definitions and mapping correspondence proofs | Selected fragments of 41 reviewed relations; external meaning/authenticity decisions still supplied |
| JSON decoding and normalization | Strict schemas, duplicate/nonfinite/depth/shape controls, differential actual-value witnesses | Tested adapter boundary; no universal decoder equivalence theorem |
| Source observations | Exact graph membership, endpoint/revision/scope/kind checks and all support witnesses | Accepted assessment truth is assumed, not authenticated |
| Recursive extension | Positive fresh ordinary heads, immutable old frame and actual finite hypotheses; every-old-model theorem | Generic root-constrained Horn models; domain/fact/old-head changes use other targets or remain unsupported |
| Source-faithful models | Explicit sealed interpretation equality; preservation theorem | Stronger class must be named; a generic model may contain extra sealed truths |
| Derivation versus closure | Earlier-premise certificates plus saturation/complete-query witnesses | A query certificate does not establish a complete closure; partial search cannot establish absence |
| Norms and conflicts | Potential origin, exact consistent condition selection, active-norm/conflict witnesses | No fulfillment, admission, override or arbitrary-condition execution |
| Stress certificates | Pure origin/forward shape soundness | Can pass with empty steps and an invalid graph. Whole graph/query qualification requires separate checks. |
| Hash/compiler/host | Exact byte hashes and pinned compiler/kernel lock | Host/hash implementation and trusted source delivery remain assumptions |
| Shadow application | Immutable snapshots, fresh baseline registrations, current proof/source/context checks, local lock and postcheck | Cooperative local writers only. An external writer can race final check/rename; no live authority effect |
| Human use qualification | Separate S14 feedback | Machine/author acceptance supplies no human semantic or diagnostic approval |

Allowed foundational axioms are `propext`, `Classical.choice`, and `Quot.sound`. Submitted custom axioms, unsafe/partial dependencies, weakened types, stale imports and missing obligations cannot discharge the catalog. Fresh replay is not a second independently implemented kernel. Registered snapshot identity is a canonical object hash; exact file bindings are distinct. A saved current result still requires fresh qualification before application.

V1 accepted exports and original R06/G4 human gates are retained. Registry structural preservation and fresh-kind compatibility remain available through their original qualified profile; v2 does not silently widen that profile or claim full meanings for all registry declarations. Unknown resource outputs cannot authorize closure, absence or readiness. Benchmarks describe measured finite workloads, without throughput or completion-time promises.

The relevant proof/source closure is strict. External governance documents are byte-bound input leaves: their older admission/predecessor graphs are not Lean imports. Twenty-four exact metadata occurrences are separately classified in `scoped-provenance.json`: historical task-plan captures, deliberate stale-input fixtures, removed temporary v1 shadow state, and dynamic documentation links. These do not discharge current proof or host requirements; actual v2 shadow runs supply current application evidence. No formal proof source or hard obligation is excluded.

The original monolithic `RegistryKind9` reduction exceeded the unchanged 60-second stage ceiling during replay. The successor copies each original registry value exactly and proves the same `KindValid nodes kind` target through basic fields, pair uniqueness, and explicit endpoint-membership lemmas, then compiles the original whole-snapshot validity theorem. This changes proof grouping, not the relation vocabulary, validity requirement, or compiler-stage budget.
