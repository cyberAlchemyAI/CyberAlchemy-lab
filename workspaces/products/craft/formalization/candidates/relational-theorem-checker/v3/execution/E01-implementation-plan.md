# E01 evidence-collection implementation and review

1. Formalize the explicit any-accepted policy. A valid selected conformance assertion, its exact subject/target/scope and context, and a current listed accepted matching source assessment suffice. Every valid accepted listed assessment must appear in the support projection, in source order. Rejected distinct assessments do not count as support. Empty/duplicate/nonexistent/stale/mismatched selected references are invalid before projection. Contradictory source records for one assessment token are invalid, not a vote.
2. Each typed evidence reference contains the opaque assessment token and the immutable normalized graph identity. Legacy assessments have no independent revision field; their version is explicitly the bound source snapshot containing that token. This avoids inventing a revision that the source does not provide. The request additionally binds exact source bytes and evaluation context. Changing the graph changes the evidence-reference version.
3. Compile independent existential denotation versus the complete filtered support projection, all-support retention and unchanged root projection before mapper runtime. Selected-source membership and endpoint/scope matching must be explicit in the theorem and concrete witness.
4. Define a closed `evidence-collection-v1` request/result and explicit `legacy-single-token-adapter-v1`. The legacy adapter treats the entire qualifier as one opaque token, even with punctuation. Reference collections are not obtained by splitting old text. Preserve collection input order in the request identity and source order in supports; duplicate references are refused. Limits: <=64 selected references and the existing bounded source graph contract.
5. Use the shared fixed supervised worker and a narrow source-bound mapper. Decode/validate a bound core request snapshot, select one exact conformance assertion, validate current profile/context/catalog and all referenced assessment identities, then freshly compile the generic and concrete projection witness and same-kernel replay. All output predicates remain source projections; no evidence creates admission roots or publication authority.
6. Execute two-support, mixed accepted/rejected, no accepted support and legacy punctuation witnesses. Challenge empty/duplicate collections, duplicate contradictory source tokens, wrong target/scope/revision/context, missing tokens, output tampering and saved/new-client freshness. Preserve all actual evidence and failed attempts; compare original single-token behavior through its separately selectable profile.
7. Review the policy, exact projection and bridge/assessment-truth assumptions against each source criterion, bind the current artifacts and accept only after all controls pass.
