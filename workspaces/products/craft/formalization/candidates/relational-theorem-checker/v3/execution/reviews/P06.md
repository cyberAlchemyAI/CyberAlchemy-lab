# P06 review: resource bounds cover the proof pipeline

P06 passes its three acceptance criteria and 49 controls. A full fresh supervised rich run retained the exact request, discharged all 20 obligations and agreed with accepted P03 on both theories, closure, certificates, observations and support provenance. The supervisor recorded approximately 97 seconds and a sampled aggregate process-group RSS peak of 2.22 GiB.

The main change is the issuance boundary. A worker may prepare checked proof files, but it cannot issue the public result or the live completion event. The parent issues them only after successful worker exit, owned descendant teardown, whole-run/output accounting and exact input/source/policy correlation. Timeout, cancellation, advisory RSS exhaustion, output flood, forced termination and unavailable required policy all remain nonqualified. Saved inspection confirms currentness and cannot recreate a fresh event.

The closed transport schema rejects application escalation, a null qualified result, an incomplete supervisor paired with qualification and extra unbound fields. The raw CLI uses the same fixed worker. Required mode is never silently changed to advisory.

The actual host lacks writable cgroup delegation. Accordingly, advisory observation and required-policy refusal are demonstrated; hard cgroup enforcement and kernel OOM are conditional code, not tested claims. Process groups cover the fixed trusted worker and normal descendants, not arbitrary hostile code. P07 still must anchor inherited cache metadata independently and finalize immutable owned run records before shadow publication begins.
