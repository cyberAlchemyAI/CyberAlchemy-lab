# P10 implementation and review plan

This is the next unit after P09 acceptance. It does not replace the accepted operator policy or mark measurements complete.

1. Fix a closed performance-report schema before running benchmarks. Each measured interval names its parent, uses monotonic start/end, records inclusive and exclusive time separately, and states whether it ended in actual complete kernel qualification or refusal. Unknown phase time remains unknown; do not infer a replay duration by subtracting unrelated wall clocks.
2. Add a fixed operator-owned instrumentation worker wrapping the accepted P07 context. Its tool calls delegate to the original bounded streaming implementation, under the original supervisor. Bind the added worker/context sources in every owned run. Submitted requests cannot choose a worker or disable currentness, replay, output, cleanup or policy checks. Preserve accepted implementation files and receipts.
3. Measure one cold and one warm full qualification of the same supported workload in new owned directories. Compare normalized theories, closures, certificates and supports; retain the full twenty-obligation inventory and exact fresh general replay. Treat the existing anchored cache as verified evidence rather than a readiness flag. Add a second warm sample only if a failure or variation needs explanation.
4. Capture preparation, concrete witness parts, generic replay, saved inspection, explanation, successor registration and transaction duration. Reuse exact current P09 application records for already measured aggregate application/registration costs where suitable; additional instrumentation must state what was measured anew. Do not sum parent wall time with its child tool times.
5. Record the actual memory backend and advisory aggregate RSS peaks from supervision, along with policy, output bytes, CPU/host context where available, and workload dimensions. Required memory enforcement on this host remains unsupported; do not label sampled RSS a hard cap.
6. Increase only one workload dimension in a separate run while preserving the declared envelope. A preflight-valid workload that exhausts an atomic proof budget is a measured refusal, with no completed proof or publication event. Retain P09's actual staged replay timeout and richer combined observation as separate bounded evidence.
7. Choose an optimization only after these measurements locate the bottleneck. If proof compilation, trusted import/source checking or replay dominates, do not optimize finite grounding based on intuition. Any selected evaluator optimization requires separately fixed equivalence targets and actual complete closure/support checks. No optimization is a valid evidence-based decision.
8. Review every P10 criterion against exact reports. Publish workload-specific measurements and the observed success/refusal envelope, without extrapolated throughput or wider-profile guarantees. Then construct the changed public-interface worked packet for the artifact-specific P11 assessment.

The core plus all seven extensions remains selected. E00–E06 implementation follows the concrete P11 assessment; their already recorded design notes remain plans until executed and accepted.

Proposed stress dimension: change the added fresh-seed rule from one reference variable to three, introducing body occurrences `Conforms(y)` and `Conforms(z)` to bind the extra variables. Keep the graph, domain, predicate declarations, producer policy, other rules and resource policy fixed. Record the primary variable-count change and its necessary body representation explicitly. With the representative 15-value domain this is 15 cubed candidate substitutions for that rule, still below the 50,000 work ceiling; actual normalization must confirm the total bound before any proof claim. Four variables would already exceed that ceiling for this domain, so a numerical maximum in the schema is not a guarantee that every joint workload is supported. The result, including any proof deadline refusal, must be measured rather than predicted.
