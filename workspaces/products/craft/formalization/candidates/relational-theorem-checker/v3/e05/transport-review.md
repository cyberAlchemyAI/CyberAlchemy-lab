# Canonical IR implementation review

`canonical-typed-ir-v1` represents null, naturals, Booleans, Unicode scalar strings, arrays and records with explicit distinct constructors. Record keys and strings are exact validated scalar sequences, without Unicode normalization. Record fields must be strictly sorted and unique. A structural shape checker prevents array spines, record fields or nil from appearing as JSON values in the wrong position.

The universal Lean theorem says successful canonical import yields precisely the independently defined typed denotation. Reference id/version fields are preserved, and Boolean and natural constructors cannot denote the same value. This theorem starts at typed IR; it is not a theorem about the raw JSON byte decoder, SHA computation or Python emitter. The primitive recursor fold is evaluated logically by the pinned kernel; it is marked noncomputable only because this toolchain's native code generator does not compile a directly written recursor. There is no native-evaluation axiom or runtime trust-flag shortcut.

The actual owned final-source witness compares seven complete decoded values: the accepted P09 core semantic graph, each E00–E04 semantic result, and a Unicode/control-character/type/reference/key/hash challenge. Python emits primary scalars using ord and the independent semantic expectation using UTF-32 bytes. Every whole value is checked in Lean, rather than checking a few displayed fields. Duplicate/unsorted records, invalid scalars and malformed array shapes are refused in the actual concrete witness. Finite bridge tests additionally challenge raw duplicate keys/nonfinite numbers, source/content hash drift, field order, composed/decomposed Unicode, escapes, Booleans/naturals and fractional/negative values.

Direct floating semantic numbers, including 0.0, are refused by this profile. The original core still has its explicit numeric normalization rules and exact raw-input witness checks; IR consumes canonical naturals after such an explicit boundary, without silently converting a Boolean or float. Original raw source files and accepted receipts remain bound and unchanged. IR import does not reissue a fresh core mapped qualification or add authority.

The initial mutual recursion and automatic recursion-table representations exceeded the retained 60-second atomic tool limit. Changing only proof tactics did not fix them. These failed attempts remain historical resource refusals, with cleanup and no issued event. The final design uses direct structural recursors and Unicode scalar data rather than expensive logical String iteration; its universal proof compiled before the final runtime witness. No operator policy or accepted core source was changed. The successful measured batch is evidence for that batch, not a guarantee that every input within static tree limits finishes.

Use `execution.extension_runtime.Client('E05', policy).qualify(raw_bytes)`. Whole batches are capped at 16 values, 8192 tree visits and depth 32; the raw decoder/schema/output and owned runtime stage/whole-run policies still apply. Required host memory enforcement remains conditional on an actually available delegated backend, and advisory observation remains advisory. The tested JSON/emitter bridge, supplied semantic-source truth, exact file/hash assumptions and pinned same Lean kernel remain the stated boundaries. Independent whole-core checking is outside this unit.
