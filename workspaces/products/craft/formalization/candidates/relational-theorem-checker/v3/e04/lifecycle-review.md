# Lifecycle implementation review

This is the separate `candidate-lifecycle-v1` profile. A successor declaration, eligible successor, and committed current head are distinct. The universal policy requires exact predecessor/current head and expected generation, a successor absent from history, declared succession, yes eligibility and a separate accepted review matching head/successor/generation/context/epoch. Qualification alone commits nothing.

The transition theorem preserves the complete previous history/evidence prefix, advances exactly one generation and names one new head. A historical successor cannot reactivate. Declaration alone with non-yes eligibility cannot transition. These definitions and proofs compiled before the SQLite mutation code. Actual concrete witnesses cover two eligible competing successors and a declared-but-unestablished successor.

Use `Store.create(fresh_owned_path, head, context, epoch)`, `snapshot()`, `commit(client, fresh_answer)` and `recover()`. The commit gate requires the exact E04 client/result, rederives the exact typed transition from its bound input, checks current state/generation inside a cooperating lock and immediate SQLite transaction, then checks the live event before writing. Saved/new-client, changed, rule-only or ineligible receipts cannot enter this gate. Input/completion references are exclusive durable immutable files; DELETE/FULL SQLite metadata is authoritative. Two real competing thread writers through separate store handles produced one commit and one conflict.

Recovery verifies the saved input, source identity, completion reference/request identity, closed schema and transition/history chain. It reports recorded state with fresh_event=false. Real child process exits before and after commit in isolated clones measured old/new durable generations. Those crash tests exercise the internal storage primitive after an already checked source; public freshness is tested separately. They do not claim a child inherits a newly issued proof event. An uncommitted artifact directory may remain after a crash; recovery does not mistake it for committed metadata.

The original fixed-frame append/conservativity theorem still applies only to its declared fixed frame. Head replacement/retirement here follows the new lifecycle invariant instead. The candidate API has no live publication/admission authority. Accepted core shadow stores and source files remain untouched. Supplied declarations, eligibility and review truth, tested JSON bridge, pinned kernel, hashes, cooperating callers and host/SQLite durability are assumptions. Direct host access to the internal storage primitive is outside the public gate assurance; it is not a hostile-code sandbox.

The accepted store-control directories are frozen review evidence. Create a new owned directory for subsequent experiments rather than modifying those historical stores. No deployment or external lifecycle effect occurred.
