# U0 technical contract source scaffold

C05 candidate source model in the existing Core DomainSpec project carrier. It describes finite shared contract shapes with existing Entity, Rule, Operation and Interface roles; it is not the successor Alch business source carrier or a new meta-type. `OWNER-MAP.json` links source selectors to the actual C01–C04 owners and the CAV2-D65 construction chain. Schema IDs, exact bounds, references and original custody remain with those owners; a structural String digest field is not proof of a SHA256 or a genuine handle.

The submission shape retains exact UInt64 and Bool types. Other records describe source, review, decision, entry, wire and artifact metadata. The technical Rule explicitly checks `item.verified` on the named Submission record through the existing typed Rule owner, without a FormalClaim. A supplied flag never verifies delivery/provenance or approves a product. Decision and permission records retain outcome/kind fields; their exact enum and original custody remain with the schema owners. The structural Operation/Interface describes a boundary signature. It is not the C03 native pure ABI implementation and is not invoked or generated here. No empty-settlement/store behavior is inferred.

C05 compiles this authored project through the existing public Core compile API into a fresh absolute graph/certificate target in private execution evidence. Actual compiler graph/certificate identities and source selectors are recorded there. The public selected-node owner (`loadProjectNode`) separately checks the Rule typed closure; whole-project structural compilation alone is not that check. Missing property and Bool/String mismatch controls reject at the selected typed owner. No authored JSON system graph is accepted as a genuine compiled owner, and no graph/Goals/ontology admission is performed. This is contract-shape prototype evidence, not behavioral proof or native support.

The zero-claim business witness is the separate `test/profile-engine/fixtures/u0-v2/business.alch`; its real successor parser/executable/handler and native views remain later tasks. All thirteen canonical role definitions and existing legacy public contracts remain unchanged.
