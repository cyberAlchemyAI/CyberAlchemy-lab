# Business-only campaign generation

The business model declares current consent and preference versions, sender/account eligibility, cancellation intent, human approval, and quarter-hour schedule alignment. It composes the current-preference Mapping inside both draft and schedule Operations and enforces typed Policies. Users select `Profiles.MarketingApplication@0.1.0` in `application.json`; the profile supplies original source projections and Mailchimp draft, content, schedule and metrics stages.

The host supplies genuine document/release authority, inference resource, authenticated CRM preference Query resource, and Mailchimp connector credentials/HTTP transport. This infrastructure is not handwritten campaign logic. Private source/release/model-candidate custody, approval expiry/content/audience/account binding and future schedule checks remain with existing native owners. Contacts are never included in model context. Draft and content can be prepared before approval; scheduling requires it. Accepted scheduling does not claim delivery, and no post-schedule cancellation endpoint is added.

`fixtures/business-cases.json` exercises genuine current-contact assembly and the generated typed business rejection cases. Fixture success does not qualify a live model or Mailchimp account. Formal claims are optional. Hosting, TDE, EVF, deployment and publication remain deferred.
