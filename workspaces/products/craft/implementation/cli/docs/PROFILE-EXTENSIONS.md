# Supported profile extensions

Start with [package authoring](PROFILE-PACKAGES.md). The qualified boundary is finite typed package rules and owned assets over existing graph/callable semantics. The second architecture adds an actual typed shared port and changes component ownership/dependencies. The appointment example changes domain types, rules, provider cardinality and calculation without compiler edits. These are stronger checks than renaming paths.

## Open Questions

New primitives, relationships, source adapters, guarantees or provider semantics require Core work and fresh qualification. See [the generation guide](PROFILE-GENERATION.md#open-questions). Local hosting, TDE, EVF and publication remain deferred.
