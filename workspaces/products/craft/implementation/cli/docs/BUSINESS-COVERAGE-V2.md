# Source obligations, required outputs and support cells

C04 defines data contracts and finite planning checks. A declaration/inventory/JSON view is not a genuine checked graph or native/installed observation. S01 and U09 later own actual source-to-checked-owner-to-artifact joins; U11 owns actual required-output completion.

`inventoryBusinessSourceContractV2` captures the independent original source denominator before semantic lowering. It checks the exact source byte count/SHA256, every physical noncomment line, one original span/obligation per fact, and exact source/line/column/text provenance. It retains all authored facts, including examples, Rule prose and optional claims. Additional obligations name the Entity shape, actual Boolean condition, guard wiring, whole-input result, authored rejection, empty effects, logical entry and its inline permission. They require named semantic owners; all start `producer-required`. An invented view, matching digest or dropped source line cannot close the denominator.

| Obligation | Actual owner required later | Evidence boundary |
|---|---|---|
| Authored physical facts | U01/U02 original parser/resolver capture; S01 inventory custody | Exact original text and immutable original selected source |
| Entity/Bool condition and type/path/parameter correspondence | U03/L02 compiled direct-condition owner | Genuine compiled Rule/Entity owner, no claim-derived substitute |
| Guard, return, rejection and no effects | U05/G01 checked pure Operation and actual emitted callable | Actual generated behavior and output origin |
| Logical entry, payload mapping and inline permission | Q01/Q02 early request owner | Original intent precedes generated callable/input; protected input remains unsupported |
| Codec, handler, limits and actual native binding | U06a–c/U07/U08 | Exact selected actual assets and generated native handler observations |
| Business/system/bridge projection | S01/U09 existing checked view owners | Real original graph/native lineage and actual emitted files, no ontology admission |
| Installed support | H01/F00/V03/R00 | Fixed real runner/candidate before independent installed observations |

The inventory is only a contract-data helper until S01 registers it against the original selection and source before lowering. It does not independently parse or reconstruct every business clause; U01/U03 do that. Checking source spans alone cannot prove that a supplied semantic DTO matches the text. Final coverage must join actual original owners, not use this helper as a replacement source checker or registry.

## Requested outputs

Output kinds are code, API contracts, business graph, system graph, business-system bridge, base model and conjecture problems. Requiredness is explicit per requested kind. U0 selects explicit `code-only` mode with required code; it can also require the existing graph/bridge/API artifacts. Nothing changes v1 defaults. There is no automatic choice of code-and-model output.

`planBusinessOutputsV2` rejects an unsupported required model/problem output before finalization. Unselected optional model/problem output records `unsupported-optional`; it neither supplies behavior nor forces native parser/solver dependencies. All supported selected outputs begin `pending-producer`, never produced/complete merely because a recipe names them. U11 must check actual output files, requiredness, real owning graph/native producer and current epoch before finalization. Unknown/duplicate kinds, forged readiness and absent explicit required code reject.

The status vocabulary distinguishes not-requested, pending-producer, produced, unsupported-required/optional, failed-required/optional and stale. Required rows cannot claim an optional-only failure state. Produced rows carry exact bundle-relative artifact paths, byte identity and actual owner/producer references; paths escaping the bundle reject. The output kind is declared once on the row. A successful optional output cannot hide a failed required output. Partial/stale/missing required artifacts cannot finalize a complete bundle. Actual native model/problem production is U1, not C04.

## Support and construction

A support cell names exact source contract, recipe, descriptor, ABI, entry access and effect scope. Its evidence variants distinguish declared, generated, native-observed and installed-tested. Each later variant requires its own actual producer/subject/receipt or candidate/runner identities; no ready Boolean, proof claim or ontology admission is admitted by this schema. The shape alone cannot qualify a stage: actual owner receipts/currentness remain mandatory.

CAV2-D65 selectors remain definitions → candidate ontology/source scaffold (C01–C05/J00) → actual business graph/native prototype (G01/U08/U09) → exact private candidate (F00) → current installed tests (V03) → separate owner approval → separately authorized operations. C05 maps the exact technical source and these obligations to existing canonical roles/graph owners. This inventory introduces no meta-type, universal IR or competing graph authority.
