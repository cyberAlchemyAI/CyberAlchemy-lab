# Shared U0 contracts and producer interfaces

J00 integrates the additive `alchlang.business-spec/v2-candidate` contracts. Core
owns the schemas and shared TypeScript data declarations. AlchLang has generated
local data mirrors and its independently implemented identity projections. Public
source exports expose these contracts; genuine successor runtime producers and
installed package qualification are subsequent tasks. A type or matching digest
never authenticates a checked owner handle.

`BUSINESS_CONTRACT_RESOURCES_V2` lists ten fixed Core-owned schemas. The existing
v1 schemas, claim-dependent normalization and existing `BusinessInputV2` carrier
remain intact. The new authoring input is `AuthoringBusinessInputV2`. Shared
interfaces are in `business-authoring-stages-v2.ts`; they describe future methods,
not stub implementations or registered native support.

| Producer | Interface or output | Actual implementation task |
|---|---|---|
| Source parser | `BusinessParserOwnerV2` | U01 |
| Resolver and optional assurance | `BusinessResolverOwnerV2` | U02 |
| Direct frontend lowering | `BusinessDirectLoweringOwnerV2` | L01 |
| Independent Core recipe | `BusinessCoreRecipeOwnerV2` | U03 |
| Review, captured decision and acceptance | `BusinessReviewOwnerV2` | K01 |
| Early request and separate late binding | `BusinessRequestStagesOwnerV2` | Q01 |
| Input, direct condition and checked application | `BusinessInputOwnerV2`, `BusinessDirectApplicationOwnerV2` | L02 |
| Pure native source and actual generated import | `BusinessPureGenerationOwnerV2` | U05, actual join G01 |
| Bytes, exact values and output | `U0DecoderOwnerV2`, `U0ValueOwnerV2`, `U0EncoderOwnerV2` | U06a, U06b, U06c |
| Injected HTTP infrastructure asset | `U0HandlerAssetOwnerV2` | U07 |
| Genuine coverage and view projection | `BusinessCoverageViewsOwnerV2` | S01 |
| Fresh required-output checking/publication | `BusinessOutputWriterOwnerV2` | U11 |

Component implementations use these signatures before a loaded profile exists.
J01 builds the real SDK/native basis after components exist; J02 captures actual
selection. Early request preparation and captured review/acceptance precede input;
checked graph and generated/imported callable precede late native binding. Late
binding receives the same original early handle, actual generated import and
original native basis. No caller JSON or executable callback replaces them.

Core independently reconstructs the authored direct Boolean condition. It must
select and check the real Rule typed closure as well as the structural compiled
project graph. Property paths in that selected closure use the actual Entity
property identities. A serialized graph, a plausible closure hash or the technical
contract example cannot substitute for those owners.

The selected native ABI is `craft.u0.pure-submission/v1-candidate`; its invocation
is synchronous and has no effects, dependency override, store or transaction.
The HTTP handler is asynchronous only around bounded body acquisition. Its native
asset seam accepts an invocation for infrastructure tests; application binding
must obtain that invocation from the actual generated import owner. Seam tests
alone cannot qualify generated behavior.

The first wire example remains POST `/confirm-delivery`, 4096 request bytes,
1024 response bytes and 2000 body acquisition milliseconds. Native configuration
checks are not runtime qualification. C03's rejection maximum of 59 bytes is for
`delivery-verification-required`. U06c must compute the actual bound from the
checked authored rejection code (`U0ResponseDomainV2`) and check the configured cap
before binding; it must not generalize that fixture maximum to other codes.

Formal claims/definitions have a separate optional assurance projection. They
never supply executable Rule conditions. Required unsupported formal outputs
reject; optional unsupported formal outputs retain explicit status. Required code,
API and graph artifacts need actual producer/currentness checks before a complete
bundle can be finalized. Output metadata alone grants no completion.

## Ownership and contract epochs

The coordinator alone changes shared schemas, public exports, mirrors, package
registries, build outputs, materializers and native capture pins. Component tasks
change their assigned implementation/test files. Run the source-workspace mirror
check with `npm run business-contracts-v2:check` in Core. It checks six exact
data-only mirrors. Installed Alch code imports local mirrors, never this checkout.

The private execution evidence records an immutable J00 source manifest and its
digest. Every downstream task context records that manifest and rechecks its
contract members before starting. A contract amendment creates a new explicitly
reconciled epoch and invalidates affected downstream evidence; it does not silently
rewrite a completed manifest. Public builds and native captures remain serial.
Alch's split-package file closure is regenerated from actual built bytes at J01;
no generated `dist` or private release archive is changed by this contract task.

## Open Questions

Actual parser, semantic graph/input/review custody, generation, native codecs,
handler and output behavior are assigned above. New native artifact digests are
producer obligations until their bytes exist. J01 resolves the successor profile
against those actual assets. Formal model exporters remain a separate optional
branch. Local hosting, TDE, EVF, live identity/provider/database/broker activation,
deployment and publication remain deferred.
