# Commerce SDK and actual native profile production

The commerce profile selects implementation families from a checked technical
model. An unresolved native requirement is only a requirement. The source
producer now emits actual JavaScript for the implemented bounded-value and pure
computation families and records observed files, exports, versions and closure.

The Core and Alch public roots export the `commerce` namespace. SDK capture uses
compiled public entries, all nine registered schemas and actual current package
bytes, including Alch's exact TypeScript 6.0.3 runtime dependency. Final clean
installation/bootstrap qualification remains in-progress EC12 integration.
Whole application generation remains EC13 and the
later effectful slices; no provider, persistence or workflow primitive becomes
implemented by appearing in profile metadata.

## Actual pure native producer

`createCommercePureNativeProducerV5` requires the genuine original family owner.
`produce(family, sourceRoot, freshOutput)` checks the same original source/model
and permits only implemented pure primitives. It reuses the actual source codec
generator and direct computation compiler. Each selected pure root has emitted
TS/JS and its exact compilation manifest. Fixed native ABI adapters expose
check/decode/encode/copy and check/compile/evaluate operations over those actual
components. No serialized AST evaluator or user callback substitutes for code.

`inspect(product)` describes actual source lineage, complete profile data,
source-selected computation contracts and produced members. The native code
closure consists of actual JavaScript members plus the module package
configuration; the full profile product also
includes its source/debug/manifests and descriptor. Dependency versions come
from the actual Core producer package, and required exports are observed from
the emitted imported modules before resolved descriptor data is formed.

`modules(product)` returns function wrappers that check genuine product/family/
source/code/physical currentness before and after each native operation. Schema,
checked computation and compiled computation tokens live in original private
registries. Manifest JSON, copied output directories and cloned tokens cannot
construct those owners. Disposal or changed/same-byte physical replacement
invalidates already acquired wrappers. Occupied outputs are preserved.

Profile-model authoring and original application generation are separate
construction steps. Native production may validate the technical model and its
declared value domain. Its internal profile-authoring parents cannot stand in
for a later original application generation source handle. The public bootstrap
must load a real current native basis before preparing that new source prefix.
`produceForSource` can then consume the exact original Core stage owner/source
handle. `assertSourceParent` rejects a prototype created using earlier internal
profile-authoring parents. It cannot adopt a matching serialized inspection.

The source-specific kernels and their profile-shaped component records are
post-source generation outputs. They must not be used to stand in for the
reusable pre-source SDK/native basis. That basis needs actual generic compiler/
codec support and original late source/output binding; its public integration
and proof remain in progress. The detailed boundary is recorded in the EC12
NATIVE-ORDER-BOUNDARY evidence note.

## Wire and future composition

Bounded-value operations use the canonical public value ABI. The underlying
compiled pure component retains its explicit tagged computation wire for
algebraic variants. The actual codec adapter supplies
encodeCommerceComputationParameters/decodeCommerceComputationValue so later
generation can bridge those ABIs explicitly. The existing EC08/EC09 code and
wire contracts remain unchanged.

Pure native components do not construct private Auth, entry, invocation,
transaction, commit, delivery or worker ownership. The application scope retains
requirements on those still-unbuilt assets and is rejected by this pure-only
producer. Naming a new primitive or copying a plausible manifest supplies none.

## Reusable basis and original source prefix

The new public entry source is `commerce.ts` in each project. The Core
`createCommercePublicSdkV5(frontendPackageRoot)` bootstrap requires an actual
built Core package and matching built Alch package. Its physical capture includes
the actual running Node executable, complete dist/contracts/profile and frontend
runtime trees, and nine registered schema resources. A source execution, forged
capture token, missing public namespace or changed registered asset rejects.

The SDK exposes the genuine technical model and family owners. After checking
the technical source and deriving a pure family, call
`sdk.native.produceAndLoad(family, freshBasisRoot)`. It emits and imports reusable
native modules using the current public SDK. Their seven methods implement the
fixed value and computation ABI through private original source/output binding.
They contain no compiled application-specific kernels. Versions, semantic ABI,
exports, runtime members and SDK closure determine the actual basis identity.

Only the loaded original basis can enter
`sdk.native.prepareSource(basis, sourceRoot)`. This creates fresh Core and Alch
source captures after basis loading. The two parsers retain their own capture
identity algorithms: the join checks complete file paths, hashes and byte
lengths, alongside original physical custody. It never equates different capture
hash algorithms or turns matching JSON into an original source handle.

`produceForSource(prefix, freshComponentRoot)` emits the selected source-specific
codec and direct computation components. `bindComponents(prefix, product)` checks
their exact original source parents and derived family before creating a private
binding. `native(binding)` then exposes the seven ABI methods over that original
binding. Copied tokens, foreign source/product pairs and cross-binding schema or
compiled handles reject. Acquired wrappers retain current SDK, basis, source and
output checks; disposing any required parent invalidates their use. Calling a
generic module directly without the original binding rejects.

This is source-to-native **component** binding. It is not a whole generated
application, imported API, private entry authorization or transaction context.
Those original EC13 and later construction steps must consume the genuine
parents and actual outputs rather than borrowing this component qualification.

The first EC12 integration tests used isolated, serialized build candidates.
The public root exports and schema/doc package allowlist are now integrated,
with predecessor bytes archived. Actual canonical builds pass; final clean
public-package installation and bootstrap qualification remain required. An
isolated successful replay alone does not close EC12.

## Selected pure source review and input

The built public bootstrap exposes `sdk.stages` over the original native prefix.
The caller supplies an explicit review owner, an existing absolute decision
output directory, and an accept/reject outcome. Formal claims remain optional.

```typescript
const parents = sdk.stages.prepare(prefix, {
  reviewOwner: 'example-maintainer',
  decisionRoot: absoluteExistingDecisionDirectory,
});
const selected = sdk.stages.selection.select(
  parents.source, parents.profile, parents.basis,
);
const early = sdk.stages.selection.prepareEarly(selected);
const review = sdk.stages.reviews.review(parents.source, selected);
console.log(sdk.stages.inspectReview(review));
// The caller explicitly chooses this outcome after examining the review.
const decision = sdk.stages.reviews.recordDecision(review, 'accept');
const input = sdk.stages.formInput(parents.source, selected, early, decision);
const product = await sdk.stages.produceForInput(input, absoluteFreshOutput);
const binding = await sdk.stages.bindForInput(input, product);
const native = sdk.stages.nativeApi(binding);
```

Selection checks the actual application profile source, Mapping and parameters
against the loaded original family. Early requests account for real source
obligations and actual loaded native ABIs/exports. Review combines the original
Core source review with that exact selection and early request. The explicit
decision writes an exclusive source decision and an exclusive selected decision;
changes or replacement invalidate the resulting input and its acquired native
wrappers. A rejection cannot form an input. Copied, foreign and cross-selection
parents cannot acquire custody. Disposing the stage context also invalidates
accepted wrappers.

This path generates the selected pure components. It does not establish whole
application, service, API, graph, bridge or protected-entry acceptance. The
lower-level `native.produceForSource` remains a separately qualified source
component API. The selected path binds production and every native call to the
original accepted input; an ordinary native binding cannot be passed as an
accepted binding. Release accepted bindings before disposing their stages.
Current source/build/installed qualification is recorded by the original EC12
execution evidence; the implementation alone is not a qualification receipt.
