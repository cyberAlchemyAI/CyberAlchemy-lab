# Commerce source and lowering contract

This is the EC05 candidate specification. `COMMERCE-GRAMMAR-V1.ebnf` owns syntax, `tools/commerce-contracts/source-contract.json` owns the finite defaults and diagnostic mapping, and the nine Core schemas own the role data shapes. None is a shipped parser, checked business graph, executable generator or native qualification. EC06 implements parsing/linking, EC07 independently reconstructs semantics, EC08 implements the computation successor, and later tasks implement their native producers.

## Source and names

Source is strict UTF-8, with Unicode scalar JSON strings and two-space indentation. Blank/comment-only lines do not affect indentation. Tabs, skipped indentation, inconsistent dedents, malformed strings and trailing tokens reject. `#` begins a comment at the start of a line or after whitespace outside a string; an attached `#/...` is a JSON pointer within a reference. Paths use the normalized relative-path contract and must remain inside the captured root without symlink escape. Reference spelling is not permission to read arbitrary files. Each referenced pointer must resolve to the registered contract and expected shape.

Imports precede declarations. In `use Shop.Values.Identifier, Currency`, a bare item inherits the last qualified item's module; no globally unique-name fallback exists. Local declarations and imported aliases cannot collide. Every ordinary declaration has its containing module identity and source byte span. A qualified entry declaration is already its exact logical entry ID. The `entry` surface composes Interface, Rule and Policy; it adds no meta-type. `formal-claim` is optional assurance metadata targeting existing declarations, also not a new executable meta-type.

Signature/value dependencies must be acyclic after projecting imported records, refinements, enums and pure calls. A module communication cycle is allowed when it does not create a recursive value or pure call dependency. Orders and Inventory refer to each other through typed entry contracts, not imports of each other's private tables. Private local helpers remain callable only in their owner module. An internal Interface's `exposes` list supplies its exported operations/queries; API or service callers go through a declared entry. No profile can elevate visibility or entry permission.

Unqualified enum patterns resolve against the checked subject enum, never against an arbitrary global tag. An unqualified enum value in a state-machine initial/transition clause resolves against its declared state or input type. Qualified values must name the same enum. Duplicate variants/fields/binders, mixed unrelated variant payloads, recursive data, unknown fields, unknown versions and ambiguous names reject. An enum may contain nullary values or payload variants, but may not mix wire representations in one declaration. Nullary values encode as declared strings; payload variants encode as closed `{kind:<tag>,...payload}` records. A one-field positional constructor consumes that field; several positional fields use declaration order, while named arguments require the exact declared field set. Calls cannot mix positional and named arguments.

Record `version 1` is schema metadata for Event; `version UInt64` is a data field. Entities require an identity; updates need the full declared identity or declared unique key, the exact original row and expected version. Missing `immutable` means no additional immutable fields; identity fields remain immutable. `immutable all` includes every field, including version. A create supplies every field once, including optionals (`none` explicitly); a partial update preserves unspecified fields and cannot change immutable fields. A declared version field must advance exactly once per committed update; immutable-all records are insert-only. A profile cannot introduce missing business data values.

Transparent String Value Objects are bounded scalar refinements. If `unicode-scalars` is absent, minimum is the declared minimum UTF-8 bytes only as a byte constraint, while scalar bounds are 0 through the declared maximum UTF-8 bytes. Normalization/case folding/trimming are always none. Patterns are restricted to the registered bounded pattern subset: anchors, literal ASCII characters, character classes and finite repetitions; no callbacks, lookbehind or unbounded regex. `String` without a declared refinement/bounded expected context rejects rather than inheriting an arbitrary global limit. Lists are finite, with maximum 1..100; plain `List<T,n>` permits 0..n unless a declared associated predicate strengthens it. ValidQuoteLines/ValidStockLines are associated explicitly by CommerceValueDomain.

## Pure expressions and meta-types

Numeric literals are exact UInt64; Bool literals are Bool. Strings/refinements, optional `none`, empty lists, record/enum constructors and function arguments use the checked expected type and bounds. An unresolved expected type rejects; there is no `Any`. Refinement-to-carrier projection for pure equality/sorting preserves exact bytes/scalars; constructing a refinement validates its bounds/pattern. Structural equality covers checked records, enums, optionals and lists and preserves source ordering. Arbitrary object prototypes/functions/contexts are not values. Pure records are constructed by declared field order; wire serialization uses canonical key order independently.

Operator precedence is the EBNF order. `and`/`or` short-circuit; implication lowers to `not a or b`, inequality to `not eq`, and membership to bounded structural equality over the checked list. Other arguments evaluate left to right. Arithmetic is checked UInt64. Default division rounding is reject; a Calculation can explicitly select floor/ceil/reject. `require-some` and `require-variant` failure is an evaluation `InputType` at that expression path, not Bool false. `length` accepts a List; strings require `length-utf8` or `length-scalars`.

Rule has one Bool expression and no effects. Calculation has an explicit result type, body and typed evaluation failure. Mapping has one of three bodies: exact field mapping, total ordered cases, or a typed expression (including an exhaustive variant match). It never gets a missing body from a formal claim. `preserve` requires exactly one declared record input of the target type; preserved and assigned fields are disjoint and cover the target completely. Mapping `requires` is a pure precondition with `InputType` on false; it performs no authorization or effect.

Ordered Mapping cases lower to checked `if` nodes in source order, with exactly one last otherwise case. Policy cases select a declared Calculation of the same result type; Policy owns the named `policy` AST and a mandatory otherwise Calculation. Rule/Mapping/Calculation calls use checked `call` nodes with exact signature/argument order, an acyclic call graph and shared fuel; names cannot dispatch to an Operation or context method. A context projection becomes a pure input only after its real owner supplies its declared bounded data; a pure declaration cannot acquire that owner.

Maps/filters/folds preserve source order and have typed hygienic binders. Indexed fold adds a UInt64 index. `repeat(count,max n,initial,state:T,index:UInt64 => body)` checks count against n before iteration. `while-bounded(max n,initial,state:T,guard => body)` and `until-bounded` test before each body; reaching n with further work required yields IterationLimit. `range(start,end,step,max n)` is ascending, end-exclusive and rejects zero step or a count above n; start>=end yields an empty list. Every explicit maximum is 1..100 and cannot exceed the selected limits. Binders cannot shadow or escape. Shared fuel/byte/call-depth budgets span nested invocations; each nested expression does not get a fresh budget.

Sorting accepts the simple field form or typed multi-key form. Each key has direction and numeric/lexical/natural mode. `binary-utf8` normalizes to lexical over valid scalar sequences. Lexical compares scalar code points with no normalization/locale; natural compares alternating ASCII digit/non-digit runs, digit magnitude, then run length to resolve leading zeros, then subsequent runs. Equal complete keys retain original order. No user comparator, host locale, collation or effectful key extractor is admitted.

StateMachine is a pure proposal function, with state and input parameters and the existing `state_machine` AST. `Machine.propose(state,input)` resolves to that declared function; `propose` is not a global command. This revision emits no intents: intent type is Bool with max_intents=0. Terminal declarations describe states, not an implicit persistence or blanket ban on explicit self-transitions. Initial and terminal values must belong to the state enum; transitions are first matching, with typed optional guards. Otherwise stay/reject is explicit. The result is `outcome<State,Bool,0>` with tag transition/stayed/rejected, state, empty intents, machine, branch and reason. Reject is successful proposal data, not an evaluator exception. Callers must inspect the tag before using state to mutate a record. This specifically applies to Orders.RecordCheckoutObservation; it maps each observation to the declared CheckoutSignal, checks transition, then passes proposal.state to StoreObservation.

## Operations, reads and local transactions

Operation is structured effect control, separate from the pure AST and Workflow coordination. Lexical statements lower into source-owned blocks and typed actions. Every block/reference/result/handler has an identity derived from its containing declaration and original source span; no caller can register a callback or supply a competing generated implementation. Nonloop edges are acyclic, paths have checked result types, use-before-bind rejects, and loops range only over bounded collections. `source_order` retains lexical provenance; the blocks own control flow. Every data reference has one declaration, and every declaration must be reachable or explicitly nonexecuting protocol metadata.

Bare `requires e` means reject precondition-failed when e successfully returns false. It does not catch arithmetic/resource errors. Absent expression error handlers mean fail calculation-failed before a transaction, or proven-rollback then fail calculation-failed inside it. Explicit `on-false`, `on-error` and Calculation `on-evaluation-error` override the applicable failure channel only; the immediate enclosing expression handler takes priority, then declaration handler, then the fixed default. A guard/error after dispatch must retain original command/journal and cannot assert no effect. Failures include provenance and original uncertainty separately from their public error code.

`let x = count Entity` is a service-owned store read, not a pure intrinsic. It checks the bounded count without scanning unbounded data; unavailable means outcome-unknown. The retention admission limit is rechecked in the same transaction that creates a new record. Matching recorded receipts remain readable when capacity is exhausted. `read x Entity by ...` without on-missing binds optional<Entity>; an explicit on-missing action narrows x to Entity on the continuing path. `on-present` applies to the nearest preceding read's value until the next read; an explicit subject overrides it. It unwraps only on its true branch. Flat read handlers attach immediately to that read, exactly like indented handlers; they are never free-standing handlers. Duplicate handlers reject. Unavailable defaults to fail outcome-unknown, never none/missing. Reads from an entry need its exact argument/output/context contract and fresh target permission; optional outputs and declared not-found are distinct.

`on` with a Bool expression is an ordinary conditional; with a variant/tag list it narrows the checked subject. An omitted subject means the immediately preceding call result or bound disposition; absence/ambiguity rejects. `before ...` is a checked ordering constraint on those effects, not an effect itself. A matching branch returns before later statements are evaluated. It does not pre-evaluate ID/clock/quote/provider expressions. Missing a branch means continue lexically, not a fabricated outcome. `return Helper(...)` for an effectful local Operation or Query lowers to invoke-return, never a pure call. Inherited contexts are the actual original live compatible invocation owners; they cannot be acquired from arguments, JSON or hashes. Cross-service calls must target declared entries. Calls cannot recurse; errors from an unhandled call propagate their typed failure retaining original uncertainty.

Query is read-only. Local queries lower to ReadPlan sources with typed bindings, inner joins, checked predicates, guards and projection expressions, typed missing/unavailable actions and bounded max_rows. All sources belong to the same service. Lookup identities/unique keys or a declared bounded set are required; there is no unbounded table scan fallback. A single-output query rejects multiple matching rows. For optional output, a projected element is wrapped in some; an explicitly optional projection must already match the output. No row runs the declared missing action. `delegates` expands a declared Query with checked argument substitution/context forwarding and a cycle check; its explicit output must match. A native protocol Query instead targets its declared external Interface/ABI. It does not masquerade as a local table read. Effects none is always enforced even when its redundant source clause is absent.

Read-set loops collect closed row data with original row identity/expected-version provenance. `bind line, stock, expectedVersion = stock.version` defines an anonymous closed record type scoped to that read-set. All declared checks complete before any transaction writes. No row/capability escapes to another service or process. Sorting stabilizes acquisition order; CAS still rechecks every affected original version.

Transaction constraints carry explicit require-absent entity/key tuples and retained-record capacity entity/maximum. Capacity source shorthand resolves the retained entity from its declared replay/preflight contract; ambiguity rejects. Both checks run inside the actual transaction before mutation. Mutation bodies are ordered and include typed local let bindings and record-event constructors as well as creates/updates/conditional/loop nodes, so event/result aliases are defined before use even inside a conditional. Outbox descriptors bind the exact outbox entity, outbox row alias and event alias to the checked source mapping/metadata callsite; they do not separately execute or duplicate a send. Transaction participants are exactly the declared service-owned entities; record-event forms checked immutable event data but sends nothing. Insert/update/outbox rows, all affected version/invariant/unique/capacity checks and result materialization occur atomically. Source-local aliases refer to validated provisional rows inside the same transaction; they escape only after a committed result. All needed pure computations occur before the first physical write or inside a rollback-capable transaction. Original row locks/CAS/commit/rollback evidence belong to the actual storage owner. Canonical full-range UInt64 TEXT/BLOB rules are in COMMERCE-NATIVE-V1.md.

Transaction on-version-conflict/on-unique-conflict/on-arithmetic-error/on-invariant-error handlers run only after actual proven rollback. Specific source handlers take priority, then an explicit on-proven-rollback handler for rollback-proven outcomes, then fixed defaults. Absent handlers reject transaction-contention, reject identity-conflict, fail calculation-failed and reject invalid-stock-invariant respectively. on-proven-rollback otherwise fails transaction-rolled-back. on-unknown-commit otherwise fails outcome-unknown retaining all original participants/command/ticket. A thrown/timeout/storage exception cannot select a rollback handler without proof. Rollback failure becomes indeterminate, suppressing the planned conflict or business rejection. Unknown commit may only return an explicitly typed Unknown/Pending result, fail retaining original evidence, or inspect the original command; no create, new dispatch or replay-as-fresh is allowed.

The finite recovery shorthands are typed templates, not string evaluation. `resolve original replay-record` rereads the exact prior ReplayRecord key/fingerprint under current action access and reapplies CheckoutReplayGate once; accepted returns original receipt, other outcomes preserve their original errors, absent after uncertain conflict remains outcome-unknown. It never reruns PlaceOrder. `reread original inbox` rereads the original consumer+occurrence and validates fingerprint/order before returning the stored receipt; absence/unavailable remains outcome-unknown. `rollback-all then reread original inbox-or-shipment` first proves rollback, then uses original consumer/occurrence/order keys: inbox exact match returns its receipt; shipment exact order fingerprint returns its view; conflict rejects the source conflict code; absence/unavailable remains outcome-unknown. These templates refer to the source's checked keys/Rules, not callbacks. Native conformance Operations with ordered-protocol are non-invocable protocol constraints used by preflight contract; they never become an implicit generic executor. Native DemoPay Capture/Inspect have the finite adapter contract from their declared Interface and registered wire protocol.

## Workflow and event defaults

Workflow coordinates declared entries and local observations using its typed WorkflowContract. Source snapshot/claim/observation drivers include actual argument expressions and result types; every driver ID/signature is cross-checked against the entry/Operation. An unknown step/state/driver/output mapping blocks generation. Every remote result variant is handled in source order, with a mandatory call-failure path or the declared fixed suspend behavior. Repeated variant patterns are allowed only as guarded first-match branches with an unguarded final case. An otherwise-unhandled variant or failed success require suspends at the same persisted state with the original journal retained. No empty data is substituted. Source labels such as same-state, ownership-unresolved and needs-review normalize to tagged control outcomes; persisted states normalize to the declared state enum. These categories cannot be confused or written as arbitrary domain states.

Snapshot is reread before dispatch and after a committed observation. Snapshot missing stops with resource-not-found; unavailable suspends with no dispatch. Claim is CAS against the current progress version and actual private worker predecessor evidence; contention stops this worker, unknown retains unresolved ownership and starts no step. A restored workerOwner/workerEpoch row is data, not a live claim. All contexts/entry decisions are fresh independently of worker lifetime. At most64step transitions may run in one resume call; exhaustion suspends with the original journal/current persisted state. The private owner's unresolved resources remain retained; a later resume needs its original current owners, never renewed tickets from DTOs.

Observe uses the original exact observation and current Order/Progress versions. Contention rereads and reapplies that observation without redispatch. Unknown invokes the declared inspection with the original observation, and only original commit/quiescence evidence may resolve the pending ticket. A recorded view alone does not issue a fresh continuation. A then-target runs only after fresh acknowledged local observation and a matching reread state; otherwise run the resume table. Evidence conflict records the original command's EvidenceConflict; if that local commit is unknown it also suspends. Local mark-dispatched requires the same local observation path. Only actual never-dispatched journal proof permits first provider dispatch after recovery; clock expiry/absence/UnknownKey cannot supply it. Finish checks the declared persisted terminal guard against current owned rows and performs no domain write. Failed terminal guards suspend instead of falsely completing.

Event wire envelope has exactly schema_version, event_type, event_version and event. Schema version is craft.commerce-event/v1-candidate, event_type is the fully qualified Event selector, event_version is canonical decimal string1, and event is the exact closed source Event value encoded by its checked schema. Metadata exists only in event.metadata; it must agree with the actual registered producer, aggregate/version/ordinal/command, source event slot and occurrence fingerprint. It does not confer producer authority. Envelope cap is131072bytes, including metadata/keys/escapes. Internal event schema/value cap is524288bytes, but an oversized encoded envelope is OutputBound and cannot enter the relay.

Selected event routes are exactly the declared two event projections; payload arguments are placed and confirmed respectively. Workflow enqueue commits WorkflowInbox+WorkSchedule and returns WorkScheduleReceipt before acknowledgement; it does not run checkout effects inside enqueue. Fulfillment commits ShipmentInbox with the source declared shipment/outbox result before acknowledgement. Duplicate exact consumer+occurrence returns the stored receipt without effects; differing fingerprint is conflict. A terminal event from a different occurrence is checked by the source order fingerprint too. Do-not-ack is the default for failed, rejected, unknown or unproven commit.

Acknowledgement on the selected injected service port is an original local commit receipt/result owned by that actual consumer; it is not a public constructor or a JSON Bool. An untrusted byte acknowledgement reports transport acceptance only. `CommerceEventDeliveryV1.consumer_completion` becomes observed-original-local-commit only when the selected original owner recognizes that receipt for this event/consumer. Peer disconnect, byte timeout or repeated delivery never implies no effect. No broker, network listener or distributed commit is selected.

## Profiles, outputs and diagnostics

Existing meta-types describe the technical model and finite families. The pure selection Mapping sets profile fields; selected scope determines its actual dependency closure. No future producer hash/version is invented. Scope pure-pricing can use bounded values/computation before SQL/Auth/HTTP exist; application scope still requires every actual selected obligation. Parameters are checked against declared pattern and exact operands; unknown fields/native exports/primitives reject. Native signatures, source contract refs, ABI versions, packaging and six capture barriers are in native-contract.json and producer-stages.json. Cross-package mirrors do not share nominal owners: the bridge retains actual original Core objects privately after Core's independent reconstruction.

The root application captures exactly its source/module/service/entry/profile/contract closure. It requires code, API contracts, business graph, system graph and business-system bridge, each linked to original source/profile/native/output owners. A missing output fails RequiredOutputUnavailable; a hash/inspection JSON cannot replace the output or owner. Imported generated bytes precede late binding/views. Component generation does not confer full application admission.

Diagnostics have the finite code union in CommerceDiagnostic, path and start/end UTF-8 byte offsets into original captured source, plus a bounded explanatory message. Syntax/shape errors precede linking; names/types/role/coverage checks precede native resolution and output production. Stable code and source span are contractual, free wording is not. The exact category/producer table is in source-contract.json. Pure runtime failures use the separate ExpressionFailure schema with expression_path/index_path/call_path; their presence cannot satisfy a source/owner/native diagnostic. Zero formal claims remains valid; optional external proof sources are bounded captured assurance assets and are never invoked to generate or authorize executable behavior.

## Open Questions

The grammar/default/role data contract is frozen by EC05 only after its actual source/mirror/identity checks. Implementation conformance belongs to EC06–EC12 and the later local-effects/protected-entry/provider/coordination/application milestones. The known H01 test-inclusive TypeScript residue remains separately recorded; source typecheck does not close it. Local hosting, TDE, EVF, publication/deployment and live activation remain deferred. No new user decision is needed for the bounded contract work.
