# Commerce successor contracts

EC05 adds candidate data contracts beside the tested U0 surface. Core owns the nine schemas generated by `tools/commerce-contracts/schema-source.py`, their TypeScript data declarations and the stage interfaces in `src/commerce/`. AlchLang receives exact generated local mirrors. There is no runtime implementation or public root export added by defining these types.

Run the schema generator without flags to compare generated bytes; `--write` materializes its owned files. `tools/commerce-contracts/mirrors.py` checks the stage and native mirrors. New source can be typechecked independently of building/capturing an SDK. Shared/public exports, package membership, builds and native closure records are coordinator-owned stages; actual commerce capture starts at EC12 after the assigned implementations exist. Existing frozen packages and U0 schemas retain their original scope.

The value contract describes closed records, scalar refinements, bounded lists, optionals and closed algebraic enums. Its computation successor is `domainspec.iteration-expression/v2-candidate` with `ordered-metered-commerce-v2-candidate`. It preserves the old v1 contract instead of relabeling it. Maps, filters, folds, indexed folds, repeat/range and bounded condition loops have typed binders. Sorting has explicit numeric, Unicode-scalar lexical or fixed ASCII-digit natural modes and direction; equal keys retain source order. Host locale and arbitrary comparators are unavailable. Algebraic constructors/matches and structural equality operate only on checked bounded values. Pure declarations cannot read stores, invoke transport, obtain clocks, issue identities or run arbitrary callbacks.

The unshipped candidate contracts now preserve exact literal field values, both UTF-8 and Unicode scalar minima/maxima, enum wire values and Event schema versions. Zero maxima describe an empty-string domain, never an unbounded string. Explicit dynamic refinement construction emits `validate_refinement`, checks the named declared refinement and yields InputType on an invalid value; it is not an unchecked cast. A Policy action retains its entire expression, including source-ordered hygienic argument lets and its selected Calculation identity. Only the selected branch evaluates its action. Every pure declaration carries its own rounding and evaluation-error action. Its listed preconditions describe checks already embedded once in its body; a consumer must not execute that list a second time. StateMachine ASTs retain initial/terminal states and the declared fallback rejection reason. The independent Core pure-contract projector rebuilds these fields from source; its returned JSON is candidate data, not a checked/native owner or evidence of actual evaluation. EC08/09 still implement the runtime/codec consumers, and structured native callsite/private projection fidelity remains a separate role-contract obligation.

Schema shape is the first boundary. Semantic owners must additionally reject unknown names, duplicate symbols/variants/parameters, record/enum cycles, incompatible field types, invalid optional/variant extraction, non-exhaustive cases, unused/missing mapping fields, source-order errors, incompatible profiles and out-of-domain counters. Recursive schema syntax does not admit unbounded runtime types: source/value depth, record count, AST depth, call depth, bytes, iterations and fuel are explicitly bounded. The matching EC03 source contract owns their selected values. An absent required optional/variant is `InputType` at its expression path; it is never a false Rule value or an unchecked cast. Zero formal claims is valid. Optional assurance never supplies executable conditions or effects.

Reads, local transaction effects, durable workflows, entries and profiles remain separate role contracts. They join through typed selectors and explicit source order. Their closed `RoleExpression` carries a checked result type, a position-preserving `FlowExpr` and exact reachable local-record projection requirements. Native observations remain inside their original argument, branch, match, loop or sort-key position; a list of native calls must never become an eager prelude. Private context leaves carry the captured ABI, source type and bounded field schema with public construction forbidden. These fields describe requirements for recognized original owners and do not acquire owners or execute native code. Pure `Expr` and computation contracts remain free of native/private nodes. Named pure, record and enum constructors evaluate argument expressions in authored order before assembling their declared parameter/field order.

Read plans distinguish local keyed reads, typed delegation with original context forwarding, and native protocol obligations. Effect plans retain ordered Operation control separately from ordered transaction steps, exact keys/versions, result/failure actions, rollback/indeterminate recovery, provisional aliases and inbox acknowledgements. Workflow plans retain inbox identity/fingerprint, worker ownership, actual snapshot/claim/observation drivers and inspection inputs, branch retention/restrictions, persisted resume/terminal guards and fixed suspension defaults. Entry contracts retain inline permission, original Auth/context/decision requirements, exact resource origins/fields and phase, fresh invocation decisions and committed event-completion evidence. A permission-only entry needs no invented guard Rule or formal claim. Shared/native declarations have an explicit null service where source ownership is absent; a projector cannot invent a service owner.

`commerce-core-role-contracts.ts` freshly reconstructs each role from source and captured assets before projecting its separate candidate contract. Whole-proposal comparison rejects erased native positions, private fields, permission/recovery/guard changes and added ownership claims. The returned `independent-source-role-contract-data-only` data is not a semantic/review/native owner, executable implementation, or public runtime support claim. Raw protocol tokens are preserved source/conformance evidence under an explicit noninvoking or original-producer-required mode; they are not an executable hook. Producer/runtime consumers must implement the checked role control and acquire the original owners separately.

Transaction mutations use checked field expressions and exact expected versions. A profile maps already implemented native families; it cannot implement an absent database, transport, Auth owner or payment adapter. Native obligations intentionally lack future hashes/versions; resolved records require actual produced bytes and exact versions. The selected provider is synthetic DemoPay-v1 over injected byte ports. Each service owns its scratch SQLite state. No new production service or broker is selected.

An entry composes existing meta-types; it is not a new meta-type. Permission stays inline with the entry. Resource guards refer to checked Rules and explicit private causal/intent/scoped-row binding producers. ResourceProjectionType separates a data value view from an owner-provided private context projection. Private projections are excluded from serializable ValueType; a public codec cannot construct one. Its declared bounded fields are extracted only after the actual original owner is recognized. Missing/foreign owned resources retain the declared 404 outcome. Current action authorization precedes replay and effects. Worker lifetime custody and fresh entry decision custody remain separate. Resource phase is explicit: fresh planned intents before effects, scoped query rows before response, or private causal inputs before invocation. PlaceOrder repeats check current action and trusted replay scope without constructing a new intent, clock/Order ID or quote read; its planned-Order guard applies only to fresh work. This phase split does not move permission away from the entry.

The component APIs accept data for bounded schema/semantic/generator tests. Full application APIs require original registered source, selection, early request, decision, input, checked graph, generated/imported output and selected native owners. Unique TypeScript brands are documentation/type boundaries; actual implementations must also recognize original objects in private registries and revalidate source/config/native/output currentness. No serialized inspection record or graph hash can recreate them. Actual imported output must precede late native binding and system/bridge projection. Generated business evaluation cannot be replaced by a handwritten application callback.

The complete candidate syntax is [COMMERCE-GRAMMAR-V1.ebnf](/home/vlad_/projects/cyberAlchemy-v2/craft/projects/domainspec-v2/impl/cli/docs/COMMERCE-GRAMMAR-V1.ebnf); [COMMERCE-LOWERING-V1.md](COMMERCE-LOWERING-V1.md) specifies names, defaults, typed control, StateMachine proposals, event wire/acknowledgement and source-to-role lowering. `tools/commerce-contracts/source-contract.json` freezes the finite role/default/diagnostic contract. The earlier pure grammar remains a historical fragment. The independent EC05 EBNF recognizer checks syntax only; the production parser and independent Core reconstruction remain EC06/07. The repaired Orders source preserves the exact original EC02 bytes and records its explicit source succession. Read plans now carry actual local joins, predicate/projection/guard expressions and typed outcome actions; effect plans include full mutation keys, count/local-call slots and all rollback/error channels. Workflow plans include driver input/result bindings, typed control suspension targets, terminal guards and bounded resume transitions.
