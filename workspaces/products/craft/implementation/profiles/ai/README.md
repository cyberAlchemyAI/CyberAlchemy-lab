# Shared native implementation profiles

This is the mutable local implementation of the selected reference-application
DAG. Existing Craft/AlchLang source, authorization, persistence, workflows and
C03 generated codecs/bindings remain reused. Native owners add actual effect,
source-release, accounting, parser, index, identity and connector behavior.

Business requirements live in the six reference applications' `.alch` files.
Profiles connect those checked models to the selected native implementations.
Recorded model/provider responses exercise generated code without making live
provider calls. Actual PDF parsing, index ranking, cryptography and persistence
must execute wherever advertised. Source/profile generation is not provider
qualification. No public repository is created or updated by this work.

## Use the selected profiles

The portable `alchlang-generic generate-application` command consumes an authored
application project and computes identities from this installed package. The
application API is exported from `@craft/ai-profiles/application`; source-owned
knowledge stages, supplementary graph views and observations have separate public
subpaths. See [application ownership](native/application/README.md) for the runtime
boundary. Direct inference requires `@cyberalchemy/are-model-transports`; the
separate agent export additionally requires the optional ARE coding runtime.

`application-system-graph.json` and `application-business-system-bridge.json`
join native selections to the original generated Core graphs by exact hashes.
They retain the original Core artifacts and distinguish source formation from
runtime/provider evidence. Credentials, source access, human approval and owned
storage remain trusted host resources.

## Open Questions

The enclosing distribution and suite reports identify the exact local artifacts
and checks. Package installation or source generation alone does not establish a
completed six-application runtime suite. The selected scope is 32 local tasks;
credentialed-provider qualification, measured actual-model quality, optional
integration follow-ons, local hosting, TDE, EVF, deployment and publication remain
separate. No public repository is created or updated by this package.
