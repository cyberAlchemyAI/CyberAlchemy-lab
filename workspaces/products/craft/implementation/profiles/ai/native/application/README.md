# Generated application profiles

`compileApplicationProfile` preserves the exact authored business source as a
byte prefix, retains additional canonical source components with exact body spans, and appends protected technical job, result and workflow Entries.
It reuses the generic event/SQLite/Auth generation path and original R03 source
workflow. The generated operation calls the selected authored business operation;
JavaScript does not reproduce its eligibility predicates or calculations.

`createApplicationAccess` consumes original native Auth transfers for every read,
evaluation, command and inspection. A retained `openFence` checks the original
READY transfer synchronously across native effects. An optional credential lease
refreshes current trusted membership before asynchronous boundaries and checks
credential expiry synchronously.

`createApplicationSourceGateway` reads actual document-role bytes under the
original protected principal Entry. Profile projections select fields, constants,
records and bounded lists; they contain no expressions. Current source versions,
ACLs, full context manifest, candidate bytes, clock, destination, release decision
and owner approval are supplied by their original owners. `extendContext` accepts
an original opaque release manifest and includes all dependencies, including
uncited sources. Approval sources stay outside their own disclosure manifest.

`createApplicationWorkflow` binds selected handlers to original opaque R03 stage
ports. Native stages use original model/exposure/effect/source owners and exact
installed artifact identities. A native unknown remains unknown until the
original owner supplies an observation. Public status excludes model proposals
and source context. Provider fixture success does not establish provider quality,
issuer qualification, live delivery or production readiness.

`createApplicationAccess.assertCurrent` uses the original runtime registry/source/Auth/store-physical authority check when the selected SDK exports it. `assertStorageCurrent` preserves the full original journal/schema validation at native binding, last dispatch, awaited HTTP completion and result disclosure. Every actual generated Query/Command still invokes its original owner checks. No permission, query value or business result is cached across effects.

`createApplicationQuerySource` exposes actual protected generated Query results to the original source-release adapter. It retains opaque leases, not serialized grants. A source store change or original Auth revision invalidates an old observation; a fresh protected read is required. Optional `recipientRelease` source configuration checks all actual full-context inputs against each source-selected recipient before setting the internal protected-context fact.

The public consumer fixture accepts `CRAFT_NATIVE_PACKAGE_ROOT`, `CRAFT_REFERENCE_APPS_ROOT` and `CRAFT_GENERATED_APPLICATIONS_ROOT`; the last contains actual CLI outputs under crm/marketing/invoice. The singular `CRAFT_GENERATED_APPLICATION_ROOT` remains supported for an individual CRM output. Test fixtures use public installed exports; development package staging is conditional and never substitutes for an installed final tuple.

## Open Questions

The selected app profiles and final installed SDK/package closure remain owned by
the cumulative reference-app objective. Final qualification requires the actual
model, provider, identity and runtime environment selected by its operator.

The checked technical-profile provider installer also supports a finite runtime
Policy family. Its only argument is `owner.observation.attempt`, captured inside
the original stage from its real effect journal and retry owner. The source
Policy selects Dispatch, Backoff, InspectOriginal, Finish or Halt. The installer
binds the exact source/envelope/selector into the capability identity and calls
the original source evaluator; applications supply account, credential and HTTP
resources, without capture/invoke callbacks. Original business, actor,
disclosure, attempt and deadline checks still apply before and after awaits.
A Policy cannot turn unknown or completed work into another send. A longer
Backoff is persisted by the original effect owner. Finish requires an original
confirmed observation and current disclosure authority.

This family's effects are conservatively Mutating. It rejects `readCurrent`
and credential actions/inputs; the broader generic runtime binding remains a
separate original-owner adapter surface. A provider-specific 401 refresh codec,
a new native action ABI, or arbitrary evidence/credential inputs need their own
supported original owner, rather than a claimed caller observation. See the
existing Open Questions section for the remaining qualification boundaries.

## Source-generated application inputs reuse the existing wiring

`deriveApplicationInputs` consumes a genuine checked `craft.application-inputs/v1`
source selection, exact business role assignments and a nonsecret environment
identity. It derives the current application intent/source/profile arguments and
retains the original provider, composition and architecture source selections.
It does not calculate provider capability identity from a raw Mapping result:
`prepareTechnicalApplicationProviderStage` remains the original owner of the
normalized selection, account/native identity and final capability digest.

`openGeneratedApplication({directory, resources, mode, expectedMetadataSha256})` is the thin generated
input integration path. Its generated wrapper supplies the pinned metadata digest;
callers normally import that wrapper's `open` function. It calls the existing generated native bootstrap,
`createProviderStages({access,gateway})` and `createApplicationWorkflow`; it does
not replace their factory installation, effect recovery, Auth checks, workflow,
HTTP or cleanup behavior. The caller supplies low-level original host resources,
not per-application connector constructors or worker/handler Maps. Opening starts
no listener; `advance` remains explicit. Original customer actors may be supplied
per request through the existing host issuer.
The model resource must include public `identity` matching the selected inference
environment record and a client `baseURL` matching its destination; they cannot be
omitted to bypass the generated selection. This is configuration matching, not
real-provider/model qualification. Local fixture identity support is
not production Auth/session qualification.

The Query-source extension supports bounded `subjectInputs: {prefix,inputField}`
as an alternative to the existing static input Map. Its opt-in
`resultView: {kind:'single-record',identityField}` requires one non-null,
subject-correlated result and exposes `{record: value}` while retaining opaque
Query observation leases/currentness. Legacy Map/records mode stays unchanged.
Preference `record.version` is a business UInt64; the observation revision remains
an independent opaque SHA256 identity.
The original source-release registration returns its own retirement token; Query
source close retires that registration so the same borrowed release owner can
attach a fresh source on reopen. A retired token cannot remove its successor.

For the why, role/source boundaries, selected commands and resource responsibilities,
see the matching Core guide `docs/APPLICATION-INPUT-PROFILES.md`. The existing
Open Questions above continue to own production/provider/model qualification;
hosting, TDE, EVF, deployment and publication remain deferred.


### Private state and explicit original modes

`openGeneratedApplication` accepts the digest embedded in the generated wrapper as
`expectedMetadataSha256`. It checks that metadata and its pinned file inventory
before mutable resource creation. The owned path reopens the selected layout's
`architecture.runtimeApplication`; a genuine borrowed owner must represent the
same generated business source.

The top-level `mode` belongs to the original application store. `resources.journal.mode`
may explicitly choose the original Workflow journal mode independently after
partial startup (for example, store `reopen` plus journal `create`). The host must
provide an existing physical private state parent. Local acceptance notes are
written in that parent; the original Workflow driver alone creates its journal
directory. The integration neither pre-creates/chmods that directory nor deletes
existing stores/history to recover from a failed open.

`approvalBinding(actor, {id,run})` delegates a read-only binding inspection to the
original gateway for an actual authorized operator/approval workflow. It returns
source/input/manifest binding data, not an approval or transferable grant. The
host remains responsible for producing an actual approval matching that binding.

Both `resources.model.identity` (the selected environment inference record) and
the supported client's `baseURL` are mandatory and must match generated public
identity. Account/attempt settings, source release custody and native bytes are
also checked. These are configuration/ownership checks, not provider attestation.
`resources.model` supplies the original client/resource/exposure settings; it
never supplies an application-specific controller factory.

A Workflow ServiceAssembly remains an explicitly split artifact: its manifest
records `service_facade_complete_application:false` and the original application
Workflow supplies execution. With no selected original HTTP profile,
`command_client` is null; the existing Workflow submission port is used instead
of inventing an HTTP contract. Generated code starts no listener or background
worker. Borrowed resources remain borrowed and in-flight wrapper calls drain
before original cleanup.

The matching Core package ships the source-only
`examples/technical-profile-source/crm-application-example` project and a complete
check/compile/generate walkthrough in `docs/APPLICATION-INPUT-PROFILES.md`.
Open questions remain with the existing section above; real providers/models,
production Auth ingress, hosting, TDE, EVF, deployment and publication stay deferred.


### Dispatch deadline and recovery inspection are separate

The generated `environment.effect.deadline_ms` becomes the Workflow stage budget
and the deadline on a newly prepared original provider attempt. The dispatcher
already uses the smaller of its resource `timeoutMs` and the attempt's remaining
deadline for a normal dispatch; the join does not add a duplicate timeout policy.

Original uncertain-effect inspection deliberately has a fresh, separately bounded
resource `inspectionTimeoutMs` window (30 seconds by default, at most300 seconds).
That window may inspect the same original attempt after its mutation deadline;
it does not authorize another write or change the original provider/account/bytes.
The inspection resource timeout is not bound into the generated capability identity.
A Workflow timeout is an unknown lifecycle result, not proof of remote cancellation
or successful reconciliation. These remain original dispatcher semantics.


## Business-only knowledge source profiles

The matching Core package also ships `knowledge-ingestion-application-example`
and `permissioned-rag-application-example`. Their checked Alch Mapping profiles
use `craft.application-inputs/v1` with the finite
`knowledge-ingestion/domain-v1` and `permissioned-rag/domain-v1` families.
The CLI derives source/stage selections and emits the original architecture,
bootstrap and field-level views. No CRM provider or preference Query is required.
Ingestion uses the original paid embedding infrastructure without a text-model
stage. RAG uses the original generated ingestion reference and model owner.

Generated `application-bootstrap.mjs` calls `openGeneratedApplication`, which
checks the pinned `craft.generated-knowledge-inputs/v1` metadata and selects the
knowledge opening branch. Operators supply original Auth/source/release and
private application resources plus `resources.knowledge`: original `scope` and
`index`; RAG additionally requires `queryEmbeddings`, `{port,reference}` in
`ingestion`, an independently configured `quality` reviewer and `cachePath`.
The bootstrap constructs per-application handlers, Workflow and, for RAG, the
model host and cache. Borrowed shared infrastructure stays caller-owned.

The knowledge contract preserves original currentness and disclosure before
clean business review. It does not use the CRM human-approval kernel. RAG
persists actual input/wire/original confirmed model provenance separately from
the index generation and verifies it through the original model owner before
validation/release. Before paid dispatch, the JSON-encoded canonical selected
input stored in provenance is limited to 16384 UTF-8 bytes within the existing
32768-byte origin wire bound; business codecs may impose stricter limits. Public reference/read access retains owner-filtered Auth
and full source dependencies, including uncited inputs.

Use fresh stores for this contract; no legacy migration is supplied. The original
explicit administrative retirement project remains supported separately.
Quality-resource binding does not establish factual truth: trusted operators
can supply incorrect review labels. Exact runtime results belong to the selected
knowledge-profile proof; real provider/model qualification, hosting, TDE, EVF,
deployment and publication remain deferred. Open questions are owned by
`goals/plans/craft-knowledge-profile-extensions-2026-11-02/DESIGN.md`.
