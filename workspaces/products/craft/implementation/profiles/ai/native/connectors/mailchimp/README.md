# Mailchimp approved campaign operations

`createMailchimpConnector({account,serverPrefix,listId,segmentId,replyTo,fromName,credentials,http,assertCurrent,suppressionPort,apiRevision})` configures one account, data-center HTTPS origin, list, saved segment and sender. Neutral `campaign-draft-schedule-inspect/v1` has separate `draft.create`, `draft.content`, `campaign.schedule` and `campaign.cancel` effects, plus read-only `campaign.metrics`. No direct send endpoint, arbitrary recipient substitution, transactional mail or ad spending is exposed.

Setup verifies actual account ID, list and authenticated/verified sender domain. Mailchimp API/OAuth credentials grant broad account access rather than fabricated fine-grained provider scopes; current business permission is enforced by the original `assertCurrent` owner. Draft creation POSTs a regular campaign with selected saved-segment recipients/settings. Arbitrary HTML is a separate PUT content effect. A lost create may inspect only the first100 list campaigns for a unique exact title/correlation/settings match; absent/duplicate/partial history remains review.

Scheduling compares actual provider content bytes against the approved content digest, checks exact account/audience/content approval, unexpired approval and the provider send checklist. `suppressionPort.checkCurrent({account,listId,segmentId,audienceDigest,binding})` is the original trusted current CRM preference/audience owner and must establish that the current provider segment matches the approved eligible audience. It is checked immediately before scheduling; no audience ACL mirror is created. [Schedule time is UTC on a quarter hour](https://mailchimp.com/developer/marketing/api/campaigns/create-action-schedule/). POST204 is only acceptance: a GET must confirm scheduled state/time.

Cancellation maps to [unschedule for a scheduled campaign that has not started sending](https://mailchimp.com/developer/marketing/api/campaigns/create-action-unschedule). Current save state confirms unscheduled; sending/sent/unknown races remain review and never trigger another sender or direct send. There is no instantaneous late opt-out or recall guarantee. The read-only `campaign.metrics` slot uses `encodeCommand({contract: "campaign-draft-schedule-inspect/v1", semanticVersion: "1", operation: "campaign.metrics", campaignId, manifestDigest})` with the same original R02/current-read context. `readMetrics({campaignId,manifestDigest,binding,deadlineAt,signal})` is a host convenience for the same finite observation path. It verifies the current selected campaign/account/list/segment, then uses the [official campaign report GET](https://mailchimp.com/developer/marketing/api/reports/get-campaign-report/). No mutation or schedule acknowledgement supplies reporting counts.

Only actual numeric JSON UInt64 counts are projected: `emails_sent`→`emailsSent`; `opens.opens_total`→`opensTotal`; `opens.unique_opens`→`uniqueOpens`; `clicks.clicks_total`→`clicksTotal`; `clicks.unique_clicks`→`uniqueClicks`; `bounces.hard_bounces`→`hardBounces`; `bounces.soft_bounces`→`softBounces`; `unsubscribed`→`unsubscribed`. Numeric lexemes retain exact integers above2^53. Missing fields become null with a `missingFields` list; an actual reported zero remains "0". Local `observedAt` identifies read time, not provider update time. Observations always retain `partial: true` because report counters can change; even every selected field present does not certify final delivery or attribution. A404 report after current campaign verification is `metrics-not-yet-available` with report null. Authorization rejection, outage and malformed/changed count schema remain distinct typed outcomes. Rates, revenue, attribution and a general reporting/pagination API remain outside this projection.

## Runtime boundary and lifecycle

The factory consumes a trusted `http(request)` seam; there is no default network client or SDK. Request fields are exact HTTPS URL/method/headers/owned bytes, the existing signal/total deadline, 262144 response-byte bound, `redirect: error` and `maxRetries: 0`. Each native operation makes at most eight selected requests, each bounded by the same total deadline and a 15-second local maximum. The HTTP implementation must enforce these limits during I/O; the adapter independently checks returned byte/status/shape bounds. Test transports return explicitly synthetic recorded HTTP responses and never contact a provider.

`credentials.current({provider,account,operation})` returns trusted current `{token,account,scopes,revision,status,expiresAt}`. The credential owner verifies account/scopes and refreshes or rotates secrets outside business payloads; this adapter checks its current exact-account binding before every request. Revoked, expired, unavailable or mismatched credentials stop new dispatch; there is no automatic refresh/replay or second account/provider. `assertCurrent({provider,account,operation,command,binding,inspection})` must synchronously enforce the actual current Entry/approval/source/resource authority; serialized command digests do not grant authority. Recheck occurs before/after awaited HTTP.

`encodeCommand` admits only the named finite neutral contract/version/operation and selected fields. `createSlot({id,operation,resourceId,action})` returns the original R02-compatible `execute/inspect/validateObservation` slot with source release required. Install it in the existing effect dispatcher: R02 owns logical intent/payload conflict, durable attempt identity, bounded retry/backoff/rate/concurrency/circuit policy, one-use dispatch custody, source-release tickets and unresolved retirement. This connector owns no attempt database or alternative retry loop. Unknown writes are inspected with the original payload/account, never automatically repeated. Definite pre-dispatch denial and documented400/401/403/409/422/429 errors are distinct from uncertain transport/5xx/redirect/partial/malformed outcomes; operation-specific inspection may remain unknown. Retry-After metadata is capped at60seconds and never starts a retry here.

`retire()` stops new connector execution and preserves inspection with current credentials/grants. First use the original dispatcher retirement operation to reconcile unresolved attempts or explicitly retain them for review. Original source/effect owners retain their receipts and protect payload retention/deletion. No local receipt is an account/provider certification. `artifactIdentity()` hashes actual owned module/package/shared-helper bytes; the parent integrator supplies the complete public package/export/dependency closure and generated consumer qualification.

## Open Questions

The implementation is tested in synthetic recorded-wire/local mode. Real account availability, token provisioning, source/recipient policy, hosted API changes and actual provider behavior remain separately qualified operands. DTO/schema/semantic-version drift rejects; a package hash does not freeze a hosted API. Full bidirectional synchronization, unrestricted pagination, provider migration/coexistence/failover and stronger duplicate/delivery guarantees remain outside this selected subset. Local hosting, publishing, deployment, TDE and EVF remain deferred.

The schedule mapping reads the exact bounded saved segment through the official [list segment members contract](https://mailchimp.com/developer/marketing/api/lists/segments/list-segment-members), including cleaned, transactional and unsubscribed members. Incomplete membership, nonnumeric totals, changed selected list and any member without current subscribed status block scheduling before POST.
