# Craft architecture

The architecture keeps intended behavior separate from code and from evidence about that code. In the Customer Success example, the owner decides what should lead to a renewal suggestion, the business source records that rule, a selected implementation handles the protected review, and checks report what happened for named inputs.

Product defines value and capabilities. Project coordinates Goals and Work. Authority supplies current meaning/owner contracts. Ontology reads those definitions and current native models through the shared lifecycle application. Implementation bindings select existing component owners and their native dependencies.

Derived outputs do not replace source meaning. No runtime or admission follows from a file move.
