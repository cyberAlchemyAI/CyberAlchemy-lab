Follow an incident

A customer reports missing records. Follow what an agent needs, what it can establish and how the next decision becomes reviewable.

6 minute read · The fictional Northstar case used throughout the guide

1. Start with the customer’s report

INC-0241 · Northstar · Customer support

“Our customer-data export is missing records. Please investigate the file we received.”

Customer-data service owner · Incident open

The report starts a response. It does not yet establish what went wrong. The service owner needs an investigation that can distinguish missing identifiers from an incorrect filter, a changed source or a mistaken expectation.

The customer report and the Incident’s response scope.
Work to prepare
A bounded investigation within the export-repair Project.
Needed to proceed
A named owner, an assignment, applicable permission and usable task information.

2. Make the question and boundaries explicit

The customer-data platform is the Product. Exporting eligible customer data is one of its capabilities. The repair Project coordinates the response; the investigation is a bounded Work item. An Agent Assignment identifies the agent’s job.

This is the case’s definition illustration. The Definition contract additionally requires its exact identity, owner, voices, boundaries and other governed fields; this annotated excerpt helps read those responsibilities.

Agent reads
The definition, assignment, applicable policies, recorded delegation and checked Context and Ontology Views.
Scope it records
Northstar; status = active; S1; E12; run 12; software revision 7; completeness definition 1.0.0.
Needed to proceed
The separate 30-minute delegation permits inspection, identifier comparison, saving candidate material through the recording route and preparing a proposal.

Changing source data, deploying code, admitting a definition and closing the incident each require their applicable authority. An assignment alone supplies none of those permissions.

3. Compare the selected records

Use the values in fixed snapshot S1 to select Northstar’s active records. Then compare their stable identifiers with E12. Comparing row counts alone would miss duplicates or a different set of identifiers.

Agent reads
The saved source and output, the selection rule and comparison method version 2.
Agent produces
An Operational Observation of the missing identifiers, with attributable inputs, method and result.
Needed to proceed
Save the material through the permitted recording route, retaining its exact sources and limitations.

The observation records what happened. The method, selected data and result make it examinable. A new snapshot or changed filter would need its own comparison.

4. Connect the result to a bounded assessment

The agent assembles an Evidence Set for the omission claim. A Failure Assessment evaluates the occurrence, mode, cause, impact, containment, recovery and uncertainty independently.

What the comparison establishes
Assessment questionCurrent conclusionNext evidence needed
Did omission occur?200 required identifiers are absent from E12.The saved inputs, method and comparison support this scoped result.
What caused it?Unresolved.Investigate how the selected input became this output.
How far does it reach?Confirmed in E12; wider impact unresolved.Inspect other outputs and downstream uses within authorized scope.
Has recovery succeeded?Unestablished.Assess the recovery result against its declared criteria.
Agent reads
The source-bound observation and the requirements for the claim being assessed.
Agent produces
Candidate assessment material with the omission established and other postures left unresolved.
Needed to proceed
Review evidence for the particular conclusion and record its standing. Evidence presence alone does not accept a claim or decide a response.

5. Prepare a repair proposal for a decision

The case includes proposed software revision 8. Its repair effect has not been established. A useful proposal identifies what would change, the suspected mechanism, how to assess it, the affected scope and unresolved questions.

Agent reads
The implementation’s recorded identity and version, scoped assessment and applicable constraints.
Agent prepares
A candidate change proposal and a plan for checking identifier coverage and other required behavior.
Needed for a later transition
The responsible owner reviews the exact revision, evidence and requested effects. Adoption, activation, recovery and closure retain their own requirements.

Craft can help express and construct the software change. Generated code and checks can become Work outputs. Their existence does not admit Lab records or authorize deployment.

6. Resume from saved knowledge in a new session

At 10:10, task view 3 has expired. The agent pauses because it cannot rely on that view for the next action. This does not mean its 30-minute delegation has necessarily expired; view usability and permission have separate conditions.

The next agent can recover the 200-identifier omission and the candidate proposal. It still needs to investigate cause, establish wider impact and assess any recovery. Continuity preserves both knowledge and its limits.
