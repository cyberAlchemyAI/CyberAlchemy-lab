Meaning, format and the particular record

A definition, a type contract and a record answer successive questions. Keeping them identifiable lets meaning remain stable across many records and lets formats evolve through their own governed versions.

DefinitionWhat does it mean?
“Complete export” states the identifier-coverage criterion and its scope. An accepted exact version governs that meaning.
Artifact TypeWhat must this kind of record contain?
The Work contract binds meanings, canonical structure, validation and representation requirements for Work records.
ArtifactWhich particular recorded item?
This investigation’s Work record has its own identity, version, owner and state, under its declared type.

Check the boundary: a schema-valid definition can still lack acceptance. An accepted type contract does not accept every instance that uses it. A new display or diagram does not change the underlying meaning.

Need, promised value and bounded effort

IntentWhat need matters?
Customers need complete eligible data. Intent Resolution selects a response and the conditions for judging satisfaction.
ProductWhat enduring value is promised?
The customer-data platform provides export capabilities. Its capability is the promised outcome; a particular Implementation realizes it.
ProjectWhat coordinates the effort over time?
The export-repair Project keeps its goals, decisions, evidence and work together.
GoalWhat future result must be established?
A scoped repair outcome, with achievement criteria, required evidence and an accountable owner.
WorkWhat is the bounded effort?
Investigate Northstar’s output using selected inputs, constraints and expected results. Work can also exist outside a Project where its contract permits.

Check the boundary: finishing an investigation does not establish that a Product promise was fulfilled or a repair Goal achieved. Those conclusions need their own criteria, evidence and transitions.

Observation, evidence and assessment

Operational ObservationWhat was observed?
The comparison records 200 missing required identifiers in E12. In ordinary Project work, this is an Operational Observation; research- or experiment-specific Observation has its own boundary.
EvidenceWhat bears on a particular claim?
The source snapshot, output and comparison support the scoped omission claim when their provenance, method and suitability can be examined. An Evidence Set groups the relevant material.
Failure AssessmentWhat conclusion is supported?
The occurrence is established in this output. Cause, wider impact and recovery remain unresolved and are evaluated independently.

Check the boundary: an observation is not automatically sufficient evidence for every claim. An omission assessment does not establish a pagination defect or successful repair. A Decision chooses a response through its applicable authority.

Assignment and permission

Agent AssignmentWhich participant has which job?
Assign the agent to investigate the omission as a Work item.
DelegationWhich actions are permitted, and when?
Permit inspection, comparison and preparing candidate material within a recorded scope and time window.
Definition authorityWhat criterion governs this meaning?
The accepted completeness definition governs the identifier-coverage assessment within its declared scope.

Check the boundary: the agent needs both an assignment and applicable permission. Knowing what “complete” means does not grant data access, deployment or incident closure authority.

Saved state, selected views and session memory

Project StateWhat endures?
Governed external records, definitions, decisions, evidence, relationships and histories—including preserved proposals with their own standing.
Context ViewWhat information answers this task request?
An immutable selection bound to the request, exact sources and declared usability conditions.
Ontology ViewWhat connected model is selected for this purpose?
An immutable projection of an exact consistent ontology cut, with purpose, consumer, freshness, expiry and limits.
Session MemoryWhat is temporary working memory?
Working memory belonging to one Agent Session. It expires when the session terminates.

Check the boundary: views select saved state; they do not replace its canonical sources. Later machine sessions use new instances, new working memory and newly checked views and permissions.

Lab ontology and the Craft software model

Two models with different responsibilities
QuestionLab ontologyCraft software model
What is represented?Typed project subjects and declared connections, with meanings, evidence, ownership and governance.Software responsibilities, behavior, architecture and construction constraints.
What does the incident use it for?Recover how the investigation, inputs, assessment and decisions fit together.Express and construct the proposed software repair within supported model-to-code paths.
What does a graph connection establish?Only the meaning allowed by its declared ordered endpoints and qualifiers.The software relationship defined by Craft’s applicable model contract.
What requires a separate decision?Acceptance and permitted effects on governed Lab state.Adoption of outputs and any release or deployment through the applicable authority route.

Craft is a software-design Product within the broader Lab. A project can use Craft’s tools; code, models and checks can become Work outputs and evidence. The documentation describes how they fit together without assuming an automatic connector.

Check the boundary: a connected ontology node is a representation of a governed subject, not a new authority source. A Craft model edge is not automatically a permitted Lab relation between two Artifact instances.

Calculation, Query, Rule and Operation

RuleDoes a condition hold?
Evaluates a Boolean condition.
CalculationWhat value follows from the inputs?
Derives a value without changing business state. In the capacity fixture, it returns Accept or Reject.
QueryWhat information is retrieved?
Retrieves the selected information under its declared contract.
OperationWhat business state change is requested?
Owns the state-changing behavior, such as reserving capacity. A rejected attempt can leave state unchanged.
The existing Craft capacity example uses strict less-than
Request / capacityCalculation resultSupplied capacity afterward
4 / 5Accept5
5 / 5Reject5
6 / 5Reject5

Check the boundary: Accept is a calculated result. Reserving the available capacity belongs to a separate Operation and requires its own permitted state change. Numeric Calculations remain values, too.
