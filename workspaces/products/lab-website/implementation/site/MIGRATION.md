# Website import and portability changes

The maintained Lab and Craft documentation and their linked robot-learning article were imported into `website/source/`. `IMPORT-MANIFEST.json` records original file digests, sizes and import scope. Existing attachment files were left intact.

Portability changes made after import:

- Added `build.py`, `site.json`, pinned Python requirements and local output exclusions.
- Preserved both documentation folder names so cross-page navigation, Craft links, diagrams and the shared search index retain their relative destinations.
- Added an explicit `--repository` argument to `build_research.py`; normal builds render the captured edition and never capture current repository state.
- Let the integrated build postpone Craft's search compilation until all surfaces have been generated.
- Replaced the old dated package builder with a compatibility entry point for `website/build.py`.
- Replaced the historical backup dependency in `documentation_checks.py` with `research/preservation-baseline.json`: fingerprints of the 454 imported reference bodies and eight essay bodies, excluding explanatory reading aids.
- Added deterministic archive packaging, a selected-file release manifest and a root entrance pointing to the existing Lab homepage. The introductory guide remains separately reachable.
- Made Craft's folder entrance redirect to the maintained Craft article in the generated site.
- Added a manually triggered GitHub Pages workflow with deployment disabled by default.

At import, the guide, essays, reference meanings, Craft article and original captured authority records retained their content and standing. The sibling robot-learning page was retained as a supplied standalone article, rather than regenerated by the Lab/Craft renderer.

The Git-readable Markdown edition remains under `docs/lab/`. Refreshing that edition or updating the authority snapshot is an explicit maintenance operation. Neither is silently performed by the website build.
