# Define Product Business Ontology

Private durable candidate package for the business meaning of CyberAlchemy v2 Define. It owns thirteen business nodes and twelve business relations. The model includes the candidate handled-definition registry, the committed progressive context-sufficiency rule, bounded Language consultation, and DomainSpec construction readiness.

## Identity and ownership

- Ontology: `cav2.define.business-domain.v1`
- Type: `business-domain`
- Branch: `business`
- Root: `B-DEFINE-PRODUCT-CAPABILITY`
- Owner: CyberAlchemy v2 product owner
- Visibility: private
- Authority effect: none

The parent [`../profile.json`](../profile.json) owns the business-system bridge. The sibling [`../system-ontology/`](../system-ontology/) owns the system runtime model.

## What this package models

The package models Define as a product capability, shared meaning as its intended outcome, the Definition Pack, Language Context View, and handled-definition registry as product outputs, and eight business rules: concept coverage, human control, work continuity, progressive context sufficiency, bounded Language application, bounded authority, proportionate governance, and DomainSpec construction readiness.

At start or resume, Define consumes a Language Context View bound to one
language, context, intended use, and exact source epoch. It reuses usable
bindings and exposes missing, stale, ambiguous, conflicting, or owner-unresolved
meaning. The view gives context; it does not grant meaning ownership, accept a
definition, choose an open realization, or create authority.

Construction readiness means that Define preserves exact canonical-definition,
product-ontology, and capability business-ontology identities, digests, owners,
validation outcomes, residue, and challenge routes for the next DomainSpec v2
consumer. Define does not compile the project, generate or admit the system
ontology, bind implementation, prove conformance, or enforce the chain.

## Validation

Run `python3 scripts/validate.py`. The validator is check-only and deterministic. Receipts are append-only history and do not grant promotion or acceptance.

## Claim ceiling

This package supports only a source-current private candidate of Define product meaning. It does not prove measured outcomes, implementation, runtime conformance, canonical admission, promotion, execution, publication, release, deployment, or any external effect.
