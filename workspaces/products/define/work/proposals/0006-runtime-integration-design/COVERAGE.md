## Reuse rather than restart

- **G01/G03:** reuse exact accepted-with-limits six-meaning/profile preparation and prior limits. Actual semantic/profile/owner effects remain pending.
- **G04–G06:** this design specifies the executable contracts, Python kernel, exporter, handling/materialization and field lineage still to implement.
- **G07/G08:** use real owner scope evidence and current Lab core/review/publication contracts. No parallel owner system.
- **G09:** exact source/epoch/binding/store compatibility, permitted ontology views and bounded agent context remain shared integration obligations.
- **G02/G10:** preserve Product/realization/adoption boundaries, verification order and final documentation requirements.
- **R01–R12:** retain all amended risk-control obligations. A design resolution does not close its runtime evidence obligation.

[work-crosswalk.json](work-crosswalk.json) maps all79 existing IDs to design sections/layers without changing their statuses. New application/assessment requirements are mapped by the design coverage above; no new normative Definition is created to name each implementation task.

## Review checklist for this design

- Does the Pack remain the normal task output, with explicit reusable materialization?
- Can the source/parameter/assessment mapping be implemented without silently changing the reviewed meanings?
- Are snapshot-only preparation, real host operation, pending owner review and actual application visibly different?
- Are exact numeric/source bytes protected from cross-runtime reserialization?
- Are the selected host all-or-nothing profile and new-cohort behavior respected?
- Does persistence use existing permitted records/custody rather than a new Pack carrier?
- Are all external qualification and owner effects still explicit?

The design package's own validation checks only links, exact source bindings, ID coverage and self-consistency of the proposed layer/component maps. It does not validate future schemas, execute the matrix or establish host readiness.
