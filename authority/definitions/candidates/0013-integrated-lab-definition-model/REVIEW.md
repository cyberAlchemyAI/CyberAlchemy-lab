## Batch boundaries

- These candidates define meanings only.
- Abstract Definitions do not require standalone carriers.
- Carrier, exact relation pair, qualifier, ontology scope, Policy instance, runtime, and consumer admission remain later decisions.
- A Machine Agent Instance is Session-ephemeral; durable memory is Project State selected through Context and Ontology Views; Session Memory expires with the Session.

## Agent boundary model

| Boundary | Required rule |
| --- | --- |
| Identity | `Person != Principal != Actor != Agent != Agent Instance`; identical models, Profiles, or Implementations do not merge Agent Instance identities. |
| Concrete operation | An Agent acts only through one active Agent Instance inside one active Agent Session. |
| Machine lifetime | A Machine Agent Instance belongs to exactly one Session, cannot predate or outlive it, and cannot resume in another Session. |
| Participation | Agent Assignment states expected participation and scope; it grants no authority and proves no completion. |
| Technical ability | Agent Capability states what may be attempted; it grants no authority and proves no successful performance. |
| Authority | Authority Claim or Delegation separately binds the Principal, recipient, action kinds, subjects, Policies, gates, period, evidence, revocation, and claim ceiling. |
| Durable memory | Project State belongs to the governed Project. A Machine Agent receives selected Project State through exact Context and Ontology Views. |
| Short memory | Session Memory belongs to exactly one Session, has no authority effect, expires with that Session, and cannot be consumed by a later Session. |
| Attribution and effect | Agent Action records attribution and posture. Completion does not prove delivery, acceptance, correctness, external effect, or authority effect. |
| Self-change | An Agent may propose changes to its Profile, Capability, Implementation, Policy, Delegation, or lesson selection but cannot approve or activate those changes for itself. |
| Persistence | Only an explicit governed Agent Action can write a separately identified artifact, event, evidence record, relation, receipt, or proposed change into Project State. |
| Governance | Agent output becomes a Finding, Decision, Definition, Policy, admission, or accepted evidence only through the separately governed owner path for that artifact. |

### Agent boundary example

`agent-instance:step2-review` is created with `session:lab-model-2026-10-06`. The Session binds one Profile, Assignment, Context View, Ontology View, Policy set, Delegation, tool set, and budget. The Agent Capability permits candidate authoring, while the Delegation permits writing review candidates only. The Agent writes candidate files through attributable Agent Actions. Those files enter Project State as candidates; they remain unadmitted until the Definition owner records a separate Decision. When the Session ends, its Agent Instance and Session Memory expire. A later Session creates a new Agent Instance and reconstructs its working state from new Views over Project State.

Accepted: the Agent proposes a Profile revision and records evidence for owner review.

Rejected: the Agent edits its active Profile, grants itself admission authority, carries private Session Memory into a later Session, or treats a completed tool call as proof that an external effect occurred.

## Integrated example

A human Principal delegates candidate authoring to a Machine Agent Instance for one Agent Session. The Session receives Project State through a Context View and Ontology View and keeps only ephemeral Session Memory. An Agent Action materializes this 60-Definition candidate. An Operational Observation and Work Outcome Assessment record coverage; an Agent Reflection may propose an Operational Lesson. None of those records admits the Definitions. A Definition-owner Decision with an exact Decision Scope and Effect is still required. If admitted later, Artifact Type owners may design carriers, Relation Kind owners may declare closed pairs and qualifiers, and an Ontology may represent admitted instances without replacing their canonical identities.
