# Definition Voice Guide (quality bar + lessons ledger)

definitions-governance requires three voices per card (Formal / Plain-language / Domain-context). This guide
adds the **quality bar** for each + a growing **lessons ledger** — append a lesson each time a card is
authored or improved, so the next card starts better.

## Quality bar (per voice)
- **Formal voice** — restate the `.schema.yml` criterion in prose; state identity/discriminators **positively**;
  don't carry mechanics the plain voice should carry.
- **Plain-language voice** — lead with the **single clearest real instance**; make the reader *feel* the
  concept; end on the discriminator.
- **Domain-context voice** — where the term actually appears in this repo's artifacts + its edges; state the
  discriminator as a **flip** (add/remove X → it becomes Y).

## Lessons ledger
1. **Lead with the single clearest canonical instance** (Money for Value Object) before generalizing.
2. **State the discriminator as a flip** — "add a designated id → it becomes an Entity."
3. **Frame identity positively** — "identity *is* the value" beats "no identity."
4. **Formal voice = the criterion in prose;** don't restate mechanics the plain voice carries.
5. **A dictionary-style opener reads best for concept nodes** — lead with a crisp noun-phrase definition
   ("a past fact about the system state" for Event) before the instance, rather than an analogy-first opener.
