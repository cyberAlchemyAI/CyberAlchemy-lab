# Combined resource guards and diagnostic meanings, before implementation

The evidence interpreter currently bounds the authority capture separately from
the declaration/selection catalog. It also evaluates exact Nat numeric fields.
A short exponent token can request a very large decimal power despite a small
byte count. Complete the combined resource boundary and classify its local causes
before interpreting typed numeric fields. Keep mathematical meaning distinct from
the configured supported resource domain.

Independent combined budget meaning counts the authority capture plus every
declaration and selection, uses their actual original content lengths, enforces
one aggregate-byte and count bound, and enforces the per-capture byte bound for
every input. Limits are explicit caller configuration, not an accepted global
policy or an operational measurement. An invalid declared byte count does not
reduce the bytes charged to the budget. No unused input is skipped.

Numeric resource configuration bounds retained token character count, combined
integer/fraction digit count, exponent digit count and absolute exponent value.
Independent token meaning requires the existing full lexical Representation and
these bounds. It does not call the arithmetic evaluator. Decimal/exponent spellings
and negative zero remain supported when their exact values and resource bounds
permit them; a resource refusal does not assert that a number is mathematically
invalid. Bound exponent digit count before folding its digits. Do not call
mantissa/numerator/denominator/decodeParts or compute decimal powers in preflight.

The scalar JSON parser preserves number lexemes and object entry order, including
duplicate keys. Enumerate every numeric token in nested arrays/objects without
normalizing or filtering. The numeric guard precedes every existing typed source
decoder/Nat evaluation in the guarded evidence entrypoint. Prove that accepted
numeric Parts bound each decimal-power exponent used by the existing evaluator.
This is an arithmetic-input guard, not a proof of whole-process memory or time.

Each capture preflight first checks its envelope, then exact digest/profile,
then supported scalar JSON, then its numeric tokens. It retains the complete
original capture. Its refusal categories have independent meanings:

- invalid envelope: count/profile/digest shape does not satisfy EnvelopeMeaning;
- digest refusal: the existing independent digest-outcome meaning, never verified;
- scalar source refusal: no supported scalar document meaning exists;
- unsupported numeric work: an actually retained numeric token fails the configured
  lexical/work meaning. Preserve that token and the source input position.

Combined budgets are checked first. Ordered input preflight visits authority,
declarations and selections, reporting the first failed capture and preserving its
envelope. Only successful preflight may call existing profile/authority preparation.
Then distinguish unavailable profile data, unavailable authority data and failed
source evidence joins. These are stage causes with exact missing meanings; do not
invent a field path, blame or an authentication conclusion from a coarse failure.
The local contract must explain which diagnostics remain coarse.

The prepared-data outcome must be equivalent to independent PreparedEvidenceMeaning
plus combined budget and complete numeric/digest/scalar preflight meanings. Prove
its equivalence and that bounded success retains the preceding profile/evidence
meaning and all original envelopes. Actual authoritative-snapshot, Schema/review,
independent-checker and final-use premises remain separate. Successful preparation
does not grant ownership or authority.

Controls must include authority-inclusive byte/count limits, dishonest byte counts,
per-capture limits, supported decimal/exponent/negative-zero spellings, huge positive
and negative exponent refusals before powers, nested/unused numeric tokens, numeric
boundary cases, original captured evidence success and each preflight/stage refusal.
Never run the old unguarded Nat evaluator on a huge exponent to reproduce the risk.
