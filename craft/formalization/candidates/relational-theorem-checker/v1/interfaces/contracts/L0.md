# L0 interface boundary

## Definitions

- [baseline-snapshot](../schemas/baseline-snapshot.schema.json) — Exact source snapshot with explicit source/effective-state overlay; no claim of perpetual freshness.
- [semantic-profile](../schemas/semantic-profile.schema.json) — Explicit candidate semantic input profile with reviewed meaning required before semantic readiness.
- [relation-assertion](../schemas/relation-assertion.schema.json) — Identified relation assertion. Dynamic qualifier validity is checked against the selected kind declaration.
- [graph](../schemas/graph.schema.json) — Finite identified graph. Identity uniqueness and endpoint referential integrity are contract obligations.
- [normalization-report](../schemas/normalization-report.schema.json) — Field-preservation projection, exact dependencies and remaining parser trust boundary.
- [check-receipt](../schemas/check-receipt.schema.json) — Scoped checker outcome bound to exact inputs, invariant statement and explicit trust assumptions.
- [l0-assertion](../schemas/l0-assertion.schema.json) — Three-kind companion structural input. It covers the selected materialization kind without changing frozen Typed Relation/v2.
- [l0-graph](../schemas/l0-graph.schema.json) — The companion finite graph with all assertions restricted to the selected three-kind structural carrier.
- [snapshot-request](../schemas/snapshot-request.schema.json) — Request contract for captureSnapshot; exact references must resolve through the local artifact store.
- [normalization-request](../schemas/normalization-request.schema.json) — Request contract for normalizeGraph; exact references must resolve through the local artifact store.
- [check-request](../schemas/check-request.schema.json) — Request contract for checkAddition; exact references must resolve through the local artifact store.

## Behaviors

- **C-captureSnapshot**: Hash every source and resolve effective state through exact registry evidence. A selected immutable snapshot with explicit capture evidence; no perpetual currentness claim.
- **C-normalizeGraph**: Reject unknown kinds, identity collisions and malformed input; retain exact ordered pairs and original qualifier shapes. A deterministic projection with preservation mappings and explicit parser trust.
- **C-checkAddition**: Fully recheck the resulting graph against independently defined validity; structural scope stays separate. A scoped result; semantic-valid requires checked general soundness for the selected profile.
- **C-artifactTransport**: For named JSON envelopes reject invalid UTF-8, duplicate keys, schema mismatch and unsupported documents. Store raw proof, statement, provider and dependency bytes as untrusted artifacts. Resolve each operation's expected role/schema independently of upload labels; hash original bytes without reserialization. Artifact identifiers never grant read permission; access remains principal-scoped.
- **C-jobLifecycle**: Queued -> running -> completed/timeout/unavailable/failed; queued/running may cancel. Terminal states are immutable. HTTP 202 and completed job state say execution happened, not that an obligation was satisfied.
- **C-layerEvidenceGates**: F0 starts with P01 relational semantics, P03 independent formal predicates, P04 Lean reference checker and P05 general soundness review. B00 baseline refresh and P02 schema/API/decoder alignment follow that accepted evidence. Every later task requires current predecessor evidence; G2 closes supported non-rule scope while I06 closes rule obligations. Contract authoring does not complete any implementation/proof gate in the DAG.
- **C-protectedLineage**: Match targetVersion, effect, scope and epoch against legitimate roots across all indirect rule paths. Conformance may coexist with independently justified admission; conformance cannot justify admission.
- **C-compatibilityClaims**: Check selected data, generic invariant preservation and model conservativity separately. A conservative-extension claim covers every base model via an expansion with unchanged old reduct.

## Acceptance boundary

These interface definitions are authored. Their executable semantic behavior and proof obligations remain the corresponding DAG tasks.
