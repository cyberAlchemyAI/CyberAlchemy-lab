# L4 interface boundary

## Definitions

- [proof-policy](../schemas/proof-policy.schema.json) — Pin toolchain, isolate untrusted submissions and audit exact statements, dependencies and transitive axioms.
- [proof-submission](../schemas/proof-submission.schema.json) — Untrusted proof submission; matching metadata does not itself prove its required statement.
- [proof-audit](../schemas/proof-audit.schema.json) — Verifier-produced exact-statement, dependency, replay and axiom audit, bound to a proof submission.
- [provider-result](../schemas/provider-result.schema.json) — Raw provider execution separated from normalized verdict; exhausted bounded search is not theorem evidence.
- [obligation-result](../schemas/obligation-result.schema.json) — Scoped verifier conclusion with independent execution, freshness and evidence-method dimensions.
- [evidence-bundle](../schemas/evidence-bundle.schema.json) — Replayable untrusted submission with exact scope and dependencies; does not carry client readiness flags.
- [review-report](../schemas/review-report.schema.json) — Verifier-produced aggregate over independently derived hard obligations, not a client-owned all-passed flag.
- [application-recheck](../schemas/application-recheck.schema.json) — Candidate-only baseline recapture at simulated application; readiness is not governance authority.
- [job](../schemas/job.schema.json) — Asynchronous execution lifecycle; accepted HTTP request is not semantic acceptance.
- [api-problem](../schemas/api-problem.schema.json) — Transport or service failure with an actionable code; semantic violations are result documents.
- [capabilities](../schemas/capabilities.schema.json) — Explicit supported profiles and actually available execution engines; this package starts no engine.
- [cancel-request](../schemas/cancel-request.schema.json) — Cancellation requests terminate execution without producing readiness.
- [proof-request](../schemas/proof-request.schema.json) — Request contract for verifyProof; exact references must resolve through the local artifact store.
- [review-request](../schemas/review-request.schema.json) — Request contract for reviewBundle; exact references must resolve through the local artifact store.
- [replay-request](../schemas/replay-request.schema.json) — Request contract for replayBundle; exact references must resolve through the local artifact store.
- [application-request](../schemas/application-request.schema.json) — Request contract for recheckApplication; exact references must resolve through the local artifact store.

## Behaviors

- **C-verifyProof**: Isolate replay, pin the exact required statement and dependency closure, and audit transitive axioms. Audit of the actual theorem statement and policy; assumption and kernel boundaries remain explicit.
- **C-reviewBundle**: Recompute all digests and required obligations independently; draft normative profiles cannot become semantically ready. Readiness only after every hard obligation has allowed, current, completed evidence; human meaning review remains explicit.
- **C-replayBundle**: Compare the complete bound dependency closure with the observed snapshot and rerun affected obligations. Currentness and invalidation are verifier-produced, not trusted client flags.
- **C-recheckApplication**: Recapture a trusted observed baseline and recheck at simulated application time. Candidate recommendation requiring separate human authority; authority effect remains none.
- **C-artifactTransport**: For named JSON envelopes reject invalid UTF-8, duplicate keys, schema mismatch and unsupported documents. Store raw proof, statement, provider and dependency bytes as untrusted artifacts. Resolve each operation's expected role/schema independently of upload labels; hash original bytes without reserialization. Artifact identifiers never grant read permission; access remains principal-scoped.
- **C-jobLifecycle**: Queued -> running -> completed/timeout/unavailable/failed; queued/running may cancel. Terminal states are immutable. HTTP 202 and completed job state say execution happened, not that an obligation was satisfied.
- **C-layerEvidenceGates**: F0 starts with P01 relational semantics, P03 independent formal predicates, P04 Lean reference checker and P05 general soundness review. B00 baseline refresh and P02 schema/API/decoder alignment follow that accepted evidence. Every later task requires current predecessor evidence; G2 closes supported non-rule scope while I06 closes rule obligations. Contract authoring does not complete any implementation/proof gate in the DAG.
- **C-protectedLineage**: Match targetVersion, effect, scope and epoch against legitimate roots across all indirect rule paths. Conformance may coexist with independently justified admission; conformance cannot justify admission.
- **C-compatibilityClaims**: Check selected data, generic invariant preservation and model conservativity separately. A conservative-extension claim covers every base model via an expansion with unchanged old reduct.

## Acceptance boundary

These interface definitions are authored. Their executable semantic behavior and proof obligations remain the corresponding DAG tasks.
