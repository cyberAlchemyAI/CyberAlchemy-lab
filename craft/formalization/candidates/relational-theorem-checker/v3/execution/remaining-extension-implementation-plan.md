## E01 — evidence collections

Select the explicit candidate policy already proposed: any current accepted exactly matching listed assessment suffices. Preserve every matching accepted support in source order. Rejected assessments do not count as positive support; contradictory records for the same identity, duplicate references, empty collections, nonexistent members and stale/mismatched supplied references are invalid. This avoids silently skipping malformed evidence. Mixed accepted and rejected *different* assessments can qualify through the accepted one; the non-supporting assessment remains visible in the source.

First define source assertion membership, exact subject/contract revision/scope/context/epoch matching, accepted assessment membership, the projection and the independent existential meaning. Prove support soundness/completeness and retention of all valid supports; projection must not add admission roots. Then implement a closed explicitly versioned reference collection and checked source projection. Execute actual two-support, mixed-verdict and no-support witnesses and malformed/migration challenges. Review the chosen aggregation policy and source/assessment truth assumptions.

## E02 — bounded redelegation

Define typed path composition with exact source support per hop. The path's queried action and scope must be permitted by every ancestor; all half-open time intervals must cover the query epoch. Every hop needs its exact contextual policy/gate status and revocation decision, and every intermediate hop needs redelegation permission. Define any dual-role endpoint representation explicitly in this new profile; do not silently change the legacy endpoint kinds.

Prove effective-chain support and non-amplification before implementing traversal. Enumerate bounded simple paths with explicit maximum depth, nodes, edges and work. A complete supported bounded query can be yes/no/unknown; exhausting traversal is scoped unknown/resource refusal and cannot authorize a positive conclusion from a partial search. Cycles, expired/revoked ancestors, action/scope widening, broken joins, missing gates, missing redelegation and context/epoch drift are adversarial cases. Compile actual positive and negative/unknown path witnesses and compare the separately selectable direct profile. A chain never establishes independent admission or unrestricted authority.

## E04 — lifecycle transitions

Fix a separate lifecycle policy before mutation: exact predecessor revision, one current head, reject competing successors at a generation, preserve immutable declaration/history evidence, and require checked eligibility plus current-head review before a transition. A succession declaration alone cannot retire the predecessor. Replacement/removal claims use lifecycle invariants, never the fixed-frame model-expansion theorem.

Compile the transition theorem and actual eligibility witnesses first. Implement an owned candidate lifecycle store with authoritative transactional head/history metadata, generation comparison, scoped event ownership and crash recovery. Test two successors, stale predecessor, cycles, declaration-only attempts, rule-only receipt substitution, changed/saved events and crashes before/after the transaction commit. Recovery can recognize an existing commit but cannot create new freshness. Preserve original core shadow stores and APIs.
