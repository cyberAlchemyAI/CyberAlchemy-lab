# P09: qualify the complete public boundary

Execution requires accepted P08. This document is a plan, not completion evidence.

## What must agree

Use one bounded supported proposal in both combined and staged layouts, under identical semantic profile, fixed catalog and unchanged operator resource policy. Both successful paths must discharge all twenty obligations and agree on normalized predicate declarations, grounded rules, complete closure, certificates' semantic conclusions, source supports and theorem statement types. Compiled bytes, module partition and timings may differ. Also retain the rich target/scope cyclic fixture: a combined deadline refusal is a measured limitation, never evidence that the layout proved its obligations.

Each layout must exercise fresh public qualification, recorded saved inspection, an exact positive explanation, typed absence within the complete finite profile, and two successive applications with separate fresh successor registrations. Existing P08 application evidence may be reused only by exact current bindings; additional layout coverage needs new jobs. No stored result or copied readiness flag supplies a live application capability.

## Implementation and review sequence

1. Compile the regression specification into a closed suite/report contract. Every case names its public entry point, expected claim scope, exact input bindings, actual outputs and evidence type: fresh qualification, saved inspection, abstract theorem or explicitly unqualified fault probe.
2. Execute the two-layout positive comparison and fixed inventory coverage. For each obligation, link the independently specified statement and actual kernel evidence; count neither omitted modules nor a sampled closure as a generic model theorem.
3. Run decoder/type/profile controls: duplicate keys, nonfinite numbers, depth and bytes, predicate identity/version/hash, reference revisions, undeclared domain values, arity/sort mismatch, negation, changed domain and unsupported delegation chains. Distinguish invalid, unsupported and exhausted outcomes from proved absence.
4. Challenge semantics: derived or caller-supplied protected truth, empty stress certificates for invalid graphs, missing rule slots, unseeded positive cycles, different contract targets/scopes, potential versus active norms, conflicting condition records, and actual active require/forbid pairs with retained origins. Fulfillment remains unestablished.
5. Challenge evidence: missing obligations, weaker theorem statements, custom/admitted axioms, source/olean/cache substitutions, transplanted manifests/completions, and a saved result presented to a new context. Pin expected cache metadata independently rather than trusting its own digest claims.
6. Reuse current P06-P08 resource, cancellation, process-cleanup, head-generation and crash evidence. Run any genuinely new failure through the public boundary and show that it cannot publish a successor. Do not repeat every already accepted expensive check merely to inflate the suite.
7. Resolve the observed query-number gap in an additive facade: integer-valued JSON numbers can compare equal in the finite domain while their serialized identities differ. After exact saved-proof inspection, select the corresponding bound closure atom for trace lookup, retaining exact predicate/reference/scope checks. Verify positive and absence behavior; malformed/outside-profile values still refuse. Do not rewrite accepted P04 code or evidence silently.
   Review composed deadline diagnostics too: P08 uses a deadline-aware cancellation object for mapped workers. Its internal cancellation signal can describe a whole-application deadline rather than user cancellation. The unified facade must distinguish those causes, retain the underlying run record, and report unknown-resource for elapsed budget. Both causes must remain nonqualified and unable to publish. Strengthen success-response validation so an applied status requires concrete heads and a transaction, while failure branches can retain null fields.
8. Review missing coverage, exact evidence currentness and claim ceilings. A finite adversarial suite is not a universal theorem about the decoder, operating system or every possible relation. Accept only when each criterion has linked executed evidence.

## Review questions

- Does every successful entry point discharge the same fixed catalog, with the allowed foundational axioms only?
- Do both layouts agree on semantics, including all support origins, without requiring equal proof bytes?
- Does every failed or exhausted request retain a diagnostic and leave publication unavailable?
- Is any proof/operation merely planned, inspected from disk, or injected as an IO probe being counted as fresh kernel completion?

Selected extensions E00-E06 remain separate profiles after the P11 review gate. Regression must preserve that boundary rather than accepting a broader expression, chain, lifecycle or fulfillment meaning through the current recursive entry point.
