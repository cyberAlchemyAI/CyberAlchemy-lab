# P08 implementation review: one exact successor per reviewed generation

P08 implements an owned local candidate store whose authoritative head and publication journal commit together. Full public API tests applied two real extensions, independently registered both successors, and rejected a competing publisher of the same starting generation. A deliberately interrupted mirror write after the second database commit was recovered as an applied successor, rather than being misreported as an unchanged head.

This is an author implementation review. It is not independent review, human meaning approval, admission or deployment authorization.

## What changed and why

The old read/check/rename pattern left a race between checking a head and replacing it. The new store uses a SQLite transaction to compare the complete reviewed head and its generation, update the authoritative head, and record the committed publication together. Immutable snapshots and registrations are written and synchronized first. `HEAD.json` is a mirror with a narrowly defined recovery window.

Application requires two newly completed checks in the same live context: the exact proposal, and an identity-extension check with the proposed successor as both before and after. That second check independently establishes the successor's registration. The earlier proposal result cannot stand in for it. A preparation handle can be consumed once. Another context, saved JSON, a current file hash or a copied readiness flag cannot create that live handle.

Optional mapped requests retain their existing separate semantics. The application freshly checks each concrete delegation or inheritance witness. It requires a positive verdict; inheritance additionally requires a known positive condition and no active norm conflict. Every mapped request and context is bound to the review. Different contexts/epochs remain separately named, with no merging of their truth.

Each qualification discharged the stronger twenty-obligation inventory; each registration also names the fixed seventeen-obligation registration inventory. One of the seven is the earlier completed initialization of this same generation-zero fixture, preserved after correcting a test fixture. Resuming the test inspected that registered initial state; it did not transfer any application event. All applications obtained new proposal and registration events in the new test context. Interrupted attempts remain explicitly unaccepted in `p08/validation-attempts/`.

## The formal statement and its limits

Six independently compiled statements define the abstract guard and recovery behavior. The indexed guard says:

`Matches(head, review) ∧ FreshProposal(review.before, review.after) ∧ FreshRegistration(review.after)`.

From that guard, the formal theorem obtains a fresh proposal from the current head's baseline and a fresh registration of the exact successor baseline. Another theorem excludes substituting the previous baseline identity when the successor differs. Incrementing the generation prevents a second commit from the same reviewed generation. Conflicting artifacts and an unrecorded mirror mismatch require reconciliation.

Four statements use no axioms; the two recovery simplifications use `propext`. There are no custom axioms or admitted proofs. See [the exact kernel evidence](../../p08/transaction-kernel-evidence.json).

The live predicates correspond to P00's verifier-owned fresh evidence boundary plus the runtime's exact request-identity checks. These are abstract operational theorems. They do not prove SQLite, fsync, storage hardware, Python isolation or exclusion of a same-privilege external writer.

## Actual failures and recovery

The [metadata report](../../p08/metadata-controls.json) records 34 explicitly unqualified IO controls. Five real processes exited at journal, snapshot, registration, metadata-head and mirror boundaries. Precommit preparations were aborted with the old head preserved. Postcommit recovery preserved the new head and repaired only the exact journaled mirror window. Changed durable artifacts, missing committed registrations and external mirror edits required reconciliation without rolling back a possibly committed successor.

The full public-path mirror interruption separately demonstrates the same postcommit result rule after actual fresh qualification: the second application reports its durable commit after permitted recovery. IO probes are not counted as kernel qualifications.

The [mapped report](../../p08/mapped-controls.json) separates active inheritance, unknown-condition potential norms and expired direct delegation. Fresh checks retain the exact source/typed/context identities and same-kernel replay. Saved or changed receipts cannot recreate a live mapped event. That replay is not an independent proof checker.

## Definition gaps found in review

Registration must correlate the checked request, qualification result, completion and full owned run record. The saved inspector returns a summary, so reading that summary as the full record was incorrect. The implementation now first performs inspection, then reads the separately bound record and compares all four identities.

A delegation snapshot is represented in the context, inference profile and typed query. Changing an epoch requires those representations and the interpretation identities to agree. A positive fixture initially violated that correspondence; static preflight caught it and the fixture was corrected. E05's checked-IR work should reduce this repeated representation rather than make callers maintain it manually.

P09 must finish two diagnostic refinements identified during this review. An internal deadline-aware cancellation signal for a mapped worker must be distinguished from actual user cancellation in the unified facade. Also, its success-response validator should require concrete heads/transaction while allowing null retained fields in failure responses. These do not supply a publication capability; P08's live guard and commit path remain responsible for application. P09's plan records these refinements alongside the query-number trace normalization gap.

## Acceptance and remaining work

The public race provides the first acceptance criterion: one reviewed generation commits and its peer rejects. Actual crash probes and the full postcommit failure provide the recovery criterion. Both real successor applications have their own exact fresh registrations, with saved-receipt and one-time-handle controls providing the third criterion.

P09 follows with adversarial interface/layout regression, then P10 measures the supported envelope, and P11 requires actual feedback on a new concrete packet. All seven extensions remain selected and outstanding. Existing v2 feedback is not approval of that new packet; original v1 R06/G4 remain separate. All implementation and tests retain `authority_effect=none` and do not change any real project head.
