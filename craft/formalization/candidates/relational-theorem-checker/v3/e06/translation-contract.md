# Independent sample translation contract

The public claim is **sample checking only**: E00's actual `unknown_not_negative` theorem, `tNot unknown = unknown`, checked with its complete exported declaration closure. No whole-core or universal byte/export translation guarantee follows.

The trusted challenge is structural `Eq.{1} Truth (tNot Truth.unknown) Truth.unknown`, using the accepted `RelationalExtensions.Expression` definitions. `run_sample_controls.py` resolves expression, name and universe tables before comparing that statement. The accepted source binding, exporter commit and complete original export identity remain part of the challenge: a valid theorem under substituted definitions is a different challenge. The concrete negative test changes `tNot` to the constant unknown function; nanoda accepts its valid equation, but the trusted closure pin refuses it.

Lean4export exports the stored exact expression/level/name DAG, definitions/theorem proof and grouped inductive declarations/constructors/recursor computation rules. It is run from its pinned source by the pinned Lean 4.33.1 interpreter because this local cache lacks C development headers. Only the cloned toolchain selection file changed; the accepted core toolchain was not changed. Metadata and exact versions are retained. The original exporter is not a verified translator and does not independently authenticate source meanings. [Exporter format and source](https://github.com/leanprover/lean4export).

The NDJSON 3.1.0 parser resolves indices and universe parameters/instances. Each constant instance is checked against its declared universe arity. The actual export contains 18 declarations in complete inductive groups, 164 expression entries and four levels including zero. All expression constant references, declaration types/values and recursor rules are available to the standalone checker. No axiom is permitted; Nat and String primitive extensions are disabled for this sample.

Nanoda is an independently implemented Rust type checker. Its standalone binary checks every exported declaration, including inductive signatures, recursors, definitions and the actual proof. It does not call Lean and does not accept a Lean acceptance bit as proof. A forged accepted flag with an ill-typed proof, missing universe instance, unpermitted axiom and missing inductive group all fail. A changed theorem statement fails the trusted structural challenge. [Checker implementation](https://github.com/robsimmons/nanoda_lib/tree/68d5ca9db226849b41a6fff59d796ff19d0a8840).

The assurance still assumes the trusted informal statement/definitions are correct, export/statement plumbing is correct, exact files/hashes and host/compiler executions are reliable, and the independent checker has no relevant bug. The test does not prove universal translation correctness, independent validation of all core proofs or absence of common-mode checker defects. The original required same-kernel replay remains unchanged. A future production integration must independently anchor each complete challenge/definition closure and verify every selected theorem, rather than reuse this sample receipt as authority.
