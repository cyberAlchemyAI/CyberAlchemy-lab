## How the records fit together

“The experiment evaluates the export capability” works in conversation. For a record, we need to identify the design or run and capability version. We also need to distinguish evaluation from evidence support or software adoption. Each connection should answer its own question.

A Definition governs meaning within its owner’s scope through scientific and formal wording. Plain-language and domain voices explain it. An Artifact Type governs the record kind’s machine format and required views. An artifact instance identifies a particular versioned record. Type acceptance and instance acceptance are separate admissions.

A Schema states structural requirements, including kinds, fields, constraints and connections. Passing its checks leaves evidence strength, source freshness and action permission to other records. [W3C SHACL](https://www.w3.org/TR/shacl/) illustrates explicit graph-structure checking. This comparison establishes neither Lab use of SHACL nor acceptance through a structural pass.

The Four-Facet Artifact Invariant applies to governed actions on load-bearing artifacts, state or meaning. Before downstream governance, the action must bind, create or record typed residue for classification, schema, a human continuation view and a machine-readable view. Missing facets need reason, owner, evidence and a continue, defer or block outcome. The Canonical Representation Invariant separately designates one machine representation. That designation concerns form and origin, without itself proving truth or authority.

Registries select exact definitions and contracts. Artifact Type Resolution uses an exact reference or declared discriminator, reporting ambiguity instead of guessing from filenames. An older reference can resolve while a newer version is current. An Artifact Type Request records a reusable-contract gap for review, without supplying the missing accepted contract.

A Relation Kind declares meaning, direction, permitted ordered endpoint pairs, required details and inference limits. A Typed Relation instantiates the rule between specific versions. This snapshot has 41 kinds and 550 permitted ordered pairs. Source and target are not interchangeable, and separate lists do not permit every possible combination.

Membership, intended contribution, evaluation and evidence support need different connections. member-of, contributes-to, evaluates and evidence-bears-on record those facts, including support or opposition where required. Experiment Design and Experiment Run may evaluate Product, Product Capability, Product Thesis and Capability Realization Binding. Product connections are available alongside research connections, with no promised favorable outcome.

The Typed Connection Extension Rule governs expansion. Reuse a fitting meaning and constraints. An additional ordered pair needs review and an accepted successor contract; a different semantic question needs a distinct relation kind. Ownership, evidence, versions, lifecycle and challenge rights remain explicit. Registering an endpoint kind grants no extra connections.

Non-collapse asks whether concepts describe different facts. Assignment can precede delegation, capability can precede adoption, and evaluation can fail. Formalization expresses those distinctions logically. A witness or countermodel demonstrates a distinction under assumptions. Consistency asks whether the combined requirements hold together in the selected theory.

The inspected assurance work covers sources for 183 selected definition identities and partial translations. It reports zero verified whole-definition proofs. A proof checker’s accepted statement still needs a justified relationship to the intended definition. Lean’s documentation explains that boundary. A Lab claim requires adequate evidence connecting the formal statement to its source meaning. [Lean, Validating a Lean Proof](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)

An ontology organizes concepts, things and relationships. A Node represents a specific subject and revision. An Edge represents a Typed Relation or an explicitly declared local connection. Local appearance does not make a connection global. Graph and source identities stay separate, and drawing an edge supplies no authority to change its source.

A Model Instance Binding links a local instance to a shared parent model while preserving owners and authority. An Ontology Cut reconstructs a consistent state from selected event-history positions; a View selects from it for a purpose. A lifecycle graph needs sources, coverage, exclusions, unresolved references and freshness. Completeness is assessed within that scope.
