## Sources, interpretation and remaining work

The research package captures 484 source files from 8 October 2026, with content fingerprints. Essays combine selected registry entries with governance, integration, acceptance, implementation, assurance and planning records. Catalog coverage and whole-repository ontology coverage are different claims.

The publications explain particular mechanisms. Comparisons establish neither Lab implementation, standards compliance nor reproduced results. Past validation reports retain their captured scope; this editorial work reruns no implementation suite.

### Primary literature

- [W3C PROV-DM](https://www.w3.org/TR/prov-dm/)

   Provenance vocabulary identifies what existed, which activity produced it and who participated. It helps follow a Lab record to its origins while leaving authority to separate records.
- [NIST SP 800-162, ABAC](https://csrc.nist.gov/pubs/sp/800/162/upd2/final)

   Attribute-based access control considers requester, subject, action and conditions. Actor permission is one question within the Lab’s broader authority model.
- [Saltzer and Schroeder, Basic Principles of Information Protection](https://web.mit.edu/Saltzer/www/publications/protection/Basic.html)

   Least privilege limits grants to the task. Checking access on each use explains why an earlier permission needs reconsideration before later actions.
- [W3C SHACL](https://www.w3.org/TR/shacl/)

   SHACL declares constraints on graph fields and connections. It helps explain structural validation, without establishing that the Lab implements it.
- [Martin Fowler, Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html)

   Event sourcing retains changes and reconstructs state from history. The Lab separately records the authority behind governed changes.
- [Martin Fowler, Bounded Context](https://martinfowler.com/bliki/BoundedContext.html)

   A Bounded Context establishes where a model’s vocabulary applies. The same word can have different scoped meanings, with connections between models needing explicit rules.
- [Park et al., Generative Agents](https://arxiv.org/abs/2304.03442)

   The study examines agents using observations, retrieved memories, reflections and plans in simulation. It provides an external-memory precedent within that scope, without establishing business reliability or Lab conformance.
- [Lean reference, Validating a Lean Proof](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)

   A checker can verify a formal theorem. Relating that theorem to the intended meaning is another obligation. The assurance discussion keeps both questions visible.
- [Mensh and Kording, Ten simple rules for structuring papers](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1005619)

   The editorial method asks for a central contribution, attention to what readers know and a logical progression. Those questions informed the essay structure.

### Questions that remain open in this snapshot

### Governance lenses: authority, provenance and lifecycle Proposed module revision remains open

The proposed module emphasizes decision rights. Accepted definitions also govern meaning, record requirements and connections, so authority needs that broader reading.

The essays read the accepted model broadly. A revised module still needs its own review.

### Keeping software aligned with accepted changes Update proposed; repeatable operation remains planned

The admitted local software uses an earlier source selection. A successor proposes later Project State and has a captured validation report. Accepting that update is still a separate step.

Read source selection, implementation acceptance and observed execution as separate facts.

### Historical references that do not resolve Recorded gaps remain

Some older references remain unresolved against selected versions. Renaming them leaves the missing binding to be established.

The graph-query explanations preserve those unresolved references and the resulting limits.

### How much of the definition model has been formally proved? Partial translation; no complete definition proofs

The report covers 183 identities, with three source-linked partial pilot translations and eight source-linked foundation notes. It reports zero verified whole-definition proofs.

Non-collapse looks for cases distinguishing meanings. The essays claim neither proven global consistency nor complete proof coverage.

### Which sources does the ontology cover? Coverage is limited to declared source sets

The ontology import has 21 packages and the runtime selects bounded sources. Their manifests supply those boundaries. They establish neither coverage of all current objects nor a continuously running service.

Read the graph against its source set and the question the view was built to answer.

### Has a particular implementation been adopted for a capability? Separate adoption decision not established

A runtime’s capability reference still leaves adoption of a Capability Realization Binding and declaration of a realizes connection to their own records.

Association, implementation acceptance, capability adoption, activation and observed benefit each need a distinct account.

### What does Projection Specification mean in its source? Possible mismatch between the name and intended meaning

The governing definition concerns a concept requiring a governed information view. Its name alone supplies no additional formal projection-mapping contract.

The library preserves the exact statement rather than adding requirements inferred from its name.

### Is there a stable release? Not established in this snapshot

The admitted local foundation leaves repeatable operation, integration, scoped ontology coverage and usable-product work to the proposed roadmap. Stable release has its own prerequisites.

The essays show the foundation and open stages. A plan remains a plan until evidence establishes its results.
