# From candidate model to Lab operation

This package is a reviewable candidate. Its successful local validation does not place the Project, Definitions, Artifact Types or instances in the Lab's admitted registries or runtime store.

1. **Semantic review:** assign a Definitions owner; compare each `arn.definition.*` term with the admitted Lab Definition Index and the Engineer Assessment local method. Resolve overlaps and revise meanings. Prepare canonical Definition carriers, source bindings, registry postimage, index and drift audit under the Lab Definition route.
2. **Type review:** for each genuinely new kind, bind the admitted Definition version, exact schema digest, relation roles, positive and hostile fixtures, generator and validator. Seek Artifact Type owner admission before creating operational instances. Reuse the already admitted Lab kinds listed in `artifact-types.json`.
3. **Project setup:** assign Product and Project owners; review the Product identity, thesis, Project identity, Goals, Research Inquiry and Experiment Design. Admit exact versions and establish Project State through the Lab's project setup and decision route. A document path alone is not Project State.
4. **Governance setup:** review the [actor map](governance/ACTORS.md), [rule registry](governance/rules.json) and [decision-rights profile](governance/decision-rights.json). Appoint recognized Principals with scoped Role Assignments and bounded Delegations; admit exact Policy and Decision routes. Verify independent reviewers, conflict disclosure, appeal standing, emergency pause scope and treasury signer controls. The candidate guard is an assessment, not a Decision.
5. **Pilot authorization:** freeze the synthetic protocol, cases, answer key, reviewers, budget and conflict policy. Record an owner decision and run only within its scope. Preserve all attempts, null results and counterevidence.
6. **Economic authorization:** review the [formal candidate mechanism](economics/FORMAL-MODEL.md), [cash and asset-cycle analysis](economics/CIRCULAR-ECONOMY-RESEARCH.md), [Product 001 reference term sheet](PRODUCT-001-TERM-SHEET.md), [multi-sponsor stress result](economics/MULTI-SPONSOR-RESULTS.md), [criteria](economics/CRITERIA.md) and [open decisions](economics/DESIGN-DECISIONS.md). Select an explicit Product-supported, sponsor-supported or hybrid funding regime, stress cash headroom, and resolve the finite W/U horizon before promising continuing mining. Settle the funding instrument, contributor agreement, IP/data policy, utility token design, participation formula, treasury controls and applicable legal/accounting review. Only after an accepted agreement and separately authorized implementation should any mint, transfer, redemption or payment be attempted.

The first model review should focus on the novelty comparison boundary, the definition of an independently observed research advance, and whether proposed participation units can be specified without ambiguous revenue or contributor rights.
