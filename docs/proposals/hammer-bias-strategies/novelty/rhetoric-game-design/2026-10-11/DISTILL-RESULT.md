## Concept layers and recomposition

| Layer | Responsibility |
|---|---|
| Purpose | Survive through a strategy whose weaknesses can be used constructively. |
| Capability | Compose a build, author or manually execute it, and adapt to disclosed counterpressure. |
| Workflow | One chosen hero continues through acquisitions and three boss stages. |
| Policy/rule | Observations, commands, recovery, geometry, status effects, hazard warnings and goal predicates. |
| Interface/artifact | Run specification, policy editor, event explanation and research evidence. |
| Operation | An admitted action, token transition or effect resolution. |

Inputs: hero, build, rules/routes, initial seed, command source and acquisition choices. Outputs: hero survival/death, three boss outcomes, resulting build and attributed consequences.

Named coordination: public snapshot → command request/admission → world events; encounter warning → bound attack/token → ordered resolution; XP/offer → progression choice → updated build/policy. No unnamed coordinator invents tactics. The complete run recomposes the adaptive-survival capability through those interfaces.

Future audio supplies a bounded action value with declared timing/resource constraints. It does not replace physics, resolve free text or infer hidden enemy intentions.

## Stable disagreement and unresolved knowledge

- **F1 — Comparison class:** a conventional conditional reward keyed to the public objective can reproduce the token mechanic. Claim a difference from the named goal-independent controls, not immunity to conventional implementation.
- **F2 — Utility:** the worked shield/stamina weights illustrate a possible ranking. Shield expiry or depleted stamina can erase or reverse it. They are not observed preferences.
- **F3 — Usability:** a bounded editor can still conceal a priority conflict. A paper exercise must test action prediction and repair before claiming usable authoring.

Gameplay feasibility, feel, balance, enjoyment, player comprehension, strategic benefit, retained creative learning and worldwide originality remain unknown.

## Evolution and deferred complexity

Known pressure: new encounters/counters, item interactions, policy vocabulary and possible voice inputs. Preserve data/effect/action boundaries. Defer a large campaign, multiplayer, unrestricted programming, free-text spell semantics, a large persistent economy and simultaneous rhetorical/audio subsystems. Revisit one only when a concrete pressure or successful focused probe justifies it.

## Premortem and frame expiry

Six months later, the game fails because players spend time programming but experience an ordinary survival loop. Another failure is that goal labels change rewards without supplying meaningful strategy. Guardrails: competent generic controls, visible fired-rule explanations, priority-conflict repair, one token at a time, goal-independent comparison and finite rewards.

The frame expires if the editor cannot express risk plus recovery, manual control feels delayed, the goal-pair distinction disappears, voice sensing becomes mandatory, or deployment/run requirements change. Revisit the affected contract, not the entire idea by default.
