# Preparing the next novelty investigation

This is a prospective design derived after the current experiment began. None of the variants below was executed as a controlled intervention in this run. The frozen twelve operators, controls, judgments and selection rule remain unchanged. These are process variants to investigate, not claims of globally new techniques.

The unit to prepare is a **change in what analysis can produce**. Each strategy needs an operation, a resulting mechanism or question, and an observation that would distinguish it from ordinary analysis. A striking sentence is a starting stimulus; it is not the result.

For the hammer problem, a productive progression is:

> What if the joint could tighten itself? → Which disturbance could supply the tightening force? → What geometry would convert that force into grip? → Under what load would it slip instead?

This hypothetical chain turns inversion and attack into a candidate mechanism and a failure test. Material feasibility remains unknown. “Think beyond the hammer” supplies no comparable experiment.

## Ten process strategies worth preparing

| ID | Strategy and generative operation | Required output | Matched comparison and rejection test |
|---|---|---|---|
| P01 | **Invert a causal arrow.** Take “we need the tool because the problem exists” and hypothesize that the tool or its surrounding process helps create the demand. | A feedback path and a predicted observation when one changeable link is removed. | Compare ordinary causal analysis with an explicit inversion prompt. Reject a reversal that predicts nothing different or silently removes the valued outcome. |
| P02 | **Make criticism incur a construction obligation.** Every attacked dependency must lead to a replacement, a way to remove it, or a distinguishing experiment. | Attack → exposed assumption → constructive branch → test. | Critique-only versus critique-plus-construction with the same cases and output allowance. Count distinct useful additions and unsupported assumptions separately. This elaborates F01. |
| P03 | **Turn a defect into a sensor or control input.** Ask what the failure reveals and how the system could use that signal. | An explicit conversion from adverse input to information, energy or control, including false responses and breakdown conditions. | Compare resisting the disturbance with exploiting it. Reject “learn from failure” without a conversion mechanism. The insertion-resistance cue in B015/A2 is a candidate example, not a demonstrated device. |
| P04 | **Force a meeting between two partial mechanisms.** Specify the exact interface where one mechanism changes what the other can do. | Both parent mechanisms, their interface and an interaction prediction. | Baseline, parent A, parent B and hybrid under the same requirements. A bundle that merely adds features does not establish an interaction. H2 supplies a local reason to investigate this further. |
| P05 | **Backcast from an impossible-looking object.** Describe a surprising capability, expose its dependencies, and keep the smallest currently testable part. | Future capability → missing dependencies → enabling experiment. | Future-object prompt versus direct solution prompt. Reject hidden magic, invented resources or an experiment that cannot distinguish the desired capability from existing behavior. |
| P06 | **Exchange functions with the environment.** Ask what an artifact, material, interface or local rule could do that the analyst or specialist currently does. | New function carrier, causal path, maintenance cost and remaining human responsibility. | Compare the relocated function with its original carrier. Reject unchanged work delegated under a new label, or a burden transferred invisibly to someone else. |
| P07 | **Give an anomaly two competing explanations.** Preserve an awkward supplied observation and require two mechanisms that explain both it and ordinary cases. | Rival explanations and one observation on which they disagree. | Normal summary versus protected-anomaly analysis. Reject an invented anomaly, two verbal versions of the same cause, or explanations that make identical predictions. |
| P08 | **Preserve disagreement until it becomes an experiment.** When Robot Talks roles disagree, write the competing predictions before attempting reconciliation. | A decision-changing uncertainty and the smallest probe that could resolve it. | Immediate consensus versus deferred convergence. Measure distinct discriminating questions, unresolved contradictions and burden; a longer disagreement alone is no benefit. |
| P09 | **Distill the causal relation.** Before compressing a candidate, mark the operation, dependency and observable difference that make it distinct. Preserve that relation and its caveats in the compressed output. | A traceable raw-to-summary relation, with lost or parked distinctions explicit. | Ordinary Distill versus this preservation requirement on identical inputs. Blind reviewers assess retention and unsupported additions. This elaborates F02 and addresses observed losses. |
| P10 | **Reserve visibility for a qualified alternative.** After fit and evidence checks, test whether one recommendation slot should carry a distinct alternative rather than only the earliest high-ranked familiar items. | An unchanged full candidate set plus two separately labeled recommendation views. | Frozen ordinary ranking versus a qualified-alternative slot. Measure visibility, usefulness, violations and review burden. Never protect novelty merely because it is strange. This elaborates F03; a human decision study would still be separate. |

P01–P07 generate candidate distinctions. P08 turns an unresolved distinction into a test. P09 preserves distinctions through compression. P10 tests whether the final presentation exposes them. Measure these functions separately; an apparent gain at one stage can be lost at the next.

## A reusable strategy card

For each proposed variant, fill this contract before running it:

1. **Trigger:** the observed limitation that motivates this variant.
2. **Baseline:** what ordinary analysis already says and what evidence is available.
3. **Transformation:** the exact relation, dependency, representation or capability to change.
4. **Construction:** the mechanism, causal hypothesis or discriminating question produced.
5. **Fit:** the preserved outcome and hard constraints; conditional relaxations stay separate.
6. **Difference:** the observable result that would distinguish it from the baseline and nearest alternative.
7. **Failure:** the observation that would defeat the proposal.
8. **Lineage:** the raw candidate, compressed version and recommendation position.

A strategy that repeatedly adds terminology without a new operation or discriminator stops. A strategy can legitimately return no viable opening.

## Compose the existing skills

Use the existing [single-operator dispatch](../../../dispatches/single-operator.dispatch.json) as the design reference for a controlled comparison. The previously validated [combination routes](../../../README.md) remain references for their original compositions; they do not automatically validate these new variants.

Keep the two lanes independent until their first outputs are saved. Lane Z develops and challenges the incumbent; Lane A performs the specified generative operation against the same outcome and evidence. Robot Talks organizes distinct concerns and exposes the cross-concern tension. In a P02 condition, the attack then has a constructive obligation. Distill compresses only after generation and carries lineage. Anonymous reviewers compare the raw distinctions, compressed distinctions and displayed recommendations against a frozen baseline archive and concurrent controls.

Before executing a new route, Dispatch Spec should make the changed step, inputs, outputs, dependencies, role boundaries, join rule, stop conditions and evidence artifacts explicit. Local technique extensions need a source and validation note. Reuse the skill capabilities; do not mistake a validated route structure for evidence that the technique works.

## Prepare three focused experiments first

The existing [future-test record](future-test-candidates.json) identifies a smaller first investigation than crossing all ten variants:

- **F01 / P02:** critique-only versus criticism that must construct an alternative. This addresses the user's destructive-to-creative request; the present bundle execution failures prevent a clean full-workflow conclusion.
- **F02 / P09:** ordinary Distill versus explicit preservation of the distinguishing causal relation. Use identical raw inputs, including the observed lost relations, then untouched examples for confirmation.
- **F03 / P10:** ordinary recommendation ranking versus one qualified distinct-alternative slot. The current first-two results motivate this comparison; they do not establish better decisions.

For each experiment, freeze new cases and a case-specific comparison archive before seeing outputs; include ordinary-analysis and generic-creativity comparisons where the intervention concerns generation. For compression and ranking, hold the generated inputs fixed. Declare repetitions, stopping conditions, qualification criteria and failure handling in advance. Validate the role output contract with a separate preflight, including its enumerated fields and available write command. Failed attempts remain failures rather than being silently replaced.

Report unique causal families, useful discriminating questions, constraint fit, unsupported assumptions, retention, recommendation visibility and known output burden separately. Repetition tests recurrence in model outputs; it is not replication across real organizations. A future field test is needed to establish that a candidate intervention improves outcomes.

The next question becomes concrete: **which change makes the process discover and preserve a useful possibility its baseline misses?**
