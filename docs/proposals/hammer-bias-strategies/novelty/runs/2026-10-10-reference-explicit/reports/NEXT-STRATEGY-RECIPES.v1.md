# Prepare strategies that change the next action

These are ten **future investigation recipes**, composed from the ten strategy operators. They are not additional scored arms, completed experiments or findings of the frozen run. Combining two named methods does not establish novelty. Each recipe has to produce an operation that differs from the supplied ordinary archive and from the operations produced by its component methods alone.

The working target is: **same valued outcome, different available next move, different testable prediction**. A better sentence can expose an opening; the construction and its probe carry the claim.

## Common preparation

Supply a problem packet with a valued outcome, constraints, observations, available resources, ordinary operations already considered and the preferred tool's operating dependency. Give observations stable IDs. Record who bears the work and how failure would appear.

Maintain two lanes throughout. The outcome lane guards the required function and constraints. The invention lane changes one named dependency, causal link, carrier, sequence or interaction. Neither lane may silently redefine success.

Use Robot Talks to preserve two incompatible predictions where the recipe requires them. Use Distill to retain a compact core and a separate source-bound residue, with uncertainty and discarded details still attributable to the input. A fresh builder receives the declared branch and common facts. It returns an action, closest rival, separating observation, defeat condition, resources, burden and unknowns.

## Ten composed recipes

| Recipe and combination | Sentence that opens it | Forced next action | What would defeat the opening |
| --- | --- | --- | --- |
| **1. Build from the forbidden dependency** — S01 tool deprivation + S06 residue-fed construction | “If the hammer vanished, which discarded detail would become the tool?” | Remove the preferred tool's operating dependency. Give a fresh builder the source-bound residue to construct the same function through another available resource. Compare the operation with deprivation using the summary alone. | The construction restores the forbidden dependency, needs an unavailable indispensable resource, or adds no different operation. |
| **2. Interrupt the problem factory** — S02 causal return-path inversion + S05 delayed convergence | “Does the hammer find nails, or recruit them?” | Keep initial demand fixed. Preserve an exogenous-demand account and a tool-induced later-demand account through Robot Talks. Build an interruption of the proposed return link and a sham interruption; record their different predictions for later demand. | The accounts predict the same result, the intervention changes initial demand, or the interrupted link is not the link claimed to generate later demand. |
| **3. Make failure the sensor** — S03 attack to fresh builder + S07 protected anomaly | “Can the place where the hammer fails tell us where to act?” | An attacker specifies a failure and the outcome that survives. The builder makes that failure signature a diagnostic observation and chooses an intervention whose location or timing depends on it. | The diagnostic cannot separate rival failures, cannot change the next action, or merely repairs the tool without using the failure as information. |
| **4. Put the work on trial** — S04 carrier migration + S03 constructive attack | “Give the joint the hammer's job; make the joint account for the work.” | Move a function into the object, arrangement or environment. A separate attacker traces every displaced action, resource and maintenance obligation. Build a transfer with a measurable burden ledger, then attack its new dependency. | The same work is hidden in another actor, the required function is lost, or the carrier's indispensable dependency is unavailable. |
| **5. Give the anomaly a control knob** — S07 protected anomaly + S06 residue-fed construction | “The detail we nearly deleted may be the variable we need.” | Preserve one inconvenient observation in Distill's residue. A fresh builder turns its suspected condition into a variable and sets out two accounts with opposing predictions when that variable changes. | The residue is invented, the variable is not manipulable or observable, or changing it leaves the accounts indistinguishable. |
| **6. Search backward for the first fork** — S08 rival backcasting + S05 delayed convergence | “Imagine two successes; find the first choice where they disagree.” | Construct two plausible successful futures with different dependencies. Backcast to their earliest divergence. Preserve both paths until a fresh builder proposes a feasible present action that selects or distinguishes them. | The futures use the same dependency, their divergence lies beyond available resources, or the present action cannot distinguish the paths. |
| **7. Move the conversation, keep the tools** — S09 interface ablation + S04 carrier migration | “What if the useful invention lives between the tools?” | Locate a claimed interaction between two parent functions. Transfer only the connection into another available carrier. Compare the original connection, transferred connection, broken connection, co-presence and each parent alone. | A parent alone explains the result, the new carrier changes a parent as well as the link, or the connection adds no separating prediction. |
| **8. Turn the harmful boundary into an exit trigger** — S10 objective boundary inversion + S01 tool deprivation | “At what point should the hammer tell us to stop hammering?” | Predict a regime where increasing the preferred intervention worsens the present outcome. Build an observable trigger that switches to a route without the tool's dependency while preserving the required function. Fix the trigger before confirmation. | The adverse boundary is selected after observing results, the trigger cannot be measured, or the alternative restores the same dependency. |
| **9. Attack the proposed feedback escape from the future** — S02 causal return-path inversion + S08 rival backcasting | “Which escape survives after the world learns from it?” | Propose a break in tool-induced demand. Backcast from two later worlds: one where that break persists, another where adaptation recreates the dependency. Build a present probe of the specific adaptation link rather than assuming escape remains stable. | The later adaptation is asserted without a supplied basis, the worlds differ in unrelated inputs, or the probe cannot distinguish persistence from recurrence. |
| **10. Ask the anomaly to identify the interaction** — S09 interface ablation + S07 protected anomaly | “Does the awkward result belong to either tool, or to their conversation?” | Use an anomalous observation to specify competing parent-only and interaction accounts. Preserve both parent functions while interrupting their link. Build a measurement that can attribute the anomaly to the connection. | Interrupting the link also disables a parent, the anomaly remains equally explained by a parent alone, or the probe lacks opposing predictions. |

Logical inversion earns its place through a counterexample or a changed causal test. “Without a hammer, the valued function still occurs” can challenge necessity. “Nails cause hammers” by itself supplies neither a counterexample nor a test of tool-induced demand. Present harm from more intervention and later demand created by tool use require different probes.

## Compare a composition with its parents

For a future recipe investigation, declare the ordinary process, each component method and their composition before generation. Use the same problem facts, ordinary archive and opportunity to produce proposals. Keep all raw first attempts, including explicit no-opening and delivery failures. Separate development cases from fresh confirmation cases; lock the raw independent judgments before rewriting the proposals.

The assessment asks whether the composition supplied a locally distinct operation with supported resources, a separating prediction and a clear defeat condition. It also asks whether either component already supplied that operation. More cards, different wording and reviewer agreement alone cannot show that a composition adds value. Unequal input size or actual runtime should be reported rather than called equal compute.

Before native execution, verify the actual scored output directory, exact condition identifier, source-reference grammar and available interpreter. Give machine identity separately from the method's human name. These are preparation improvements suggested by the current run's delivery failures; they have not been applied to or tested inside its frozen scored attempts.

## A prompt for preparing the next recipe

> Keep the valued outcome and hard constraints fixed. Choose one primary dependency or causal link to change. Select a second technique only if it can expose an opening the first technique may lose. State the handoff, what the builder is forbidden to restore, and the closest operation already in the archive. Return one concrete new next action, the two rival predictions it separates, a defeat condition, source-bound assumptions, resources and displaced burden. State how we would compare the composition with both parents. If no distinct action survives, retain that result.
