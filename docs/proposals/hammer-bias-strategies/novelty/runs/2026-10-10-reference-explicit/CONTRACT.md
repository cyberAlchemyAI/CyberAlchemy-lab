# Ten-strategy reference-explicit native runner contract

This package prepares, guards, joins and reports a synthetic case-bound study of 184 fresh native calls. It does not invoke models, implement a CLI model adapter, install a capability, or claim canonical skill authority. The parent owns actual native starts and observed FINAL receipts. A separate Balancer and independent prelaunch assessor must review before freeze.

The parent records actual sibling Dispatch Spec skill/schema/catalog/validator hashes in receipts/dispatch-source-bindings.v1.json; those referenced source bytes and the receipt are bound by preparation/freeze. Dispatch validation describes this explicit custom native controlled-research route. It does not establish canonical capability-bound runtime admission or a test of full canonical skills.

The complete-pair track preserves every declared raw candidate and every pair. The conservative-qualification track preserves unknowns and disagreements and computes bounded distinct-family counts. They recompose into one inspectable runner with a three-round preparation limit. The historical proposer instruction's 552-row arithmetic was corrected prospectively by the parent: 14 unit rows + 28 card rows + 112 archive pairs + 378 candidate pairs = **532 rows**. No candidate, archive pair or candidate pair was removed.

## Scope, inputs and isolation

Run root is the directory containing this contract. The required input is inputs/fresh-cases-and-archives.v1.json. Its exact top-level keys are classification, cases, independence_note. Classification must be synthetic_fresh_case_and_archive_preparation; independence_note must be "No prior candidates, strategy prompts or results were read".

There are exactly PD, WD, PC and WC case packets. PD/WD are development, PC/WC confirmation. PD/PC domain is physical; WD/WC domain is workflow. Each packet requires precisely:

- case_id, phase, domain, valued_outcome, preferred_dependency, causal_return_path_hypothesis, anomaly_id.
- hard_constraints: 3–6 objects {id,text}, with C1… contiguous local IDs.
- observations: 5–8 objects {id,text}, with O1… IDs. anomaly_id names an observation.
- resources: 5–8 objects {id,text,available:boolean}, with R1… IDs.
- parent_operations: exactly two {id,text}, with P1/P2.
- available_observables: 3–5 {id,text}, with M1… IDs.
- unknowns: 2–4 {id,text}, with U1… IDs.
- ordinary_archive: 3–4 {id,operation,relation,probe,limits}, with A1… IDs.

Nonempty text, exact keys, numeric ranges and local uniqueness are validated. Ordinary archives are split from worker case packets. Future confirmation inputs may exist on disk; development worker prompts cannot include them. Roles read only assigned literal prompts and cannot search the folder.

Per case: two shared concerns INV/ATT; fourteen conditions A B C D O G S01 S02 S03 S04 S07 S08 S09 S10; three fresh calls per condition, stage1 → stage2 → builder; and two independent whole-case reviewers. That is 2 + 14×3 + 2 = 46 per case, 184 overall. The original six-arm pilot contributes 88 calls; eight additional arms contribute 96. Shared INV examines the causal return-path hypothesis, reversed arrow and intervention with fixed initial demand/outcome, distinguishing necessity logic from causal observation. ATT breaks the preferred operating dependency, records the surviving outcome, and excludes quietly reinstalling it.

A/B/C/D form the process factorial: immediate/main, delayed/main, immediate/residue, delayed/residue. B minus A tests S05 delayed convergence; C minus A tests S06 residue feeding; D combines them. O and G retain their ordinary and generic creativity three-call controls. S01/02/03/04/07/08/09/10 are explicit interventions in stage1. S02 holds initial demand fixed while manipulating the return link; S10 seeks an adverse intervention-dose boundary and detector. They are never aliases.

All arms receive the same case packet and shared concerns. Stage2 receives only its own stage1, the case and concerns. Its summary and residue draw from supplied material; new hypotheses are labeled and are never passed off as source content discarded earlier. A/B/O/G and extra S builders receive only stage2 summary; C/D builders receive only residue. Every builder additionally receives the common case and concerns, without full stage1 or the other stage2 branch.

The caps are 600 JSON words for each stage1/stage2, 1200 for each builder, and at most two cards. Runtime applies a normalized JSON word count including keys and IDs, so the cap is conservatively stricter than prose only and independent of pretty-printing. Actual saved output words are separately counted directly from file text. Normalized complete-input and supplement words are recorded per started call, including both actual scored reviewers. Caps alone establish neither equal context nor equal compute; no padding is added. Concern output has no additional word cap. Review has a 25000-word soft cap and exhaustive coverage takes priority.

Resources name actual R IDs; unavailable indispensable resources fail feasibility. residue_refs means actual received supplement item IDs, including summary IDs for a main-fed builder. Generated artifacts use open(..., "xb") exclusively. Workers must validate their own JSON in memory and use open(path, "x") once. No repairs or retries after first save. Native join records the first observed output hash and terminal witness; later output drift is rejected. The runtime cannot prove that an external worker obeyed exclusive creation before it first observes the file; the instruction and independent parent observation are the evidence for that boundary.

Administrative unit/card labels are opaque and case-specific. ## Qualification, uncertainty and reporting

Review has exactly all fourteen units, every raw declared card, every card×archive pair, and every unordered distinct-card pair once. Duplicate, missing, invented or incorrectly bound keys fail the whole review. Relations are equivalent, distinct or unknown. No transitivity or forced merge is imposed.

A structurally valid card with available indispensable resources qualifies only if both independent reviewers affirm all five axes and judge it distinct from every archive. Uncertainty-eligible cards have no false axis and no equivalent archive relation from either reviewer, retaining unknowns. Source support covers faithful observations and explicit hypothesis/observation distinctions. Clear defeat, genuine separating predictions, hard constraints and disclosed burden are substantive criteria.

A proven-distinct edge requires both reviewers' distinct judgments. An edge is excluded from coexistence if either reviewer says equivalent. Every other edge is unknown: permitted for the possible upper bound, excluded from the proven lower bound. The exact maximum clique among qualified cards gives the proven-distinct lower bound; the exact maximum clique among uncertainty-eligible cards with unknown edges permissive gives the conservative possible upper bound. All unknown pairs therefore retain [1,n] for n otherwise qualified candidates, rather than forcing a merged singleton. Empty valid no-opening units have [0,0].

Per-condition raw, qualified, uncertainty-eligible and lower/upper counts are reported alongside case-level bounds, review disagreements and all184 dispositions. B−A, C−A, D−A and D−B−C+A use interval arithmetic. Additional S arms compare to O/G with interval subtraction. Any hard protocol failure nulls all inferential contrast/control comparisons and forbids numeric superiority claims, while preserving descriptive raw bounds when assessments exist. Missing review or gated build is protocol-missing; it is never converted into zero performance. All confirmation cases run regardless of development negatives or failures after development disposition closure.

Actual planned/started/completed/gated counts and saved output/input/supplement words are available. Native token usage and monetary cost remain null/unavailable, never zero. UTC events support observed wallclock accounting; model-internal compute is unavailable.
