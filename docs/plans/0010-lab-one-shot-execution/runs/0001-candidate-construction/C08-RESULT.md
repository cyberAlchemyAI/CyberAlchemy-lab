## What works

The new `implementation/lab-context/candidates/v1` extension composes the existing verified ephemeral Session with an independently pinned native ontology reader. It emits seven actual schema-validated candidate records:

1. Context Request — exact Context revision, named consumer, selectors, exclusions and budgets.
2. Context View — source epoch, original-byte hashes, lineage, limitations and expiry.
3. Ontology — an explicit bounded native read scope, separate from domain Artifact instances.
4. Ontology Cut — actual native semantic cursor and event-set digest.
5. Ontology View — exact cut, selected native identities, exact governance join and expiry.
6. Implementation — `implementation:lab-exact-context-generator@candidate.2`, frozen in the selected package with its exact source and environment closure.
7. Typed Relation — the existing Implementation-to-Product-Capability realization pair, separately frozen and schema checked.

Generator package version, Implementation artifact revision, original-byte hashes, native event digests and protocol projection digests retain separate meanings. The generator cannot substitute a different owner, Project, capability or executable under its frozen artifact revision. Related historical Implementation records retain their identities.

Every reference claimed as a governed source resolves in the verified Project projection. Coeval candidates, schema labels, native subjects, Session handles, routes and environment references are explicitly classified. A Principal reference does not authenticate a human, and an Assignment does not grant action permission.

Short memory belongs only to the Session. It is absent from carriers, returned packs and fresh-process inputs. Close, expiry, changed HEAD/configuration/source/code/native history erase it. A later Session reconstructs context and starts empty.
