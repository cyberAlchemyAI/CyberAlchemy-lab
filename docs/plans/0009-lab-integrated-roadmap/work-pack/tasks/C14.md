## Implementation detail: ordered rules

1. Resolve effective predecessor and preserve exact ordered pair semantics; never form a Cartesian product
2. Require same unique semantic question for reuse or propose a distinct Relation Kind with orthogonality/no-collapse evidence
3. Bind closed pair-specific qualifier domains and cross-qualifier constraints; identify schema-fit changes explicitly
4. Select one canonical writable relation authority: Typed Relation or specialized carrier with a digest-bound read-only projection
5. Resolve both exact endpoint contracts and directional roles including any explicitly permitted internal records
6. Bind contestability/owner/evidence/lifecycle/effects and stable reviewed closure before new global pair can be used

## Edge cases and failure modes

- Duplicate semantic question hidden behind a fresh axis ID
- Free strings treated as pair-specific closed value domains
- Two writable relation authorities
- New kind registration interpreted as new connections
- Review-only semantic evidence claimed as executable proof
