# Lab runtime completion layers

Status: candidate. Brownfield implementation; this plan supplies no execution or governing authority. [DAG](DAG.md) and [task contracts](WORK-PACK.md) are the scheduling source.

The minimum proof is a complete real Context/Session/learning lifetime with a functioning Machine read path. Existing implementation and fixtures provide the starting point; they do not establish this proof. Layer boundaries follow the decision unlocked, user outcome and risk reduced relative to implementation, verification and coordination cost.

Costs are dominated by full replay/hashing/native work in L0, source closure and compatibility work in L1, qualification and human coordination in L2, and actual owner/effect coordination in L3. None justifies skipping a lease, source guard, original member or acceptance clause. Later layers preserve all earlier invariants: exact selected source/profile and independent Actor authority, real deadline, raw request signatures, durable idempotency and honest uncertainty, ephemeral Session memory, protected host custody and retained rollback.

The layer labels are evidence milestones, not global scheduling barriers. Independent inventory, setup and owner-prerequisite investigation can overlap earlier layers. Each task's explicit DAG dependencies and authority preconditions decide whether it is runnable. One shared merge/freeze coordinator prevents overlapping writers from invalidating qualification.

Recommended first unit: T00, then independent T01 Machine diagnosis and T02/T35 current Source8 construction/profiling; diagnostics determine the smallest valid fixes in T03/T05. Scale, multi-host consensus and general autonomous Paperclip task management are outside this completion scope.
