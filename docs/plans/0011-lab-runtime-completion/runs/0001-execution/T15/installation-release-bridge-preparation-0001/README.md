# Staged installation, proof and native host bridges

Owned implementation only. No code here has been imported or executed during
authoring. No controls, native/API calls, installation, guard, lease or large
table byte check ran. Current captured files and the live learning process are
untouched. These modules are not selected by the current Source.

`native_launch.py` provides the new explicit `SelectedNativeLaunch` and
`SelectedNativeReadStore` types. The launcher selects dependency2345 and the
actual installation0004, runs the selected loader with cache disabled and exact
ABI directory, passes a fixed environment instead of inheriting it, and invokes
the original native executable with the original30-second limit. Actual T07
preflight and installed-file guards run before and after a later invocation.
The new read store reuses the actual original NativePins, closure, byte/digest,
request, cursor and projection boundaries. It does not replace or impersonate
the old NativeReadStore. Caller adoption must explicitly select this new type
in a new source family; no old fixture or original direct-host proof transfers.

`protected_bridge.py` opens independently selected0700/0600 custody controls
through no-follow descriptors, checks root/file identities and attachment, then
constructs the actual reviewed ProtectedReader and typed verifier at their true
origins. Complete proof rows stay in that reader; no ordinary Vault/frame limit
is raised. The host's existing guard remains active before/after each boundary.
Production custody anchors and per-record semantic/proof/current-context
dispositions remain unselected in `host-control-DRAFT.json`.

The typed graph's selected nodes contain native version refs; its declared edges
and roots contain the exact native identities accepted by the original graph
implementation. `typed-review-observation.schema.json` introduces a separate
closed v3 observation. Complete protected proof is verified independently from
semantic edges. Governed member headers are derived from the original pinned
policy nodes and eligibility bytes and compared exactly with observations;
technical code/proof/package bindings cannot fabricate semantic nodes.
Existing readiness v2 digest-edge meaning and the entire legacy `graph` method
remain unchanged. New v3 observations require an independently selected bridge,
policy, eligibility, exact member routes and real signed readiness evidence.

`composite_bridge.py` uses the actual reviewed CompositeEnvironment guard,
receipt/whole-receipt verifier and genuine original R02 installer. It selects the
whole composite descriptor and its exact R02 subdocument and independently
checks every native/ABI requirement. A new preexisting lock and root have
independently supplied identities; open descriptors and attachment checks span
the transition. The existing public host preflight, approval, source, schema,
cut, nonce, real deadline and effect-claim route remain required. Fresh guards
and whole active preimage checks run before descriptor commit. Receipts and
active descriptors are written relative to the held root descriptor; prior
generations remain. Reconciliation is inspect-only and requires an independently
selected observed active state; no automatic retry or cleanup is implemented.

`completion_bridges.py` is the trusted bootstrap interface. Construct
`CompletionBridge(raw_bytes, independent_binding, repository, modules, environment)`
with real original modules and CompositeEnvironment. The selected private plan
v2 adds exactly `bridge_binding` to the existing plan fields. The existing
authentication policy still contains only `installation_release_control.plan_binding`.
The trusted host supplies `host.completion_bridge`; a public request cannot
construct or choose it. `bind_host` requires the exact class and complete
ref/hash match. Missing bridge/custody/semantic/root/receipt selection refuses.

The optional `workflow_output_binding` in this same trusted descriptor is shared
with the separate T31 integration. Its read-only property returns a copy after
rechecking the selected descriptor; absent/null means unavailable. The property
does not grant output custody. T31 must independently verify the exact bridge
type/origin, descriptor binding and its separately selected output-reader
contract. This package does not edit Service, authentication or workflow code.
