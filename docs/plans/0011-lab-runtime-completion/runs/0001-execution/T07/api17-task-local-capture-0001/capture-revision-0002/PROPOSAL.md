It returns exactly the SHA-verified bytes from the no-follow file descriptor, with size at most64 MiB and fresh file identity, mode/owner and directory attachment checks. Parsed and compiled bytes come from that captured value. All descriptors are per invocation and close in finally. Ordinary Vault/frame limits, complete current row hashing and every original callback remain unchanged.

The original `_verify_files` AST is identical. No shared API17 file was changed by this proposal. Root must wait for the live74-case terminal, apply the exact postimage, independently recapture source/profile/inventory and all affected descendant selections, and qualify the new exact candidate. The old startup result remains evidence of its earlier scoped candidate only; it does not qualify this postimage.

Fourteen owned tests passed. Real filesystem leaf/ancestor replacement, mutation of an already-read byte, truncate/grow and mode changes are scheduled after the helper's first real OS read. The scheduler returns the actual unmodified os.read bytes. It patches only that OS read boundary in the isolated helper test process; no original source/policy/schema/custody callback or clock is imported or replaced. Owned scratch is removed. Symlink, wrong digest, sparse oversized metadata and malformed bindings also refuse.
