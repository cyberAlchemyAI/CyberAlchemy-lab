# Work, evidence and operational learning

Trace the attempt, output, review, lesson use and assessed result.

Draft prepared on 2026-10-14. Integration and final T21 qualification remain pending.

## Begin with the actual Work scope

Use the existing [Work definition](../../../../../../../../../../../../lab/reference/records/def-cal-definition-work.md) and [learning explanation](../../../../../../../../../../../../lab/guide/operational-learning.md). Operationally, select exact assignment, sources, expected outputs, permitted action kinds, budgets, tool/workflow contract and assessment criteria. Work is not satisfied merely because an agent ran or an artifact exists.

Engineering and research share source/current authority boundaries but produce different evidence. The [engineering workflow](../../../../../../../runtime-narrative-preparation-0001/evidence/implementation/lab-workflows/candidates/v1/workflows/engineering.py) binds implementation/output/action/Work postimages. The [research workflow](../../../../../../../runtime-narrative-preparation-0001/evidence/implementation/lab-workflows/candidates/v1/workflows/research.py) binds its predeclared method, inputs, observations and evaluation. A negative result or an open cause remains a valid bounded observation.

## Keep output and admission separate

| Observation | What it does not establish |
| --- | --- |
| Planned Work or WorkflowRun | An actual attempt or permitted Tool dispatch |
| Tool/process exit | Correct output, Work satisfaction or human usefulness |
| Exact output carrier | Repository admission or causal benefit |
| Local signed transaction | Organizational adoption or deployment |
| Proposed implementation/represented-subject mapping | An admitted carrier alias |
| Assessment evidence | A positive hypothesis or universal conclusion |

The [preserved workflow review](../../../../../../../runtime-narrative-preparation-0001/evidence/implementation/lab-workflows/candidates/v1/REVIEW.md) explicitly records kind/represented-subject coupling gaps and candidate boundaries. Later implementations need their own output-bearing transitions and actual native/consumer witnesses; coverage from different versions cannot be merged by count.

## Follow failure and challenge

Preserve the exact failed inputs/output, expected criterion, method, observed occurrence, manifestation/cause/impact/containment/recovery and uncertainty. A classification is not causal proof. A challenge refers to exact material and route; an agent's controlled contest is not the governing owner's response.

Candidate handlers can prepare linked observations, failure assessments and challenge records. Their returned posture and journal show the selected bounded effect. Canonical admission needs the actual independent governing transaction and source/cut proof.

## Select, apply and assess a lesson

A reviewed Lesson has applicability, exclusions, evidence, instruction precedence and an exact producer/implementation scope. Selection examines that inventory for the current assignment. Application records actual use or deliberate non-use of an exact lesson version. Assessment compares its prediction with later observed evidence.

The current Source8 route selects a conditional Lesson host and application implementation; the [historical API reference](../../../../../../../runtime-narrative-preparation-0001/evidence/docs/plans/0011-lab-runtime-completion/runs/0001-execution/T21/api-reference-preparation-0003/reference-0001/README.md) now documents both general and conditional routes. A completed candidate Application can be read through an independently scoped ApplicationJournal. That correspondence does not prove that the lesson caused improvement.

The original 900-second integrated path has no current complete apply/assess witness. Failed selection timing cannot supply an empirical full-tail reserve. Human satisfaction, product benefit and genuine governing acceptance remain separate from technical fixtures.

## What continuity preserves

Persist permitted public outputs and their exact provenance through the applicable recording route. Later Sessions obtain newly checked Context/Ontology Views and current permission; they do not recover the old private signer or notes. [Continuity code](../../../../../../../runtime-narrative-preparation-0001/evidence/implementation/lab-continuity/candidates/v2/custody.py) verifies archives/replay rather than transferring lost live resource authority.

For the Paperclip pilot, the successful bounded read episode is evidence of reading/orchestration only. The owner's usefulness assessment and autonomous engineering/research Work are still missing. A reusable Lab needs those actual inputs and outcomes, not a larger catalog count.
