# CyberAlchemy Repository Identity

Identifies the earlier CyberAlchemy v2 repository candidate and its purpose of consolidating dispersed work into a reviewable base. The definition is not evidence of a completed stable release.

**When it applies**

Use this term for the local consolidation project at `cyberAlchemy-v2/`, not for all CyberAlchemy work everywhere. CyberAlchemy v2 owns local definitions, constitutions, source maps, Craft state, and promotion routes for this stable repository effort. Its objective is to become the base repository users receive when they download CyberAlchemy, with enough authority, ontology, inventory, and runtime projection structure for others to construct above it.

**Record formats**

No record-type contract in this selected catalog declares this exact definition among the meanings it uses.

**A stated exclusion**

Admission, activation, publication, release, deployment, and external effects.

The formal statement governs the meaning. The short introduction above helps you read it; it does not replace its requirements.

## Source explanatory wording

CyberAlchemy v2 is the home base: the repo you can download, trust, and build above.

## Exact governing statement

CyberAlchemy Repository Identity is the normalized definition identified by semantic.cyberalchemy-repository-identity, owned within scope.lineage, and carried by type.definition. Any canonical instance must preserve that classification and the accepted source relations to CAV2-D9 without silently merging it with another target.

Bound source-semantic basis:

CyberAlchemy v2 is the project-local stable repository candidate that organizes the dispersed CyberAlchemy, Arcanum, DomainSpec, inventory, ontology, research, validation, and operations material into source-ledgered authority layers, candidate towers, promotion queues, and execution surfaces so it can become the downloadable CyberAlchemy base repository after owner review and extraction.

- CyberAlchemy v2 is not the same as public Arcanum, private DomainSpec, the older `cyberAlchemy/` source folder, or a finished standalone product. It may reference those sources, but it does not automatically absorb their authority. It becomes the owner of CyberAlchemy base authority only through import, promotion, boundary review, and standalone extraction decisions.
