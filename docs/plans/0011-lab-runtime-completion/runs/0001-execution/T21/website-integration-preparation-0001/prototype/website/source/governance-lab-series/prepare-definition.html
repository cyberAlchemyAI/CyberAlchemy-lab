Prepare a definition for review

State an exact meaning and prepare its review obligations without assuming acceptance.

Result and prerequisites

Prepare one exact candidate meaning and the materials its owner needs to review it. Select the applicable Definition contract, semantic owner, authority scope, supporting sources, primary consumers, index/registry route and drift route. The complete criterion specimen uses Definition/v2.

The specimen passes that selected schema, but its source posture and acceptance obligations remain unresolved. Use it to inspect structure; prepare real source and owner evidence independently.

1. State the meaning and its boundary

Identify the term, stable identity and proposed version. State one governing (normative) meaning, its applicability, exclusions and boundaries. For export identifier completeness, declare S, A, F and E, then require every identifier in RequiredIds(S,A,F) to appear in ExportedIds(E).

Value accuracy, live-source consistency, access permission and incident recovery each fall outside that criterion. A case with all IDs present but incorrect values exposes this boundary. It does not falsify the identifier-coverage statement.

2. Align the three voices

The scientific/formal voice states the governing meaning. The plain-language and domain-context voices are explicitly non-normative explanations. Use the same scope in each voice. Avoid making “every customer record everywhere” the plain-language explanation of a statement about one fixed account, filter set and snapshot.

Declare testable conditions and notation. Preserve an example that satisfies the criterion and an example that fails it, with the selected inputs visible.

3. Prepare the review obligations

  1. Bind source identities, selectors, digests and admitted source posture using the applicable source contract.
  2. Identify primary consumers and any affected meanings, formats or connections.
  3. Prepare the registry postimage (the proposed registry contents after the change) and synchronized index entry; preserve the exact canonical JSON and generated projection relationship.
  4. Declare the current drift audit, accountable owner and challenge route.
  5. Inspect internal consistency and non-collapse: meaning must remain separate from representation, classification, permission and lifecycle standing.

Schema checks establish required representation. Reference closure, source posture, generated projection consistency, the registry/index and semantic review remain separate checks.

Expected output and owner decision

Submit the exact candidate version with the formal meaning, explanatory voices, boundaries, source evidence, affected consumers, proposed index/registry changes and review findings. Keep open obligations visible. Only the applicable exact owner decision can make that version governing authority within its declared scope.

Common failures: treating a schema pass as acceptance; hiding changed meaning as a formatting update; allowing the plain-language voice to expand the formal scope; inferring agent permission from definition acceptance.

A changed meaning needs its applicable semantic change route. After acceptance, update affected consumers and derived views through their own rules. Read the lifecycle distinctions →
