## Organize knowledge and work

CyberAlchemy organizes knowledge and work. It connects meaning, purpose, performed work and possible next changes. A returning person or agent has records to examine instead of reconstructing everything from conversations.

Consider an incomplete export report. We need a meaning for “complete,” permission for relevant data, an inspectable comparison and a response decision. The Lab gives each responsibility a place in the same project knowledge.

The guide follows the fictional [Northstar incident](guide/authority.md#opening-incident-case-title). This page introduces the concepts used in that investigation.

## Begin with what the words mean

A definition states meaning and boundaries. An [accepted exact version](reference/records/def-cal-definition-definition.md#def-cal-definition-definition) is a basic unit of authority over meaning within an accountable owner’s declared purpose and scope.

For this export, completeness requires every selected identifier from the declared account, filters and fixed snapshot in the saved output. That examines identifier coverage. Value accuracy and data-access permission need their own requirements.

**[Definition](reference/records/def-cal-definition-definition.md#def-cal-definition-definition)**

States a term’s meaning and where that meaning applies.

**[Artifact Type](reference/records/def-cal-definition-artifact-type.md#def-cal-definition-artifact-type)**

Sets the contract for a kind of record, including its meaning bindings, format and validation requirements.

**[Artifact](reference/records/def-cal-definition-artifact.md#def-cal-definition-artifact)**

An identifiable, typed and versioned record—for example, this particular investigation’s Work record.

Connections also have rules. An [Ontology View](reference/records/def-cal-definition-ontology-view.md#def-cal-definition-ontology-view) displays selected subjects and relationships while retaining identities and the sources it depends on.

## Ask three governance questions

Authority, provenance and lifecycle make different parts of the investigation explicit.

**[Authority](guide/authority.md#governance) What governs meaning and action?**

The accepted completeness criterion governs the assessment. A separate, scoped permission determines what the agent may inspect or change.

**[Provenance](guide/provenance.md#evidence) Where did this come from?**

Identify the source snapshot, account, filters, output, comparison method and recorded result that support the omission claim.

**[Lifecycle](guide/lifecycle.md#change) What can change from here?**

The definition, proposed code and incident each have their own state and requirements for change. A proposed fix proceeds through its assessment and owner decision.

The three questions stay with the work. Evidence supports a scoped conclusion, permission governs an action, and a transition records a resulting state.

## Connect the need to the work

Purpose, promised outcome and particular effort need separate identities. Follow those responsibilities through the incident.

1. ### Intent The need

   

   Customers need their complete eligible data. [Intent Resolution](reference/records/def-cal-definition-intent-resolution.md#def-cal-definition-intent-resolution) selects a response and a way to assess whether it satisfies that need.
2. ### Product The promise of value

   

   The platform promises eligible export through a Product Capability. Particular implementations realize the outcome.
3. ### Project and Goal The coordinated effort

   

   The repair Project coordinates the effort. Its Goal states the outcome and evidence needed for achievement.
4. ### Work The bounded job

   

   Investigate the reported omission, using named inputs, constraints and expected results.
5. ### Agent Assignment The participant’s job

   

   Assignment binds the agent to investigation. Permission comes separately from the applicable authority or delegation.

## Let knowledge outlast the agent session

An [Agent Session](reference/records/def-cal-definition-agent-session.md#def-cal-definition-agent-session) is temporary. Context View supplies task information, while Ontology View selects relevant concepts and connections. Both identify source versions, limits and refresh conditions.

[Project State](reference/records/def-cal-definition-project-state.md#def-cal-definition-project-state) supplies continuity through saved meanings, records, decisions, evidence, connections and histories. Working memory belongs to one session. When that machine session ends, its instance ends too. A later agent recovers durable knowledge through fresh checked views.

The identifier comparison can survive the session, so another agent can inspect its basis and continue investigating cause. A saved lesson can also be examined through later use and benefit evidence.

## Use Craft for the software design

Craft is the software-design Product within the Lab. Its tools express responsibilities, architecture constraints and supported construction from model to code.

Craft separates a **Rule**’s condition, a **Calculation**’s derived value, a **Query**’s retrieval and an **Operation**’s state change. In its capacity example, the classifier accepts only a request strictly below supplied capacity. Reserving capacity is a separate Operation.

The Craft model describes design and implementation. Lab records connect that work to purpose, ownership, evidence and decisions. Generated code and checks can be Work outputs, with acceptance and deployment governed through their own authority routes.
