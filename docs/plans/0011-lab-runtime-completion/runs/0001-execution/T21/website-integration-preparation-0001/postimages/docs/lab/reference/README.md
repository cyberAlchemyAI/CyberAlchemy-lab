# Reference library

<a id="reference"></a>

[Documentation home](../README.md)

Use this library to move from an explanation to an exact meaning, record format or permitted connection. Start with [how to read the library](reading-the-library.md) and [complete record examples](record-examples.md).

| Catalog | What you can inspect |
| --- | --- |
| [Definitions](definitions.md) | Plain explanations, exact governing statements, formal expressions, applicability, exclusions, versions and captured acceptance. |
| [Artifact Type contracts](artifact-types.md) | Meaning bindings, required fields, representation constraints, versions and original schemas. |
| [Relation kinds](relation-kinds.md) | The question each connection answers, direction, exact ordered endpoint pairs, qualifiers and forbidden inferences. |
| [Endpoint kinds](endpoint-kinds.md) | The declared record kinds that can participate in typed connections. |

This captured catalog selects **183 definition identities, 121 current type-contract bindings, 41 relation kinds and 109 endpoint kinds**, with **550 declared ordered endpoint pairs**. Historical versions are retained too. The counts describe this selection. They do not establish coverage of every possible Lab concept.

The [machine-readable catalog snapshot](catalog-snapshot.json) preserves the imported selection. Its `source` fields describe the website's captured source tree; the Markdown entries link to the corresponding repository originals. The [import manifest](../IMPORT-MANIFEST.json) records source and output fingerprints and compares digest-bearing catalog records against the repository bytes at import time.

For a current authority selection, inspect the [canonical Definition index](../../../authority/definitions/DEFINITIONS-INDEX.md) and [current Project State lookup](../../../authority/project-state-transitions/current.json). A documentation explanation, schema pass or content fingerprint does not itself grant authority.

Acceptance of an Artifact Type establishes its contract. A particular instance still needs its own standing. A relation permits only its listed endpoint pairs, and an ontology projection retains declared identities and connections. None of those steps supplies an additional permission source.
