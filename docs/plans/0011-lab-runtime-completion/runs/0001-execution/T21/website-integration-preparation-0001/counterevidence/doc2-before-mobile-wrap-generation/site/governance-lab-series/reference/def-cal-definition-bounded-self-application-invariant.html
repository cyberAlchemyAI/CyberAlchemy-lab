Bounded Self-Application Invariant

A governed process may be applied to its own outputs only when every recursive step identifies its scope, owner, review gate, carried state or residue, how results will be recombined, and a stopping condition.

When it applies
Use bounded recursive self-application when definitions-governance defines definition work, Craft records and routes work about Craft, CyberAlchemy applies its method to CyberAlchemy method artifacts, or a tower creates a higher-layer artifact that must explain back down to its source.

Source explanatory wording

The system can use its own method on its own work, but each loop needs a label, a boundary, a reviewer, and a way back.

Exact governing statement

Bounded Self-Application Invariant is the normalized invariant identified by semantic.bounded-self-application-invariant, owned within scope.shared-authority, and carried by type.invariant. Any canonical instance must preserve that classification and the accepted source relations to CAV2-D30 without silently merging it with another target.

Bound source-semantic basis:

Bounded recursive self-application is the CyberAlchemy v2 invariant that a governed process may be applied to artifacts produced by that same process only when each recursive step declares its artifact, altitude or layer, scope, owner, gate, carried state or residue, recomposition path, and stopping condition.

The recursive move must preserve authority boundaries: the process, the artifact being processed, the owner route, and the resulting authority posture must remain distinct unless an explicit promotion or coupling records otherwise.

Given a governed process `P`, an artifact `a_n` already produced, shaped, or
maintained by `P`, and an altitude marker `h_n`, a valid recursive
self-application step has the form:

```text
P_hn(a_n) -> a_(n+1) at h_(n+1)
```

The step is admissible only if it records:

- source artifact `a_n`
- target artifact `a_(n+1)`
- altitude or layer relation between `h_n` and `h_(n+1)`
- owner route
- gate or validation condition
- residue or state carried forward
- recomposition path back to the lower artifact or parent context
- stopping condition, budget, or explicit next owner

Without those fields, the move is ordinary recursion, self-hosting, looped work,
or open residue, not CyberAlchemy v2 recursivity.
  • Bounded recursive self-application is not ordinary code recursion, not generic self-hosting, not endless reflection, not child-folder nesting, not automatic promotion, and not a license to run agents recursively without a budget. It does not replace `CAV2-D17` reflection tower method or `CAV2-D20` Craft method; it governs when process-on-own-artifact moves are admissible across those and other methods.
