# Resume agent work

Rebuild a usable task context and check current permission before continuing.

<a id="resume-result"></a>

## Result and prerequisites

Recovering knowledge is part of continuation. So is current permission. Bring saved Project State, exact assignment, authority evidence, policies, view request and freshness rules before resuming an interrupted investigation.

Northstar view 3 expires at 10:10 UTC. Its 09:45–10:15 delegation might still be current. The expired information nevertheless prevents continued reliance on that context.

<a id="resume-pause"></a>

## 1. Pause and preserve permitted outputs

Record the unusable view and stopping point. Save only permitted outputs, preserving candidate standing and source references. Temporary notes leave project conclusions to the applicable recording and acceptance route.

Refreshing an active session’s views leaves its authority unchanged. If the session ends, the machine instance and working memory end too.

<a id="resume-reconstruct"></a>

## 2. Select durable project knowledge

For a later session, select saved Work, comparison, observations, assessment material, decisions and open questions. Obtain newly checked Context and Ontology Views under the applicable request, selection and freshness contracts.

The [view specimen](../reference/record-examples.md#example-context-view) identifies included material by selector and digest, states exclusions and expires. Valid JSON can still be unusable when sources or time conditions change.

<a id="resume-authority"></a>

## 3. Recheck the authority envelope

Read the current assignment and delegation separately. Check agent eligibility, scope, actions, policies, gates, period, revocation and budgets. At or after 10:15 UTC, the old grant supports no later action. A new session needs its applicable grant. Copying context transfers no permission.

[Assignment](../reference/record-examples.md#example-agent-assignment) records participation. [Delegation](../reference/record-examples.md#example-delegation) supplies a scoped grant only with its governing evidence established. Views and recollection supply no independent authority.

<a id="resume-session"></a>

## 4. Bind the continuation and its stop conditions

Prepare the session envelope with its instance, assignment, exact views, policies, authority, inputs, budgets and cursor. A new session needs a new ephemeral machine instance and its own working memory. The [specimen](../reference/record-examples.md#example-agent-session) shows required fields.

Pause again for expired or revoked permission, unusable views, exhausted budget or approval gates. Earlier session records stay as history. Its temporary memory is unavailable for silent resumption.

<a id="resume-output"></a>

## Expected output and next action

**Durable basis**

Exact saved evidence and candidate assessment, with cause, wider impact and recovery still unresolved.

**Task knowledge**

Newly checked views with sources, limits and usable freshness/expiry conditions.

**Permission**

Current scoped authority for the intended action; no inferred extension from the previous session.

**Continuation**

Applicable session envelope and stop conditions, with a new instance when starting a new session.

Common mistakes are treating an expired view as current, saved state as permission, a machine instance as durable private memory, or a surviving candidate assessment as accepted.
