Packages, installation and rollback

Select exact public bytes and protect host dependencies before changing an installation.

Draft prepared on 2026-10-14. Integration and final T21 qualification remain pending.

Choose the package boundary

A source package, a public export, an installed dependency/runtime and an activated consumer are different artifacts. The captured export and import implementations bind selected records/files and prepare bounded plans; they do not grant access to every source file or admit imported candidates.

Private credentials, policy/proof bodies, Session notes and protected host dependencies are not ordinary export material. Keep selected public source bytes, manifest/digest closure, original refs and intended scope explicit.

Check exact bytes and current effects

Before export/import, resolve the declared record revisions, source/ontology cuts, permitted targets, request/envelope keys, byte bounds and current channel. A valid package envelope without its exact payload/hash/reference closure is insufficient.

Materialization and installation must compare actual preimages and refuse unsafe paths, foreign files and changed selectors. Preserve the original signed/native source trail separately from generated files. A changed publisher destination or dependency family requires a reviewed successor selection; do not rename a stale manifest to make it current.

The R02 installer and release-readiness code own bounded development paths. The existing installation0004 supports this preparation's selected environment; its prior tests do not replace a fresh setup/upgrade/rollback witness for the final runtime.

Rollback and interruption

Keep the prior installation and exact rollback dependencies until the new version has its own readiness and end-to-end acceptance. Inspect uncertainty after interruption before cleanup. Remove only retained-approved owned temporary files; foreign/unknown residue is preserved.

For local state, cold replay verifies original commits and current source bytes. For derived files, verify their source cut, manifest, selected attachment and complete receipt rather than trusting a directory name. The publisher successor illustrates ordinary filesystem no-replace and receipt boundaries, with native mixed-target integration still separate.

Current blocker and next review

Changed API17 remains ineligible until new family/selector/software/source/profile closure is accepted. Its old metadata cannot qualify modified code. Family4's inherited mutable preparation inputs exposed a cycle; the retained diagnosis requires a distinct successor, not suppressed guards.

A later installation tutorial must select that final version, execute setup/recovery/rollback in fresh owned paths and record original effects/cleanup. None of those actions is run by this documentation generator. Read maintenance for the full integration sequence.
