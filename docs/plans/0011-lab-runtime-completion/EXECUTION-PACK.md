## Just-in-time validity and lapse policy

Source validity, credential validity and live Session duration are independent. The original Source8 source period is24h, the private reader grant is at most30min, and Session lifetime is at most900s; the strictest actual current deadline wins. T02 creates a new separately signed current diagnostic family and selector/producer bindings, while expired originals remain immutable negative evidence. Diagnostic success does not freeze that early short-lived family for an indefinitely delayed final run.

After assembly, T15 selects a distinct just-in-time final source family and freezes its exact code/source/profile/cut bindings. Measured complete qualification, installation and work duration, a declared margin and actual human pilot availability must fit the remaining absolute source window. Reader grants and live Sessions are separately and independently authorized immediately before each actual attempt, within the original duration limits. They do not alter a frozen source or extend an old interval. The maintained provisioner stages new per-run nonce/channel resources under the declared custody contract.

If a source, assignment, reader grant or Session lapses, stop that positive attempt and retain the refusal. A new signed source family with changed immutable rows requires a new source/profile freeze and affected source-bound qualification, even when code is unchanged. If the existing contract permits independently selected fresh private credential inputs under the same still-live source, bind those exact inputs in the new attempt without claiming the earlier resource continued. If it does not, create an explicitly versioned successor and requalify. An unavailable pilot owner or insufficient measured window is a scheduling stop, never permission to backdate, enlarge a lease or relabel expired proof.

Parallel work policy:

- Up to three independent workers plus the coordinator; each gets disjoint exact staged files and an owned run output prefix. Shared API service/protocol/source/profile changes have one coordinator who applies reviewed postimages in order.
- Workers never freeze or mutate another worker's output, a frozen predecessor, shared fixture clocks or live state. The coordinator checks source diffs, original AST obligations and full row coverage before merging.
- Start qualification only after T15 completes. A changed executable/schema/fixture/source/control binding invalidates affected descendants; create a new frozen revision and rerun the appropriate proof. Retain earlier failure evidence.
- Final review uses a fixed target/core digest, separately bound observations and a later real response envelope. No manifest embeds its own future hash. A schema that requires the unknown owner response inside its target cannot be solved by invented bytes.

Execution record per unit: selected scope/authority; exact input bindings and source cut; actual command or review; start/end, exit and terminal events; original/current test accounting; owned effect pre/post state; output digests; failures/counterevidence; accepted result and invalidation scope. Public reports exclude secrets; protected raw inputs remain in independently authorized custody.
