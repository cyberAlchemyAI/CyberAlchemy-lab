## Receipt prefix

The separately enrolled witness serializes a stable authority-domain/operation/root history key. Writer/channel/activation/challenge are current admission fences and never create a parallel history. Historical genesis scope and response bytes remain immutable. Every unfinished original operation is restart-fenced even if its local tree exactly matches the last confirmed prefix; fresh reconciliation must establish the exact prior effects, not merely supply permission.

A sequence persists exact intent/frame/core/basis, member transition/proposed state, member receipt, derived acknowledged state, original signed broker response, final entry and independent prefix confirmation. The entry selects earlier bytes. Neither member receipt nor response contains its own future entry hash. Stage acknowledgment is provisional until prefix confirmation; no further dispatch, stable export or wire success can observe it as committed. Terminal Ledger Outcome settlement is distinct from new effect work and never repeats Outcome or re-signs an existing response.

The current-host-facts protocol has a concrete fixed serving implementation, not merely a client. It reads selected original revocation/capacity/native custody evidence before and after signing each challenge-bound reply. Genuine decisions, protected source records, independent nonrollback storage and physically reserved capacity are installed host inputs. A signed adapter record alone is not evidence of native OS custody; actual deployment qualification must establish the selected originals and service invariants.

## Limits and tests

The receipt journal reserves sixteen sequence records plus one directory, and sixteen cleanup/reconciliation records plus one directory. Accepted Ledger and generation/pointer capacity remain separately selected. Retained failed bytes/inodes stay charged. Stage/member/sequence counts are checked prospectively; query disclosure consumes no mutation position. A declared byte ceiling alone is not a promise that a selected finite chunk plan fits all sequence or capacity budgets.

Tests use exclusive fixture roots, fixture issuers and actual bounded filesystem operations. They cannot select Actual posture. All candidate Python execution uses externally pinned sources, `-B -S`, a selected regular-file cache sentinel and a minimal environment. Offline Cargo uses exact selected archives, dependency source inventories and toolchain closure in this unit's own build root.

Conservative retained-object accounting charges every non-live payload-root top-level object, including immutable generations and the pointer, against the selected retained/orphan allowance. This is an additional restrictive resource rule, not a semantic orphan classification or deletion permission. The prospective generation plus pointer envelope is checked before publication; an allowance of one may refuse a commit before effects. Exact terminal cleanup/accounting uses its sixteen-record reserve and remains available when normal payload allowance is exhausted. Effectful completion/replay does not use that terminal exception.

The separately authorized UNKNOWN inspection route creates no writable Session or Stage and returns only an exact selected closed diagnostic original. A control-unverified result means the selected control high-water could not be verified; it does not identify every corrupted control byte or claim a complete current control inventory. Receipt inventory is a bounded observed digest when available, otherwise explicitly unavailable. Missing or corrupt confirmation and bounded inventory overflow do not establish absent consumption or recovery authority.

The fixed prefix service (`PrefixWitness::serve_one`) selects its role from the manager-authenticated current host profile and obtains the control high-water from the separately held concrete `ControlWitness`. It verifies receiving channel, recipient, writer lineage, exact receipt originals, physical root separation, finite witness capacity and the intersection of role, host facts, activation, revocation, capacity and request validity before a new CAS. This is the conservative interpretation in `coordinator-integration-contract-0002.json` (SHA256 `65ca74fe52e9bbb6572f87d16c0ec3b51c8cc7aa7d41d48643c62417a1a04c9d`). A durable CAS whose reply expires stays retained; a fresh inspection fetches the exact original without re-signing or another CAS. Historical fetch does not renew expired effect authority. Pending Ledger Outcome acknowledgement remains a separate exact settlement rule.

The dispatcher checks each derived target against the independently signed core's root, output slot, preimage and per-member limit, the signed core/permit total, and the selected broker limits. It checks the full managed-root retained inventory and independently selected physical reserve before replacements. A selected derived document's hash cannot enlarge those signed limits.

Completion-position accounting uses the actual immutable captured chunk size for the current and already admitted members. A core's maximum chunk size is only a bound for an unselected future member; it cannot make a selected smaller-chunk plan appear complete with fewer positions.

The unit-owned build harness uses a finite 64 MiB per-file physical limit for compiler/test processes, including their stdout/stderr files. Accepted log validation remains 16 MiB; exceeding that validation ceiling is a retained failure, not a smaller physical write cap. The earlier 16 MiB linker failure is preserved. Fixture-only bounded wall-clock delay hooks test expiration after durable CAS and after signing; they neither replace the clock nor exist in the production build.


The fixed static integration seam for U08-02 is a same-crate serving loop owning `Session`, the selected `Channel`, and the outer `Held`/root guards. `Session::serve_one` returns `Some(ColdRequest)` while retaining its pending sequence and commit. U08-owned statically linked transport validates that exact request and constructs opaque `commit::ColdObservation` through the accepted fixed transport constructor; `send_completed_cold` then validates current authority/control and sends only the independently confirmed original. `fail_cold(ColdFailure, elapsed_ms)` fences a failed transport without a committed reply. No serialized request chooses code, callback, or a replacement authority adapter. A new U08 executable must select its complete new glue/build closure; the frozen U02 binary is not silently changed.

Historical and current writer identities are distinct. Original native start/terminal/checkpoint bytes may attest a later independently selected writer at an unchanged physical control head. Verification joins the exact predecessor/head, original physical writer, authenticated historical fence, current fence, and any first successor writer; it does not require the physical row to have been rewritten. The P07 full native fixture advances the selected witness fence without changing that row, restarts read-only history, and performs separately authorized closing while preserving the original Outcome.
