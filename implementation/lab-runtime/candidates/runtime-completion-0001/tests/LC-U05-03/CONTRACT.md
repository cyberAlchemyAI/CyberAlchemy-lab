## Partial effects and cleanup

Resources are registered inside successful constructors before postguards. Primary,
secondary postguard and cleanup failures remain separate. A constructor that acts then
throws without returning ownership remains unknown; no invented release or retry.
Local ReaderChannel close, seen.clear and exact owned bridge detach are available
after positive expiry. Original guarded source/session/handler cleanup requires a
separate fresh cleanup-only decision; denial retains unknown resources and cannot
renew startup. Source exit receives (None,None,None). Foreign replacements remain.

All owned descriptor/socket teardown paths detach ownership, attempt every resource
once and retain sticky unknown on any ambiguous failure. They never retry a numeric
FD that may have been closed/reused. Existing primary exceptions survive rollback,
including interruptions; fixed uncertainty is observable without arbitrary exception
hooks. Read-finally, constructor rollback, transport admission, received rights and
explicit close use the same semantics. Fixture cleanup removes only its owned tree;
production endpoint attempts remain retained. No actual protected bytes, credentials,
services, authority, original task acceptance or runtime qualification are claimed.

Ordinary interruption during registered cleanup is delayed until remaining owned
resources and module teardown have each been attempted. An existing constructor
primary remains primary and the result records CLEANUP_INTERRUPTED/unknown; with
no earlier primary the interrupt is rethrown after cleanup. The adapter does not
claim resilience to arbitrarily repeated asynchronous interruption or kill -9.
