# LC-U03-02 contained process lifetime

This unit constructs the Rust supervisor and verifies bounded fixture mechanics. The mandatory positive setsid/reparented containment oracle is **NOT_RUN / BLOCKED**: no independently selected writable cgroup2 delegation or authenticated actual host custody is available. The unit is not eligible for acceptance from its fixture results. Nothing here grants host authority, starts a runtime service, provisions cgroups, signs credentials, releases a historical family, or changes the accepted control store.

## Admission and lifetime

The fixed parent supplies independently verified original full ByteBindings, exact root/ancestor/mount/namespace identities, store and slot epochs, historical family dispositions, distinct worker identity, execution and cleanup deadlines, and custody/currentness/worker-exclusion policy. These crate-private capabilities have no request-JSON constructor. The actual adapter must verify ACLs, all aliases and writable handles, worker inability to migrate/delegate/change namespaces/ptrace the supervisor, and immutable executable/cwd/input custody through dispatch. The local identity checks supplement that admission; they cannot establish it themselves.

`Root::create` uses a held cgroup2 domain root, no-follow openat2 and no-replace mkdir. It binds the exact new mount/inode and sets finite pids, memory and CPU limits before launch. It never adopts an existing subtree. A failed creation/configuration retains residue for quarantine; an empty existing group is not permission to reuse it.

`Prepared` verifies the original selected ELF bytes and full timestamp/identity stamp, closed argv/environment/stdio selection, and exact held working-directory identity plus original selection binding. It rechecks bytes/identities immediately before clone. Only selected immutable custody closes the remaining check-to-exec mutation interval; the actual host adapter must establish it. The child calls fchdir on the held selected directory before closing descriptors. There is no PATH, shell, script interpreter, ambient cwd or environment fallback. Dedicated regular stdin/stdout/stderr have pairwise distinct device/inode identity, owned single links and exact access flags. Input is at most64 MiB and its original bytes/digest, full timestamps, identity and offset are selected. Both outputs must be initially empty at offset0 with no append flag. All stream selection bytes are rechecked immediately before clone, including prepare→truncate/change/offset drift. The execution selection must bind any additional runtime libraries/configuration and the worker environment in the later actual integration.

`prepare` verifies journal/control continuity, finite future terminal/recovery capacity and exact known child-group inventory before creating a group. It returns a single-use `PendingStart` with original operation/fingerprint, root/group, executable plan, history, limits and separate deadlines. Unknown groups, even empty ones, fence admission and remain unadopted. The same inventory is checked after retention, immediately before acknowledgement and before clone.

The fixed `AttemptJournal` now owns original start/terminal/recovery persistence under a separately selected held evidence root, using no-follow exclusive files, file fsync and containing-directory fsync. It borrows the already held Journal-rank control lock and reopens the accepted Ledger under that capability; it does not acquire a new lock or modify the accepted store. Its header binds exact evidence and supervisor roots, authority/control domain and finite capacity. `HostAttemptCheckpoint` is a distinct exact journal predecessor/head and current control preimage. Only an independently enrolled host confirmer can authenticate and compare-and-advance it across competing writers. An existing Ledger HostConfirmation is never proof of an unrecorded supervisor start. The implementation checks the original selected checkpoint bytes and every join; actual authentication, continuity and exclusive reserve custody remain G01.

Only a fresh `PendingAdmission` can consume the newly prepared attempt and mint `StartAcknowledgment` after exact read-back and independent journal acknowledgement. There is no unsafe hash-only launch-ack constructor. Historical inspection/restart cannot reconstruct either launch capability. Death after acknowledgement but before clone is uncertain launch admission, never permission for a second producer. Fixture roots cannot dispatch or enter actual recovery. New-name or sync failure preserves partial originals and poisons the pending journal; reopening never bootstraps, resets or repairs it implicitly.

Production dispatch uses only clone3 with INTO_CGROUP, PIDFD and CLEAR_SIGHAND, with signals masked around creation. There is no fork-then-migrate fallback. All argv/environment memory and descriptor duplication are prepared in the parent. The child uses only bounded syscall setup: selected cwd, stdio/ELF/error descriptor remapping, close_range of every other descriptor, finite aggregate output allowance divided into equal hard per-stream file-size limits, selected UID/GID with empty supplementary groups, empty capabilities/ambient capabilities and no_new_privs. Credential changes use raw syscalls to avoid the multithreaded libc credential coordination path. Signal defaults precede unmasking. No allocation, logging, callbacks or Rust locks run before held-ELF execveat.

The exact READY marker proves descriptor/credential setup completed; it does not prove successful exec if a signal intervened. Missing/partial/duplicate markers or appended exec failure retain uncertainty. Natural child exit after READY establishes workload start; signal-only outcomes conservatively leave it unknown. The terminal records missing UTC end observation explicitly and retains monotonic elapsed time; it never substitutes the start time for a failed clock read.

## Cleanup and original outcomes

Direct-child wait/reap uses the held PIDFD. PID/start ticks are captured as evidence, not used to signal a numeric PID. Exact held cgroup attachment and namespace/custody are checked before cgroup.kill and populated observations. Cleanup covers the selected owned subtree, including reparented/setsid descendants. Direct-child exit alone is insufficient. This library neither enables a subreaper nor waits for foreign children; cgroup population and direct-child reaping are distinct observations. Zombie/adoption policy for a dedicated supervisor must be qualified by the actual host adapter.

Positive execution expiry stops workload admission. A separately preauthorized cleanup deadline/reserve allows bounded cleanup of the exact owned subtree without renewing execution authority. Expired cleanup authority, failed kill/read, changed attachment, unknown setup or missing reap remain explicit uncertainty/quarantine. Missing or unresolved historical dispositions fence positive admission and release, but do not substitute for or defeat a fresh exact cleanup-only grant. An unreaped child retains its PIDFD in the returned observation for the fixed parent's disposition; a dropped observation is not release proof.

Original terminal bytes bind the durable start receipt and full operation/control scope. They must be retained exactly and then appended as the selected original operation outcome through the accepted borrowed control-store capability. A pending checkpoint is not an acknowledgement: exact independent HostConfirmation is required. Cleanup truth does not choose Committed versus Aborted and does not clear a quarantined operation. Unknown outcome eligibility admits only Quarantined. Even acknowledged clean attempt cleanup never proves historical-family release; every original predecessor disposition and the accepted family's complete transition remain required.

The explicit cleanup-only root constructor validates physical/current custody and bounded selected history without requiring that historical obligations are complete. It cannot create/admit/launch a workload. Recovery observations report actual selected historical completeness independently of kill/empty/error status. The fixed restart loader verifies the complete independently acknowledged prefix through the selected original start, then joins fresh cleanup-only authority, original group identity and separately current intact control continuity. A later corrupt/orphan journal tail can leave this exact cleanup-only path available, while new appends and admissions remain quarantined. Unknown sibling groups remain untouched. The loader never adopts a group by name, emptiness or PID. Lost PIDFD/reaper information stays unknown: even observed empty cleanup produces only a separate `RecoveryObservation`, never a normal clean terminal or family release. New quarantine is appended once through the accepted Ledger and separately acknowledged; an existing outcome is preserved rather than overwritten or auto-reconciled. If the attempt journal cannot persist the observation, no new acknowledged cleanup is claimed.

Normal terminal writing retains exact bytes and obtains the attempt-journal checkpoint before appending the original operation Outcome. Accepted Ledger PendingCheckpoint/HostConfirmation acknowledgement remains a separate final requirement. The production path accepts an opaque retained-original proof, not a caller-supplied hash. The fixed adapters are implemented here; host authentication/custody and the positive contained-descendant oracle remain unavailable external qualification, not missing local persistence bodies.

## Bounds and validation

Limits are closed: 1–1024 PIDs, 1 MiB–16 GiB memory, CPU quota 1000–100000 microseconds per 100000 microseconds, 2 bytes–64 MiB aggregate stdout+stderr; each stream receives floor(total/2) as its hard RLIMIT_FSIZE slice, so their sum cannot exceed the selected total when admitted fresh-empty custody holds, workload 1–86400000 ms, cleanup 1–30000 ms. Kernel control reads are at most 4096 bytes; start records at most 65536; selected ELF at most 64 MiB; argv/environment at most 64 entries each and 32768 bytes combined. The supervisor has a finite wall/monotonic timeout and polls at 5 ms. Individual synchronous kernel syscalls remain subject to kernel behavior; the actual supervisor host needs an outer lifetime/containment policy. These are finite construction limits, not measured runtime performance.

Rust tests use an exclusively owned offline build and accepted immutable control-store dependency. Real pipe EOF and an owned inert child exercise descriptor closure and held cwd; those are not cgroup or credential qualification. An additional real owned child attempts oversized writes to both outputs and verifies EFBIG, both hard per-stream lengths and their aggregate sum. Tests cover exact family/scopes, strict kernel text parsing, deadline separation, clone flags, setup uncertainty, causal program/cwd mutation, original start/terminal binding, pending/wrong/lost control acknowledgements and quarantine retention. The actual host gate helper reports NOT_RUN with zero checks and no effect, so aggregation cannot turn missing host proof into PASS.

`build.py` requires external dependency/toolchain manifest hashes, verifies exact source/Cargo discovery closure and accepted predecessor bytes before and after Cargo, and keeps all logs/targets/vendor inputs under the unit evidence root. Python runs require `-B -S` and the independently selected regular-file PYTHONPYCACHEPREFIX sentinel. Negative source/config/checksum/tool substitutions refuse before Cargo. Failed development evidence is retained, including the four early epoch fixtures, the SIGXFSZ fixture-budget failure, and the initial O_PATH/nonblocking inventory regression retained in failed-fixture-retention-0003.json (which preserves0001/0002). Cleanup verifies their exact identities/bytes and rejects additional or changed residue.

Kernel references: [clone3](https://man7.org/linux/man-pages/man2/clone.2.html), [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html), [close_range](https://man7.org/linux/man-pages/man2/close_range.2.html).

`RecoveryObservation::original_bytes(&self)` exposes the bounded canonical original to the fixed caller before consuming persistence. It remains available when later journal residue prevents `PendingRecovery::retain`; a caller may retain it only in a separately selected evidence sink. The accessor does not write or print anything, authorize public disclosure, alter unknown/quarantine fields, acknowledge durability, or mint launch/release authority. A failed journal append leaves its original tail untouched. This permits honest reporting of exact cleanup observations without pretending the quarantined journal accepted them.

An independently authenticated control writer may advance while the durable control head stays unchanged. Historical attempt evidence retains its original HostConfirmation and independently selected HostAttemptCheckpoint; it does not rewrite the physical head's older writer. The fixed verifier first reopens the complete current Ledger, then joins the exact historical domain/root/header/head/predecessor and ordered physical-head writer, authenticated historical fence and independently current fence. Equal epochs require identical instances. A physical successor must also respect the historical fence. The historical fence comes from the original authenticated attempt checkpoint and its complete selected hash chain, never an arbitrary caller claim. Changing those originals without the selected checkpoint fails. A valid writer advance therefore preserves acknowledged-start reopen and exact cleanup-only lookup, while conflicting history stays quarantined. These checks create no new PendingAdmission or launch capability from restart. The physical host's authentic fencing remains an external requirement.
