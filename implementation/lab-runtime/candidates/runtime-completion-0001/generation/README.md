# Generation commit coordinator

This unit implements the fixed Rust generation/pointer state machine over the accepted held-root/member and control-ledger primitives. The first supported layout puts generations and the canonical pointer in one selected filesystem root, with a separate journal directory directly below the selected nonrollbackable control root. Original T32 native-engine qualification and actual host custody remain required; fixture success is not original task acceptance.

The authoritative pointer is the exact accepted C01 `lab-completion-pointer-record/v1` record. Its `generation_manifest_binding` resolves to original C01 `lab-completion-generation-manifest/v1` bytes in `c01-manifest.json`. The richer writer manifest in `manifest.json` retains native stage identity, full original cut, operation and inventory obligations. Its binding is separately carried by every phase, cold request and terminal receipt. Both originals are retained and the deterministic projection is checked exactly; a rich manifest cannot masquerade as a C01 pointer target.

`StoreSelection` is a versioned writer profile. `c01_store` projects it to the closed C01 store record; `c01_selection_binding` names those original bytes and is excluded from the projection, avoiding a self-digest. NamespaceCore selects that exact C01 store. A separately selected `RuntimeCommitSelection` binds the writer profile and the C01 original, current execution scope, exact operation/fingerprint, generation manifest and current commit authority. The profile cannot substitute for the independently selected C01 record. `ControlPolicy` contains only preactivation physical/control policy facts. Neither static record contains activation, review, current HostConfirmation or runtime scope. The causal fixture constructs store, core, review, activation, then runtime attachment in that order.

`ReplayExpectation` is a separately selected, pre-existing versioned original-cut mapping contract. Its `source_cut` is the original canonical reader identifier, and `original_cut_binding` identifies the exact richer cut. The independently reviewed selection asserts that those refer to the same original cut; the coordinator checks exact equality to both manifest forms. The string is not a digest alias and is never guessed from a path or hash. This contract also fixes member/reader inventories, exact adapter identities, cardinalities and expected native report bytes. It contains no future manifest, result or activation reference. A later cold result binds the final manifest and this original expectation, retaining the actual native report and process observation bytes separately.

Admission verifies the exact full control-policy binding, actual held control-root identity, journal ancestor/root policy, writer and authority domains, current independent HostConfirmation, runtime selection and acknowledged original operation reservation. Names alone do not establish a join. The accepted ledger validates its complete chain. Normal complete history reads every selected original and all eight phases. Restart also verifies an already committed history with its actual contiguous phase prefix (at least six), exact native/cold originals and original terminal against independently confirmed control history. Missing post-outcome phase or wrapper bytes remain missing. Repaired history is a distinct exact proof described below. All paths validate the contiguous canonical pointer predecessor chain and complete generation coverage; corrupt or unexplained residue blocks further writes. An older generation retains its original creation instance/epoch and operation; those historical facts are not rewritten to the current activation.

Publication uses the accepted no-replace immutable stage publication and exact durable original publication receipt. Pointer preparation creates an exclusive temporary file, verifies and fsyncs it and its directory. Activation compares original pointer bytes and named identity, renames, then fsyncs the parent. Rename before durable parent sync is COMMIT_UNCERTAIN. The cold verifier runs while all relevant locks stay held; its fixed interface borrows that context and never reenters pointer-selection/commit locks. The coordinator persists the exact cold originals, terminal and control outcome, then requires independent HostConfirmation before reporting a confirmed selection. A pending append, pointer presence or clean process alone is insufficient.

There is no automatic rollback, retry, garbage collection, timestamp-based newest selection or producer redispatch. Unknown commit/outcome state remains fenced. `confirmed_selection` returns verified identity only, not current disclosure permission. U08-02 must implement the separately current disclosure/read-selection check and separately selected isolated verifier transport. Previously selected immutable generations may be inspected under fresh disclosure without implying current writer authority.

## Fixed integration interfaces and limits

`Commit::begin_admitted`, `ControlAdmission::from_fixed_host` and `ColdObservation::from_fixed_transport` are crate-private fixed-loader seams, reachable by later statically linked modules without changing this file. Their unsafe constructors mark external provenance obligations; they do not turn caller-provided bytes into permission. U02-03 owns the fixed broker main/state/quota loader and current nonrollbackable control/authority/reserve integration. U08-02 owns fixed verifier supervision/transport and read selection. U02-04 owns actual G01 deployment and namespace/custody qualification. Fixture admissions/observations refuse actual domains; there is no fallback or callback executed under privileged broker credentials.

The actual loader must independently verify and retain original native records under authorized custody, selected adapter/code/dependency identities, complete inventory, current authority and an exclusive held filesystem capacity reservation covering journal, terminal and cleanup. `fstatvfs` is only a capacity observation; it does not reserve space. The verifier loader must establish separate process identity, confinement, original process/result/native bytes, timeout, exit and cleanup truth. Current source supplies closed validation and reachable seams, not those actual host providers. Later integration must not treat a fixture or a valid record signature as deployment proof.

All member, stage, journal, retained generation/orphan, inflight, result and timeout bounds are finite. General C01 bindings preserve exact Unicode scalar strings and signed-i64 size domain; narrower filesystem member names belong to the broker protocol only. Files and directory names are no-follow and exclusively owned. Every acknowledged phase file is fsynced with its parent; failure poisons the current object and retains residue. The fixture fault tests exercise real file/directory fsync errors and competing lock acquisition, but do not establish hardware power-loss behavior or native engine qualification.

## Restart and exact repair

`RestartInspection::inspect` is read-only and returns an opaque selected snapshot over the complete original journal inventory, held attachments, original operation/fingerprint, original source/reader/member selections and current control status. It creates no Stage, member producer, new event, or replacement pointer. Partial malformed originals refuse; original bytes remain retained. `ControlUnknown` exposes selected identities only: an on-disk tail under the old HostConfirmation cannot be adopted. Only a separately authenticated current host confirmation can reopen the accepted Ledger at that head. The module never reconstructs private PendingCheckpoint objects.

`already_committed` constructs a reproducible read-only HistoryProof from the exact original terminal, native report, process/cold originals, real phase prefix and current confirmed Ledger outcome. Missing phase7/8 or confirmed.json is not fabricated. It performs no new acknowledgment, event consumption or repair effect. Loss of this proof requires reinspection. Ordinary prior admission accepts an exact original terminal selection for this case, preserving every existing optional wrapper and validating it when present.

Effectful repair accepts only the original R02 actions: SealObservedNew maps to complete_commit; AbortOldCanonical maps to seal_outcome. `repair_subject` binds the exact operation, original inventory, current root/pointer/generation identities, entire retained root and journal inventories, current activation/control head, chosen action and selected verifier. `RecoveryAuthority::from_verified` requires the accepted exact Frame/VerifiedDispatch Recovery decision, original frame bytes and independently selected original binding. Current issuer/revocation/consumption inputs remain the fixed U02-03 host loader's duty before dispatch; the actual domain cannot use the fixture constructor. Fixed integration must reverify current authority and supervise revocation/deadlines throughout a bounded transaction, including before cold dispatch and terminal persistence. U08 validates exact attached scope, unchanged control head and interval at every effect boundary; it does not fabricate the external currentness source.

Broker periods are integer Unix seconds. RecoveryAuthority explicitly converts not_before and exclusive expires_at to UTC nanoseconds with checked multiplication and an i64 ceiling; overflow refuses, with no rounding or period widening. RuntimeCommitSelection already explicitly uses expires_utc_ns. The actual fixed admission loader must select that interval from original authority with the same exact containment rules. Cold durations remain selected milliseconds and are never compared as wall-clock epochs. Historical phase/creation epochs remain identities, not times.

RecoveryCommit exclusively creates and fsyncs immutable authority, subject and intent originals before the first repair effect. Existing same-permit intent is never redispatched. Observed-new sealing fsyncs only the exact existing generation and pointer/parent, then requires a fresh isolated cold observation. Its separate lab-generation-repair-cold-request/v1 profile contains a mandatory exact repair-intent binding; ordinary v1 canonical requests retain their original bytes without that field. Old/cross-intent result and process originals cannot satisfy a new invocation. Cold dispatch is once per live repair object; failure fences it. Old-pointer abort validates the exact old canonical state and retains all generation/stage/temp residue, without rollback or deletion.

A new immutable repair terminal is bound by the ORIGINAL operation Outcome when absent, or by Reconcile when its known outcome is Quarantined. Existing Committed/Aborted outcomes cannot be overwritten. Fresh independent HostConfirmation is required before HistoryProof. The repair branch needs no synthetic post-ack wrapper: after lost reply, exact terminal plus current independently confirmed Ledger history reproduces its closure. An unconfirmed tail stays UNKNOWN. Original journals and original consumed events remain unchanged.

PriorInventory separately selects canonical generations, directory/file orphans, normal original journals, repaired journals and retained interrupted repair branches. Interrupted branches may be retained only when their exact inventories were included in a later authorized repair intent whose original operation reached a verified outcome. Fresh repair does not reuse old permission; it binds the newly observed residue and control head. Unresolved or changed branches still fence admission. Subsequent commits reverify the entire distinct closure and predecessor relation under held locks. Read-only proofs carry identities only; they never grant consumer disclosure or new writer authority.

Successor0004 uses the explicitly versioned rich store profile `lab-generation-store/v2`. It adds selected `max_repair_record_bytes` (4096..1048576) and `journal_reserve_inodes` (46..65536). Original frozen v1 bytes and their exact C01 projections remain retained; v1 has no implicit repair budget, automatic migration or admission under v2. The authoritative C01 store/manifest/pointer and broker wire profiles are unchanged.

Ordinary originals bootstrap under the existing1MiB absolute ceiling and then use their own original store's selected `max_record_bytes`, including every guard reread and historical prior journal. A successor's narrower ordinary limit does not reinterpret older originals. There are at most23 named original journal records, so bootstrap capture is at most23MiB; after decode each also obeys its original selected limit. Repair subject/intent/request/terminal originals use the separately selected repair limit, with at most12 records and therefore12MiB absolute capture. Signed authority originals, cold result/process/native report protocols retain their independent64KiB ceilings (and any smaller selected result limit). Fixture authority originals obey the same64KiB read/write limit.

Before an ordinary journal mkdir, known initial canonical records must fit ordinary limits. A conservative nonpersisted size calculation separately serializes the full23-slot original binding inventory, current scope, predecessor pointer, full current journal inventory, worst valid C01 verifier/authority metadata, repair subject, intent, cold request and terminal. The largest record must fit the selected repair bound. Placeholder sizes/hashes in this calculation are never persisted or accepted as proof. Aggregate logical data reserve is at least `32*max_record_bytes + 12*max_repair_record_bytes`: the ordinary writer permits at most31 originals and conservatively reserves32 slots, the repair writer permits12 (the current complete branch uses eight), and both new directories add two inode slots, giving46 total. Accepted Ledger Outcome/Reconcile records use the Ledger's separate reserve; pointer temporary and generation-member allocation use the generation-root capacity contract. The fixed filesystem profile must additionally cover block rounding and filesystem metadata, not interpret these logical bytes as proof of physical reservation.

Physical journal admission counts every retained directory, including aborted and incomplete repair branches. The hard inventory bound is4096; an ordinary commit requires two free directory slots (commit plus its first repair), and repair begin requires one. This does not reserve unlimited retries. Actual fixed-host admission must supply an independently authenticated, still-held remaining byte/inode reservation bound to the exact current journal inventory, original control head, root and authority domain. Both commit and repair check it before their first mkdir. A retained failed branch changes the inventory even when the Ledger head stays unchanged, so its old capacity witness cannot fund another branch. Fresh selected remaining capacity or refusal is required; no deletion, automatic capacity renewal or `fstatvfs`-as-reservation claim exists. Fixture tests prove these joins using owned directories and inert selected capacity only; actual capacity custody remains a host gate.


Ordinary record admission uses the same typed phase, cold-request, terminal and confirmation serializers as persistence. Before the first journal directory, it checks every initial original, exact phase01, the later known phase03–08 predecessor/subject shapes, phase02's known base, the exact cold request, selected native/member original sizes, the known minimum cold-result envelope, and terminal/confirmation envelopes. Future local record bindings use the selected ordinary size ceiling and fixed digest width. Original C01 identifier domains and the selected4096-byte positive remain unchanged; separate repair capacity still applies.

A future publication receipt locator and cold transport receipt metadata are not selected at initial admission. Their complete bytes and associated phase record are checked together when returned, before Stage acknowledgment or any cold-original retention. Publication has already happened at that point: refusal leaves an inspectable Intent and owned orphan under the old canonical pointer, requiring fresh AbortOldCanonical authority. Oversized cold metadata after pointer activation leaves NewUnconfirmed and requires fresh intent-bound replay; these guards do not retroactively prevent earlier publication or activation. Terminal+phase07 are checked before terminal retention and Ledger Outcome append; confirmation+phase08 before Ledger acknowledgment. All final exact put limits remain enforced. This construction does not qualify actual host reserve or transport custody.
