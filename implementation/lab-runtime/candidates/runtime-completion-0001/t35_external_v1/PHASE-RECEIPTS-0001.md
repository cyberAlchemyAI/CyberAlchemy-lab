# Disposable phase core selection

`phase_receipts.py` selects a four-step source, reader, mapped, Context chain of ten core output bindings beneath a disposable external family. A temporary Ed25519 fixture issuer signs canonical phase receipts. Each selection binds the 30-leaf stage digest, a fresh per-ledger nonce, exact predecessor receipt digest, all required prior output rows, exact phase output paths, and T03-held output bytes. Before a new phase is selected, retained signed bytes and all prior output bytes are rechecked. Normal and optimized tests cover replay, wrong issuer/predecessor/family/path, output drift, internal row mutation, duplicate and nonfinite JSON, phase order, and persistent hardlink aliasing across two outputs.

The fixture public key is selected by the test caller, and the private key is generated within the scratch test. The core output files contain synthetic JSON, not a Source8 package, signed reader manifest, mapper result, or Context construction. The selected receipts have no owner slot, current protected period, installed T02 custody, or original engine signer. Pre/post single-link checks still cannot exclude a transient alias without exclusive writer custody. This proves only a candidate selection protocol; it cannot authorize production phase effects or qualify the nine runtime roles. Full historical builder execution and protected import/issuer closure remain internal and external work, respectively.
