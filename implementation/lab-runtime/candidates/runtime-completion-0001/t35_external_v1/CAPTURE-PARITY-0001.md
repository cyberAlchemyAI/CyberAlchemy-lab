# Disposable T03 capture parity revision

`capture_parity.py` loads exact frozen T03 capture and caller bytes at SHA-256 `eba3611c44fb76d89c7e741aac36ebcf52d3dc59786006af044d0ad98dc34962` and `4222b3ac165fa5ee8a9bed801290ffe42f63e69002ced521d4ac7e9e84bb7135` from a disposable snapshot. It exercises snapshot-relative input capture and all 30 selected absolute external-stage leaves through T03's held nofollow reader. The wrapper adds pre/post single-link and selected-callback checks. Tests cover wrong pins, unselected and aliased paths, persistent symlink/hardlink aliases, output and kernel/caller mutations, and normal/optimized modes.

This is an inactive disposable read calculation. The 30 stage rows are caller-supplied scratch selection, not authenticated phase receipts. A transient outside hardlink or same-digest inode replacement between the wrapper's pre/post checks and frozen T03's open can pass without exclusive writer custody. The wrapper cannot isolate its own trusted objects from an actor controlling the Python process. The production T03 hardener, trusted controller package/launch, signed source/reader/mapper/Context phase constructors, and protected host qualification remain unimplemented. No activation or writer capability is exposed.
