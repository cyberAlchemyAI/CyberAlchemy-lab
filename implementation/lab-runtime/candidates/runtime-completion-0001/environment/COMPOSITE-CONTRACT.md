# Complete selected environment adapter

`verify_environment` consumes the exact independently reviewed complete T08
reader/semantic successor before evaluating environment origins. Its versioned
result is `lab-composite-environment-adapter/v1`; the original descriptor remains
`lab-composite-install-environment/v3-candidate`. Original schemas and contracts
are unchanged. The test prerequisite verifies literal complete-T08 checkpoint
and independent review hashes before importing this consumer and again after
the run. That technical review is not a public request credential or host grant.

The caller independently selects full C01 descriptor/schema/original-descriptor
bindings, reader source/profile/cut, an exact legacy-locator-to-binding map and
the complete installed member origin map. Legacy two-field records never become
C01 bindings by themselves. The adapter compares the selected file ID, role,
full binding and original digest before reading. Missing, duplicate, ambiguous,
unused or cross-cut mappings refuse. The same selected reader/provider/root
domain performs every read; no ambient path resolver, plugin import or loader
fallback is available.

The exact original schema checks the whole descriptor, including unknown-field
refusal. `/R02_environment` is selected only by the original versioned selector
and compared with the unchanged original composite record's exact seven fields.
The original approximately27 MiB classification and complete source/profile
tables are read as whole metadata documents and compared without truncation,
deduplication or promotion to Artifact edges. Qualification and locator aliases
retain their original unresolved/empty values. All eight original module origins
must match the fixed original descriptor; module bytes are parsed and hashed,
never imported or executed.

The complete720-row execution declaration is checked separately from R02:
eight original wheels, interpreter, native executable,687 standard-library
members and23 ABI libraries. The exact native requirement, ordered ABI list,
original modes, explicit execution configuration, all ELF declarations and
original proof identities survive. The origin adapter reads every independently
selected installed member twice, hashes exact bytes, compares original wheel
archive membership without extraction and checks all declared ELF origins and
version dependencies. Unknown ELF requirements/search paths, absent transitive
libraries and ambiguous SONAME origins refuse. Selected bytes and source-control
bindings are checked again before return.

Original finite-number JSON semantics apply to original bodies; signed selection
controls retain the C01 integer domain. Public results expose bounded aggregate
counts/digests and fixed obligations, not protected body values, proof locators,
schema excerpts or chained errors. Internal original values remain available to
the comparison code and are not copied into the public composite result.

Byte-origin verification is not runtime qualification. The result explicitly
leaves actual custody/modes, loader relocation and symbol behavior, CPU/process
ABI, original proof member qualification and original task acceptance unresolved.
Alternate selected copies do not qualify historical original locators. Actual
protected input providers and installed lifecycle effects remain later gates;
fixture permission cannot select them. No installation root is created here.

The historical `execution_configuration` includes `-I -X utf8 -B -S` and is
preserved verbatim. Candidate tests instead use the selected regular-file
`PYTHONPYCACHEPREFIX` with `-B -S`, without `-I`/`-E`. `-B` alone does not prevent
unselected cached-bytecode loads, and `-I` ignores that environment variable.
A later installed invocation retaining `-I` must independently select and enforce
an equivalent source-loading policy, such as command-line
`-X pycache_prefix=<selected regular-file prefix>`, with exact file/root and
pre/post guards. This unit neither invents that installed path nor declares the
historical flag tuple sufficient; `installed_source_loading_policy_verified`
remains false.
