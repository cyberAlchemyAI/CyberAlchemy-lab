# Versioned owner-ingress verifier

This is LC-U09-01's executable **technical fixture** adapter. It verifies independent signed review/presentation/role/disposition/effect records against exact coordinator-selected original bytes. It does not collect a genuine human response, enroll an actual issuer, authorize an effect, publish anything, or close T33/T26. `verify_actual` refuses with `ACTUAL_G07_HOST_ROLE_REPLAY_PROVIDER_REQUIRED`; no fixture context or key can enable it.

The caller is a trusted coordinator which has already independently selected root identities, complete input/source closure and the literal expected enrollment and selection ByteBindings. These are separate from request data. `AnchoredReader` enforces exact bytes/root identity/no-follow reads. Choosing a matching digest from the same untrusted payload is not this interface's trust model. All source imports must use the accepted external pre-import guard, exact interpreter/dependency closure, `-B -S` and the regular-file cache prefix. This Python prototype makes no hostile same-UID isolation claim.

## Inputs and signature domain

`lab_owner.contracts` implements exact field sets, finite counts/bytes, scalar integer times and closed version identifiers. Signed envelopes have exactly `schema_version`, `issuer_ref`, `algorithm`, `payload`, `signature`. Version is `lab-owner-envelope/v2`; algorithm is exactly `Ed25519-lowerhex-canonical-v2`. Signature bytes are canonical UTF-8 JSON of the first four fields, with the envelope domain/version and algorithm included. The accepted LC-U01-02 codec supplies canonicalization and strict duplicate-key, negative-zero, noninteger and Unicode handling. Public keys are raw Ed25519 32 bytes encoded as 64 lowercase hexadecimal characters; signatures are raw 64 bytes encoded as 128 lowercase hexadecimal characters. Trailing newline/uppercase/base64/alternate algorithm is not autodetected.

This deliberately differs from original T33's `{issuer_ref,payload}` signing domain. The old key-adapter and host-channel base64 challenge proof remain separate original interfaces; neither is accepted here or silently reinterpreted. No signer or production credential loader is shipped. Test keys are deterministic, visibly synthetic and only instantiated within isolated owned fixtures.

`lab-owner-enrollment/v2` selects separate review, host, role and effect issuer entries outside all envelopes, an exact host mechanism, role registry/cursor, bounded freshness, original schema bindings, and the replay root identity. Host and role issuer identities and public keys must both differ. A new issuer key/alias/registry selection requires independent enrollment; payload fields cannot install one. Enrollment usage is closed to `technical-fixture`.

`lab-owner-selection/v2` independently selects the exact signed review, expected current ReviewCore, complete owner-scope input set, optional effect authorization, exact separate operator/release permissions, operation ID and disposition vocabulary profile. Stable `owner_id` identifies an independently scoped owner-matrix entry, so a human with several roles/scopes is not collapsed into one blanket authority. Required owner entries and target coverage must be complete and unique. Omitted or extra original bindings do not become approved by a valid signature on another object.

## Acyclic envelopes and original joins

1. `lab-owner-review-core/v2` binds selected source/profile/environment/base, exact target/member byte bindings and intended effects, a complete owner matrix, displayed material/evidence bindings, artifact meaning, limitations and explicit required operator/release permission kinds. It contains no future disposition/Decision digest.
2. `lab-owner-presentation/v2` is signed by the separately enrolled host. It binds authenticated principal/session, exact signed review and displayed materials, timestamp, host event and fresh nonce.
3. `lab-owner-role-attestation/v2` is signed by the independently enrolled role issuer. It binds original RoleAssignment, Role and AuthorityBoundary bytes, principal-to-assignee resolution, authoritative period interpretation and current revocation originals, exact registry cursor, scope and effect set. A key alone proves none of those meanings.
4. `lab-owner-disposition/v2` is signed by the selected host. It binds original message bytes, principal/session/event, exact review/presentation/role/material chain, scoped targets, operation and the unmodified outcome.
5. `lab-owner-effect-authorization/v2` is independently selected and signed by the effect issuer. It requires every exact selected disposition to be positive and complete, the current operation/review/target/effect set, a current period, and every separately required operator/release permission. Permission kind and exact target/operation/review/period are verified; omission, duplication, expiry or substitution refuses.

Original public schemas are selected from `authority/artifact-types/{role-assignment,role,authority-boundary}/v1/schema.json`; their original bytes remain unchanged. The verifier checks assignment.assignee_ref and role_ref, Role.node_id and authority_boundary, boundary node/owner role/accountable principal/scope, active lifecycle states, original assignment start/end, allowed and excluded effect kinds, current revocation and original period text. The signed role attestation selects the exact principal-assignee correspondence and original source basis. Team correspondence is not guessed from names or key possession. The original candidate-unadmitted status and authority_effect:none remain original data; a fixture validation never elevates those records into actual admitted authority.

The native boundary period can be an authoritative exact-text period resolution or `exact-review:<stable ReviewCore payload SHA256>`. The role authority independently resolves the former; this verifier never invents semantics by parsing an arbitrary prose period. The latter can be formed after the stable core without hashing a future disposition into it. Any original carrier that requires a future Decision inside its own purported stable semantic core still needs the T13 representation gate. Unsupported representation cannot be replaced with a synthetic Decision.

The full original role period must cover presentation, disposition and current verification; current revocation and registry cursor must also match. Historical provenance is not a current permission. Every captured original is byte-rechecked before returning verification. Reverify against freshly selected originals immediately before a future effect; a returned observation is not a reusable permit. Actual enrollment must independently establish the native records' authoritative state, source interpretation, principal correspondence, revocation and current time. This fixture module does not assert those facts for real records.

## Outcome vocabulary and replay

C07's original profile is approve/reject/revise/defer. T26's original profile is approve/reject/defer/stop. The versioned adapter retains the union as exact observed values and reports `profile_supported` plus `profile_status`. A `revise` observed under T26, or `stop` under C07, remains `unsupported-nonpositive-gated`; it is not normalized or used to close that original task. All nonpositive dispositions can be retained as observations/reservations and none can satisfy positive effect authorization. Chat text or a plan instruction is not a host attestation.

`reserve_fixture` recomputes verification before reserving. The externally selected mode-0700 root is opened through an anchored no-follow chain. Durable no-replace records separately reserve issuer/mechanism/host-event, presentation event and presentation nonce. Event identity excludes target, operation, principal and caller-selected store path. Repeating an event for another operation/target, replacing a root or reusing a nonce refuses. Multiple accountable owners require distinct events and all required positive dispositions.

Reservations include exact selection/review/enrollment and original input bindings; they persist after lost response, partial reservation, process failure or storage uncertainty. There is no overwrite, deletion, rollback-to-unused or automatic retry. Concurrent attempts have at most one successful reservation. A partial failure may retain a conservative subset; reconciliation must preserve that consumption. `reserved-no-effect` describes fixture custody only. The technical fixture's exclusively owned test directory is removed by its test harness after observations; this is not production replay retention.

## Actual integration gate and limits

The actual host functionality, authoritative role/assignee/currentness sources, independently custody-controlled authority-domain replay store and any operator/release issuer remain external G07/G01 integration prerequisites. LC-U09-02 can consume an accepted verifier interface in owner-response flows, while genuine final dispositions remain T26 and separately authorized effects remain T27–T30. That integration must select a reviewed actual provider, preserve original evidence in permitted custody, enforce host-event uniqueness across attempts/key rotation/store recovery, and recheck exact current authority before the effect. It must not rename this fixture enrollment/store/result as an actual provider. Missing prerequisites remain a refusal, not a generic PASS or a chat export.

`positive_effect_contract_verified` reports only that the selected **fixture** records satisfy the mathematical/structural conjunction. Every result also states `usage:technical-fixture`, `authority_effect:none` and `actual_effect_authorized:false`. Control envelopes/native schema records are bounded at 1 MiB before reading; opaque source/profile/environment/member originals are bounded at 64 MiB to accommodate the selected full manifests. Total capture is 256 MiB and at most 1,024 members; owner count is at most 64. Protected-input reads are refused without an actual separately selected provider. No content is exported automatically; exact originals remain in the selected custody. Tests and run evidence disclose only synthetic fixtures and public source selections.
