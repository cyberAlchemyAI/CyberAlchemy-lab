# C07 repository promotion and publication

Candidate implementation. Real canonical use requires the actual final R08 owner authority. Unit and recovery observations use signed temporary stores and isolated repository copies only.

## Selected bytes and independent effects

`prepare_promotion` captures a separately selected current repository baseline and independently replays an externally pinned local store. Only explicitly selected committed targets, their required contract/schema closure, original transaction SHA/JSON selectors, selected evidence and bounded prior state/history/generator inputs are exported. Unselected target bodies, whole local approvals, keys and private Session notes have no export path. Legacy record/schema bytes use the exact committed Python JSON postimage encoding; original precommit artifact bytes were not retained. No RFC 8785 implementation is claimed.

Each selected target gets a new repository Decision identity and stable independent core. Categories retain separate owner role bindings. The current baseline, exact predecessor, current carrier/schema selector, target bytes, selected evidence and semantic inspection are part of review. Generated Project State, paired histories, governance records and receipt digests are excluded from stable cores. Their deterministic generator is pinned by the reviewed executable profile. A single separately scoped repository response covers every core and the full review; a local signature cannot authorize it.

The candidate key adapter verifies an independently resolved repository public key and actor/owner-role scope. It records no human conversation outcome. An authenticated conversation response adapter and actual R08 role resolution remain C09/S02 integration obligations; those cannot be inferred from a caller's JSON or this candidate code.

Raw ArtifactType/v3 descriptors use the exact `registered_types/items` schema selector. Selected coeval Definition/type/schema/instance closure is staged before validation; an unselected local Definition cannot become repository meaning merely by being referenced by a selected type. Relation Kind promotion requires an exact C14 review bound to its identity, revision, question, axis and ordered pairs. The inspector does not issue a semantic owner verdict. Existing typed instance pairs and qualifiers remain closed; no wildcard connection is inferred. Selected new schema files require exact managed paths in the same review when physical repository files are needed. General registry dispatch/source-profile integration remains downstream; the generated selected-target index explicitly does not claim a complete repository catalog.

## Immutable commit and recoverable projections

`render_bundle` creates real schema-checked Decision, Decision Scope, Authority Boundary, Decision Bundle, Decision Checkpoint, Project State, paired histories, Generated Output, Admission Transaction and six deterministic Typed Relation postimages. Prior state/history bytes are retained. One immutable bundle contains all selected targets, validation inputs, independent cores, owner response, generated consequences and exact output receipt.

`publish` holds one repository writer lock and the local source's shared writer lock, rechecks the current baseline and exact export, writes/fsyncs a complete hidden stage and uses Linux `renameat2(RENAME_NOREPLACE)` to commit the directory. Owner authority is checked again immediately before the commit point. Existing destinations are cold-verified for same-request retry or rejected without overwrite. Unknown/incomplete stages are retained. No push, deployment, external publication or runtime activation occurs.

Managed mirrors are applied after commit. Only explicitly reviewed paths, exact committed source files and their expected preimages can be replaced; unexpected user bytes cause recovery-required. The generated current pointer is last and is a read lookup, never a replay source. A complete immutable transaction stays committed after mirror failure. `repair_publication` cold-verifies external review/manifest/authority pins, recomputes every consequence and repairs the same projections without another owner response. Expired execution permission cannot erase a committed response; recovery remains bounded by independently resolved adapter scope.

Cold verification and repair require the exact reviewed executable closure; changed generator files or added modules fail closed. Retaining/loading historical publisher packages is a later source-profile/runtime integration obligation. The candidate does not silently run the latest code against an older reviewed bundle.

All cooperating repository publisher writers must share this lock. Unknown writers modifying managed files outside the protocol can produce a conflict; they must be reconciled before repair. The implementation does not grant permission to overwrite them.
