# Typed extension validation

Status: candidate implementation. Every inspection has zero admission and registration effects.

The bound entry point consumes an independently pinned C04 snapshot. It resolves effective Relation Kinds and current endpoint carriers from that snapshot. Candidate evidence cannot replace its original canonical bytes; candidate endpoints cannot shadow admitted contracts or assert admission. An independent snapshot digest protects effective-state metadata as well as profile-byte bindings.

An extension retains the full predecessor connection set, names a distinct successor revision, and declares explicit ordered pairs. Reuse keeps exactly the same unique question and typed axis. A different semantic question requires a distinct kind. Source-kind and target-kind lists must equal pair projections; their Cartesian product creates no connection. Internal-record exceptions require explicit permission for the selected Relation Kind.

Every pair binds directional endpoint roles, a finite qualifier value domain and the exact enforced constraints. The inspector enumerates up to 10,000 domain combinations and applies all JSON Schema constraints. Open strings, numeric ranges, patterned property names, unresolved schema references and unconstrained arrays are rejected as value domains. Every individual evidence file is limited to 8 MiB and every proposal to 1,000 pairs. These are implementation experiment bounds, not admitted policy.

Generic Typed Relation or a specialized carrier is the single writable authority. Specialized canonical records require an exact digest-bound read-only Typed Relation projection. A second writable authority is rejected. Exact owner/contestability evidence covers kind, pair, qualifiers, both endpoints and relation instance.

No-collapse preparation compares the complete selected effective Relation Kind inventory, each exact existing revision and unique question, with hash-bound comparison evidence and substantive candidate reasoning. The program verifies the structure and bindings; it does not decide whether that reasoning is semantically correct. The actual owner reviews that reasoning at R08. A text token, PASS flag or forged owner-approved label supplies no semantic verdict.

Global and ontology-local scope remain separate. Candidate endpoint admissions remain explicitly pending. Structural review readiness does not create a pair, validate an instance, authorize an action or modify either registry. The evidence schema is a candidate inspection protocol; it does not replace Relation Kind/v2 or the existing typed-extension wire request. S01/API integration must resolve wire artifact references into exact proposal and evidence bytes before invoking this entry point.
