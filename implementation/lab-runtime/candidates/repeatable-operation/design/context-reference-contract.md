# Context references and ephemeral Session contract

Status: candidate read consumer. The consumer has no signing, dispatch, installation, persistence or admission methods.

## Reference closure

Every reference claimed as a governed subject resolves to one exact version in a verified Project State projection. Stable identity resolution requires a single effective admitted or locally admitted revision. An exact historical revision may be inspected with its historical posture. A string label, role name, unknown identity, wrong kind or ambiguous revision is an unresolved diagnostic. No label is silently substituted for an Agent Assignment or execution permission.

Session and Machine Agent handles are explicitly protocol identities, ephemeral and unadmitted. The package records supplied Assignment, Principal, Profile, Delegation and Implementation references separately. Even a resolved reference grants no action permission to this read consumer.

## Source, state and generator

The constructor requires the pinned read-only store adapter and an independently pinned C04 snapshot. Original source materials must match the store baseline. Selected sources, executable controls, configuration, committed HEAD and Project State are checked before consumption. Drift invalidates the Session and erases its memory. New contexts use new handles and new current verification.

Candidate package profile and executable manifest digests describe the generator package. A related admitted Implementation artifact retains its own exact revision. It is not renamed into the new package or treated as proof of its realization. Generator-to-Implementation realization remains a visible unresolved obligation until the exact binding is prepared and reviewed.

## Bounded views and ontology boundary

The context selection and repository graph view are disposable **protocol read models**. They are not new admitted Context View, Ontology View or Ontology Cut artifact instances. The graph is limited by declared depth, node and edge budgets and retains source-backed diagnostics, excluded paths and truncation.

The two Project history cursors remain Project cursors. No ontology semantic/governance cursor is invented, and the canonical Ontology Cut reference remains null. This corrects the frozen Session prototype's substitution of Project event references into generated ontology records. O02/O03 bind actual ontology events and governed view carriers. Until then, the consumer can explain verified repository state with that limitation and cannot claim ontology-native lifecycle execution.

## Memory and closure

Durable continuity is exact Project State and source-backed Context/Ontology Views. Short memory belongs to one Session, is bounded to 100 notes, 10,000 UTF-8 bytes per note and 1 MiB total, and is never included in returned context or written to disk by this consumer. Closing, TTL expiry, changed sources, changed executable, changed configuration, or changed committed HEAD erases memory and drops the prepared pack. A later Session starts empty and reconstructs context from fresh verified state.

The candidate API must label the protocol view boundary honestly. It cannot serialize these protocol views as governed carrier instances to satisfy a stronger API contract. C09/S01 integrate the read protocol; O02/O03 own ontology-native closure and actual governed view production.
