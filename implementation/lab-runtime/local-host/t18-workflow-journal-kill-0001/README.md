# Workflow journal process interruption probe

Run `python3 -B implementation/lab-runtime/local-host/t18-workflow-journal-kill-0001/run.py` from the repository root. The runner pins the API43 source-manifest SHA-256 and executes its exact selected `workflow_output_journal.py` member bytes. The child checks the same binding and compiles captured journal bytes. It also pins and compiles captured package, kernel and fixture bytes to create an exact isolated transition plan. The fixture's host guard is a checkpoint callback, so this probe tests the journal component rather than authenticated Service permission.

Two fresh owned `/tmp` journals receive actual process-group `SIGKILL`: one after the durable claim and before transaction creation, and one after the durable transaction and before HEAD replacement. A fresh journal instance cold-replays each. The claim-only case refuses redispatch and refuses recovery without an observed transaction for its exact expected reason. The transaction case recovers to sequence 1 and exact retry preserves transaction bytes. Both reject changed-request reuse of the same idempotency key for its exact expected reason, retain exactly one claim and at most one transaction, and preserve an unrelated sibling file. Normal and optimized Python runs passed; `RESULT.json` is the final normal-mode receipt.

This is a bounded T18 recovery slice. It does not execute the API Service/Vault claim and finish, the actual producer or private grant, and it does not simulate host power loss. T18 remains open for those integration, authentication, hostile-input and transport checks.
