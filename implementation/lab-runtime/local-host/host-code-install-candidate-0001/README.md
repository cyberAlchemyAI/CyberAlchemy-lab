# Inactive WSL storage-code installation envelope 0001

This candidate does **not** install code. `verify.py --apply` exits 3 before host reads or writes. `--plan` verifies the current disabled storage release's exact bytes with `O_NOATIME|O_NOFOLLOW`, then inspects held nofollow `/usr/local/libexec` ancestry, ACL xattrs, and absence of the proposed package name. The source hash is `dcbf8d6c8ddad7f77a2f55ba6f95a77f5936456853cb8145b517ef3e22ff53c4`. The source is an inspection baseline only: `LIVE_RELEASE_ENABLED=False`, so **do not install this copy**. Installing it would require a second code replacement before storage creation and would undermine the clean one-shot effect envelope.

The [proposed write manifest](write-manifest.json) separates two future root-owned entries from the seven storage entries: a `root:root 0700` package directory under `/usr/local/libexec`, followed by an exact `root:root 0500` active-successor script, created exclusively through held directory descriptors. The first package name consumes the attempt. Each new inode and its parent must be fsynced. A failed or uncertain attempt is retained for investigation; no overwrite, retry, or rollback deletion is selected. The active successor must be frozen and independently reviewed before its bytes replace the source baseline in a new manifest. It must not execute source from this user-writable checkout as root. An installed postimage needs a second independent hash and inode/owner/mode check after the installer exits.

This is not yet an exact live installer. The current release's live gate, Python interpreter/import closure, `pwd`/`grp` NSS lookups, read-atime and cache/socket effects, final linked-tree inode check, and WSL post-effect service-UID oracle remain open. On this host `/etc/nsswitch.conf` routes passwd and group through `files systemd`, and `/run/systemd/userdb/io.systemd.DynamicUser` exists. One unprivileged `release.py --plan` run changed none of the observed access-time nanoseconds for `/etc/passwd`, `/etc/group`, `/etc/nsswitch.conf`, `/etc/subuid`, or `/etc/subgid`; relatime and current atimes make that a point observation only. `verify.py`'s own source read preserves an artificially old source atime in tests. Python root execution should use an independently pinned interpreter and import closure, with bytecode writing disabled, after exact review. A Docker host-bind route is not a shortcut: it adds daemon, image, mount, UID mapping, and host parent effects without establishing the WSL host's root-owned installed executable.

The shortest safe effect path is to repair and independently review one **active** storage-release successor, freeze its full code and interpreter preimage, replace NSS-dependent checks with bounded direct held reads or explicitly account for their auxiliary effects, and extend the final postimage check to the entire linked tree. Then review one exact root-owned code-install transaction for that successor, execute it once as administrator, independently verify installed bytes and owner/mode/inode, and invoke its selected storage one-shot with a separate WSL post-effect oracle. Neither current candidate is an approval for those effects. UID 20001 remains a proposal, not allocated service custody; G01/G02 and original T02/T35 remain open.
