## R01 — evidence and log pathname custody is not closed

`exclusive()` uses `O_EXCL|O_NOFOLLOW` only on the final leaf, then opens `path.parent` by pathname for fsync. A public temporary probe passed a symlinked parent and observed the marker written in the symlink target. `run()` checks the evidence directory before launch but holds no ancestor or evidence-dir FD across marker, CID, pre-removal and terminal writes, so a same-UID rename/swap between checks can redirect those artifacts. More directly, `capture_start()` reopens pre-created stdout/stderr paths with `Path.open('ab')`, which follows a replaced **leaf** symlink. In a public local-child probe, the stdout path was a symlink to another temporary file; the controller appended the child's bytes to that file and returned `(0, False)`. These are unbounded write-target changes, not just a missing provenance field. Use held nofollow evidence/output parent FDs, verify leaf identities/modes on each reopen, and add source/destination ancestor and log-leaf swap negatives before effect.

The Docker bind sources are also passed as host path strings after a point-in-time `frozen_inputs()` check. The controller compares root/tool inode pairs after the run, but it does not hold and reattach all mount-source ancestors immediately around `docker create`; a changed-and-restored same-UID path can evade that postclose pair comparison. The selected 986-file hashes and Reader wrapper are valuable guards, but they do not independently prove which host directory Docker mounted at create time. A future release needs mount-source custody and exact pre/post attachment evidence.

## R02 — final signal and period decision can precede publication

`period_current()` runs inside the provisional PASS branch, before `result.update(... overall='PASS')`, signal-mask setup, pending-signal check and durable terminal write. The clock can cross the exclusive expiry during that interval without a second period check. Likewise the controller checks `STOP_REQUESTED` and pending signals once, then writes the terminal while signals remain blocked. A synthetic fake-daemon probe set `STOP_REQUESTED=True` at terminal `exclusive()` entry, after the final check; `run()` returned PASS and the on-disk terminal was PASS. An actual SIGTERM arriving during the blocked terminal write would become pending only after the check. Define the commit boundary and recheck stop/pending signal and period at the last valid point before publishing PASS; test expiry and signal arrival around the terminal fsync. A provisional PASS object must not become a false final PASS.

## R03 — several purportedly bounded captures read before limiting

`output_inventory()` calls `receipt.json.read_bytes()` before enforcing its 1 MiB cap. Final stdout/stderr digests and the PASS parser call `read_bytes()` on log paths, relying on earlier capture limits even though the paths are mutable. `cli()` uses `subprocess.run(... stdout=PIPE, stderr=PIPE)` without an output cap for create/inspect/wait/stop/rm; `inspected()` parses full stdout without a size limit. A damaged daemon response or same-UID pathname substitution can therefore exhaust controller memory before the failure is classified. Use descriptor-bound regular-file reads with limits plus one-byte overflow detection, and bounded streaming capture for every Docker CLI command. The `capture_start()` stream loop itself enforces a 4 MiB persisted limit per stream in the local probe, but its log-open issue in R01 remains.

The fake lifecycle does show useful behavior: the consumed marker is written before create; lost create/client responses remain UNKNOWN/no-retry; an owned name/image/nonce/CID is checked before stop/kill/rm; a pre-removal receipt precedes rm; lost rm leaves recovery cleanup-only; changed postclose inputs and overflow do not PASS. `inspected()` accepts only the selected full `No such object/container: NAME` diagnostic: independent fake responses with a substring or a different name were refused. Two such diagnostics are a bounded daemon observation, not an independent proof against a daemon that repeatedly reports stale absence. A real effect still requires image/host UID/mount qualification, the staged private archive hash and exact 986-file inventory, a released Reader entrypoint, and a final cleanup/terminal audit. This candidate grants no Reader, Mapper, Context, protected Source8, host or original-plan acceptance.
