## Findings and claim ceiling

1. **Docker API admission remains the controlling authority.** A named local volume and `flock` do not enforce one writer against another Docker-capable client. The RW counterexample proves this. This host exposes `/var/run/docker.sock` as `root:docker` mode `0660`, and the current `vlad_` account is in `docker`; that observation does not establish an exclusive daemon-client roster or policy for a future family. The probe did not challenge another RW mount during the live gap, because its grant would itself breach the proposed control-plane assumption. A protected activation needs a held and auditable Docker admission boundary for the entire family lifetime, including cleanup and slot handoff.
2. **The probe is not the producer interface implementation.** `SLOT-INTERFACE.json` requires a separately selected owner slot release, current signed Source manifest, reviewer permit, grants, runtime image, immutable input mounts, current period and output/terminal receipts. These fields are placeholders here. The synthetic writer neither adapts T35's repository-relative code to `/lab` nor performs Source, Reader, Mapper or Context effects. Its `flock` runs from before synthetic `mkdir` until writer completion, while the stated future interface requires continuity from selection through signing, effect and terminal disposition. An advisory lock alone does not bar a second RW writer.
3. **Namespace identity witnesses are conditional on the daemon.** The fresh name, labels, `CreatedAt`, marker and dev/inode observations detect ordinary swaps in the probe, but are not a cryptographic volume identity or independent control-plane attestation. `inspect_container` checks mount type/name/RW and selected limits, but does not itself verify the selected container image ID, entrypoint or command. The run command supplies the pinned image and code; that suffices for the disposable test under a trusted daemon, not for hostile Docker API access. A production receipt must bind the exact deployed image, command, mount list, writer CID, held descriptors and final linked tree under an independently governed daemon policy.
4. **T02/T35 evidence is absent.** The historical a/b slot release, separately authorized and signed current Source8-equivalent family, protected issuer/grants, actual UTC period, T35 phase ledger and original whole-route acceptance have not been produced by this probe. The original expired family remains negative evidence. The scratch test and its cleanup do not alter original task status.

The successful cleanup claim is limited to the run's labeled Docker objects. Docker logs, image/cache state, journal entries and filesystem access-time effects were not audited.
