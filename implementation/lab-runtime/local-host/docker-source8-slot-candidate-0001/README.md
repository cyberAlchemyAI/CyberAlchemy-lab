# Docker-native Source8 slot boundary candidate 0001

This candidate tests an exclusive **container writer context**, not an authorized Source8 family. It uses a fresh Docker `local` named volume and never binds a host directory. A stopped, read-only keeper container holds a reference to the volume between creation and cleanup. A short-lived root initializer creates a public identity marker and a UID/GID 20001 `0700` instances directory. One UID/GID 20001 writer container holds a slot `flock`, creates a fresh child, pauses between `mkdir` and first open, then checks the same inode and writes one synthetic public JSON record. Network, capabilities, privilege escalation and image-root writes are disabled for that writer; no Docker socket enters it.

The adversarial probe runs two separate same-UID containers during the live gap. With the volume mounted read-only, rename and sibling creation both fail with `EROFS` (errno 30). With no volume mounted, both fail with `ENOENT` (errno 2). After the writer exits, a deliberately granted **read-write** mount lets the same UID create a sibling. This counterexample is part of the result: Docker's local volume driver does not enforce single-writer access. Exclusivity is conditional on the Docker control plane withholding all other read-write mounts for the full family lifetime. On this host `/var/run/docker.sock` was observed as root:docker `0660`; that point-in-time permission is not a global daemon-client census.

The producer-facing [SLOT-INTERFACE.json](SLOT-INTERFACE.json) specifies the intended volume, writer, lock, input-mount and output-path witnesses. Actual Source8 Source/Reader/Mapper/Context issuers, current periods, historical a/b slot disposition and reviewer permit must be supplied independently. The probe image contains only a synthetic writer, not T35. It does not adapt T35's current repository-relative paths or issue authority for a protected input. Future protected inputs must come from a separate custodian-staged read-only volume; credentials must never appear in Docker arguments, environment, labels or logs.

`/usr/bin/python3.14 -I -B -S run_probe.py --plan` is read-only. `--run-disposable` creates only nonce-labeled probe resources, verifies the exact synthetic volume inventory and independent readback, removes the owned containers/volume, and verifies their absence. The source hashes and image ID are pinned in `manifest.json`. `test-result.json` and `test-result-7e0aec5188ebe76e.json` retain public test observations; all associated Docker resources were removed. Two earlier failed initializer attempts were independently inspected as synthetic-only and cleaned before the successful run. Daemon logs, cache, journal and filesystem access-time effects are outside the object-cleanup claim.

**Claim ceiling:** disposable Docker mount/UID/lock mechanics under a trusted Docker control plane. No installed continuing writer, protected Source8 family, independent issuer/grant, actual Root/slot decision, T02 acceptance, or G01/G02 qualification follows.
