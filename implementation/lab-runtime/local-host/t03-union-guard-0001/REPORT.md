# T03 repeated verification experiment, 2026-10-22

The selected local API33 Context preflight repeatedly verifies overlapping Source, Reader, Mapper, and Context inputs. A profile of one actual `Context.control.verify_source` call found 8 `source.base.verify_inputs` calls, 8 `capture.verify_all` calls, 9,387 `capture.Batch.read` calls, and 10,912 hash updates. That profiled call took 11.902 seconds, with 10.508 seconds inside the repeated input verification calls. It explains a material part of the long live Session setup, but it is not a complete profile of the 226.5-second API33 method or the full test class.

The four selected manifests have 5,139 file rows and 1,934 distinct manifest paths with no conflicting pins. The candidate adds eight distinct proof paths from the selected chain/phase/package pins, producing a 1,942-path union. It verifies those 1,942 paths once at entry and once at exit with the selected fd-anchored Source capture implementation. It never accepts a cached byte hash from an earlier operation. It also checks the selected Source period at entry and exit. This preserves byte-closure detection at both boundaries for this candidate; it does not preserve every semantic check made by the nested production guards.

In the final code-bound [measurement](MEASUREMENT-0003.json), one selected Context preflight took 12.500 seconds. Three candidate union boundary passes took 1.381, 1.960, and 1.695 seconds (median 1.695 seconds); an additional entry/exit window passed. The approximate 7.4:1 ratio compares unequal operations: a full Context preflight versus the candidate's byte-closure boundary. It is an opportunity estimate, **not** a measured API33 speedup. Machine load and cache state can affect both timings; two earlier versioned measurements also recorded 12.777/1.588 and 13.516/2.048 seconds, respectively, but bind earlier candidate code.

Twelve focused tests pass normally and under `-O`. The six union tests cover the actual selected-family union, a modified native chain receipt, conflicting path pins, wrong file hashes, symlink refusal, mutation at exit, Source expiry before entry and after the body, and preserving both a caller exception and an exit-integrity exception. Six additional [composition tests](test_compose.py) use the actual selected capture primitive and transient cryptographic test key to verify that source, signed-package, policy, and lease callbacks run once at each boundary; a wrong signature refuses entry, revoked policy and expired lease refuse exit, changed bytes and a body error both survive, and source expiry refuses entry/exit. These callback tests are synthetic policy/lease controls, not a real API33 authenticated Session. The selected-family positive depends on its live Source period and should fail after that period expires. The probe leaves the selected family, private archive, and API33 package unchanged.

The native call graph gives an exact blocker to transparent acceleration:

| Original guard | Repeated work that cannot be dropped by an external wrapper |
| --- | --- |
| `source.base.verify_source` | Hashes the Source manifest inputs and checks environment/posture. |
| `reader.reader.SelectedReader.guard` | Hashes the Reader inputs, checks producer/package pins, then calls Source verification. |
| `mapped.base.verify_source` / `mapped.build.guard` | Hashes Mapper inputs, checks environment and links, then calls Reader guard/package and native executable digest. |
| `context.base.preflight` | Hashes Context inputs, checks external selection/environment, then calls Mapper guard and exact API profile/package bindings. |
| `reader.adapter.SignedSources.guard` | Calls source package verification, signed view/transaction guard, selected archive/replay inputs, cut, projection, and freshness checks. |
| API33 `fact-read-scope-v2.read_scope` | Runs original source and package callbacks at entry/exit, with actual policy/clock/revocation checks on the original channel; copied facts are scoped to synchronous pure work. |

The [conformance composition](compose.py) preserves four original callback categories alongside the union check. It necessarily repeats byte hashing inside those originals, and therefore has **no measured speedup**. It is not safe to select it as an API33 replacement based on these tests: it has no closed native-object origin binding and does not prove callback-order equivalence with the current `fact-read-scope-v2` under every failure path. The real selected family cannot be modified in place to introduce semantic-only callbacks; doing so would invalidate its pinned source manifests and chain receipt.

**Integration decision:** stop this candidate without production edits. A versioned native-family successor must factor the Source/Reader/Mapper/Context guards into a pure byte closure and separately callable semantic/package checks while preserving their current assertions, callback identity, private archive and signed replay checks. Only then can an API successor select those exact native objects, run union verification at both boundaries, run unchanged live policy/lease checks at their current call sites, and compare callback counts and failure order with the original scope. It must pass real API33 whole-class runs plus mutation, stale-period, package-tamper, wrong-signature, role-policy/revocation, lease-expiry, and exit-race negatives, followed by independent review. Until then, this is a measured disjoint candidate, not T03 or API33 acceleration completion.
