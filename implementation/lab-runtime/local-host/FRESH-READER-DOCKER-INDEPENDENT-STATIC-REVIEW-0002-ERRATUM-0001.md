**Corrected verdict: PASS for inert selection, held-parent copy mechanics, direct effect gates and the 986-file arithmetic; HOLD for enabling a private copy or Reader effect.** The design 0003 and candidate 0002 remain unchanged. All 22 freeze bindings matched at review, normal and `-O` inert tests passed 14/14, and the fresh Reader attempt path remained absent. No archive body was opened or copied; no Reader or Docker effect occurred.

An independent synthetic fault probe found an actual integrity gap in `anchored_copy.copy_exact`: it hashes bytes read from the source before writing, but checks only destination size, mode and identity, without hashing destination bytes. In a temporary public fixture I changed one byte in the `os.write` call while preserving its length. `copy_exact` returned successfully with the expected source digest, yet the destination differed from the source. This demonstrates that the current primitive cannot certify its own output bytes under a silent write/storage fault. Add a nofollow, held-parent destination readback by descriptor, compare its SHA-256 and exact size against the selected digest, and retain a negative corruption regression. The destination open is currently write-only, so the implementation needs an explicit safe readback path. An effect controller must also validate the final 986-file stage immediately before and after Reader use; the current reattachment checks end when the copy returns.

The future release still requires durable no-retry controller/evidence semantics, finite Docker lifecycle and cleanup, current archive digest in the separate private stage, period expiry injected during cold-open and before terminal PASS, and selected mount/image/UID feasibility. The corrected mode finding does not waive those boundaries. The active candidate remains effect-disabled at `stage()`, `selected()` and `run()`.
