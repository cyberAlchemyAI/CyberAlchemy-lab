## Portable installation contract

The existing T19 archive runs only the fixture journeys. T25 installer0003
adds the seven-file `lab.status` dependency guard and explicitly does not
execute the full original API Service. These are reusable installer and
archive-safety components, not the final product installation.

Use two explicit layers:

- A stable public code/artifact/data/ABI closure with canonical relative member
  names, sizes, modes and hashes. Keep the selected 1,010 native payload bytes
  exact. Freeze mutable repository inputs as package data and inventory all
  historical IDs separately. Retain authentic fixture-only Source semantics.
- A generated private installation binding: actual absolute root, owner/mode,
  device/inode, native receipt and selected Context role. Generate and verify
  this after provisioning each root. Select it through a closed trusted
  bootstrap; no caller wire field can choose roots, source pins or issuers.

Each installation must receive its own actual native role attestation.
Copying an old inode receipt, manufacturing a `/tmp` alias or treating a new
path as proof of old host identity is invalid. If the existing Source manifest
still includes the host role/locator, produce a genuinely fresh per-install
Source/Context binding and disclose that variation. Stable public package and
artifact bytes must still agree; do not claim identical per-host Source
profile bytes. A better stable contract separates the independently selected
host proof from artifact/domain meaning.

Inventory absolute paths before recutting: repository root/source origins,
private archive locations, current role and native receipt, historical host
dependencies and deliberately denied external paths have different purposes.
Keep required exact checks; replace host-specific selection with explicit
bootstrap bindings. Rebuild the schema execution dependency selection from
the complete observed transitive read/import closure for all34 operations
and required negatives. Keep mandatory historical schema anchors and
inherited refusal semantics. Do not drop a dependency merely because one
happy path does not read it, or package mutable host/system files by accident.

Use checked staging, exclusive publication and exact replay manifests. An
interruption may leave a clearly owned incomplete stage, not a successful
installation. Cleanup is scoped to recorded owned resources. Test the final
loader in two independent roots and a restore root before claiming portability.

## Evidence invalidation

Every receipt binds the selected source/profile, software, data, ABI and
runner. Changing an input invalidates affected checks. A runtime/schema/data
change after qualification requires a fresh coherent cut and affected reruns;
an installer-only change needs its own installer/component and installed
product checks. Historical passing receipts remain history. No task advances
by summing unrelated branch receipts or by changing status labels alone.
