# Persist native workflow scopes without retagging outputs

The Project that authorizes a WorkflowRun can differ from an ontology output's native container scope. This explicit private profile retains the actual ArtifactRef and original body scopes. It checks their independently selected correspondence during staging, every guarded effect boundary, cold replay, recovery and later currentness resolution.

`scoped_store.py` wraps the unchanged original journal and carrier validators. The host first initializes that journal and its private `outputs` directory, then persists an exact private evidence index. `ScopeSelection.from_host(index_path, index_sha256)` captures its independent binding; `ScopedOutputJournal(root, config_sha256, scope_selection=selection)` refuses missing or changed evidence. The inherited initializer is deliberately unavailable because it cannot supply that independent scope selection.

The closed index has schema `lab-owned-native-scope-index/v1`, journal config, Project scope, Run, authenticated Actor, Work, Source cut, private original members and exact output entries. Each entry binds a contract, captured scope proof, invocation lineage and actual producer receipt. Explicit JSON selectors must find the same header, proof and lineage in those selected original receipt bytes. All private files must be owned, single-link, bounded regular files with mode 0600; links, substitutions, duplicate or extra members refuse.

The separate `scope-contract.schema.json` is an owned-profile successor. The older native contract permits only `NativeMixedPublisher.capture_selected`; it cannot honestly describe ontology hydration. The new contract permits that exact entrypoint and `OntologyTypedCapture.produce`, still requiring the exact public producer file bytes. The body scope must be explicitly permitted, the container scope must equal the unchanged header, and the authority scope must equal the Project. Actor, Work, Source and the producing Run preimage must close against the actual journal event and original next-run bytes.

`scoped_currentness.py` preserves the owned-output resolver's committed HEAD, transaction, producer-original, retirement and exit checks while selecting this store. `scoped_headers.py` and `scoped_kernel.py` are explicit new private variants. The kernel replaces only the same-Project header predicate with a verified scope-correspondence predicate; its other plan predicates remain identical. Neither the original source-current kernel nor the earlier owned profile is changed.

The host remains responsible for selecting evidence from a real observed producer, validating domain semantics, and supplying current independent permission and Source guards. Private hashes and a success field alone cannot establish that execution occurred. A new scope observation wrapping an actual capture must retain the original capture receipt and identify the distinction honestly. This component provides no admission, owner outcome, runtime Session continuation or Work completion.

Run `python3 -B -m unittest discover -s implementation/lab-runtime/local-host/t31-scoped-output-0001 -p test_scoped.py -v` and repeat with `-O`. The tests use explicitly synthetic producer evidence and original typed ontology fixture bodies. They cover process-independent replay, scope preservation, exact producing Work/Run, orphan refusal, metadata and body tampering, a stage/claim mutation, recovery, currentness, attempted retagging, and the exact kernel predicate delta. They are component evidence; actual ontology capture and portable API integration remain separate qualifications.
