## Blocking finding: enforcement stops at the terminal event before release

`EventStream.poll()` appends selected events but executes `continue` when `terminal_index` is already set (`control.py:168-179`). `reconcile()` compares only `events[anchor_index + 1:terminal_index + 1]` to replay (`control.py:253-276`). In `run_case()`, the container terminal barrier is handled before the volume terminal barrier (`run_controller.py:321-329`), then final endpoint/inventory/manifest checks occur, both streams close, and only afterward are the writer container, keeper and volume cleaned (`run_controller.py:330-357`). During that interval the selected writer's stopped container still has an RW volume grant and the volume exists. The code comment that the event witness “remains active through the last identity/inventory check” is true only of process liveness; enforcement has already ended.

My inert [post-terminal counterexample](post_terminal_counterexample.py), SHA-256 `95d0c4be141a5bcab3684657f935acfb1fc342de95f3d57852dabd9c5731dfbe`, executes the exact hash-checked `control.py` bytes without Docker. After both terminal indices are set, it feeds a foreign container `create` and selected-volume RW `mount`. Each event is recorded, neither is refused by `poll()`, and `reconcile()` still returns success because both fall outside its slice. The outcome repeats under normal and `-O` Python. A foreign container created and removed after the **container** terminal event but before the **volume** terminal event can likewise evade the container slice; a create-only stopped RW grant has no volume mount event, and a later inventory can miss it. A transient post-terminal RW mount can evade the final inventory too. I did not create those Docker races on the host; the inert test proves the code path and the existing disposable suite does not cover it.

The controller should not claim exclusion from selection through cleanup or terminal disposition until it enforces and reconciles events over that full period, with a coherent common end boundary for container grants and volume mounts. Recheck against a post-barrier transient container grant and RW mount, including creation and removal between final inventories. If the protected release intentionally ends earlier, it must first show the writer grant is removed/sealed and no protected post-barrier effect or mutable archive remains; that is not the candidate's current sequence. A separately installed admission policy is still required against Docker-capable clients that do not honor this process's cooperative manifest `flock`.

The selected daemon, socket and current Docker administrator are trusted premises. Exact barrier replay can fail closed on missing/evicted history or mismatched live and replay slices; it does not prove the daemon cannot suppress events, that an unrelated API client cannot grant RW access, or that a future host clock/currentness, owner decision, protected family, issuer grants and native runtime closure exist.
