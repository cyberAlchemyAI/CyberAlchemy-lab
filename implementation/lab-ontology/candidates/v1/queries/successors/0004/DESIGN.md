The selected Python adapter answers the three written C1 questions from verified source bytes. Its query model has no write operation or authority effect. Every result is scoped to exact sources and obligations; a complete one-hop lineage answer does not claim complete repository coverage or implementation fulfillment.

## Inputs and scope

Before execution, `selection.py` freezes the adapter, contracts, source obligations and recorded development authorization. The caller supplies an independent selection digest. A request cannot supply a projection, an owner outcome, a schema, an admission override or executable code.

The D75 factory verifies the independently pinned coupling engine and creates a fresh owned temporary signed genesis solely to obtain its verified original source projection. It removes the store and key on exit. The local signature grants no canonical admission. Its temporary genesis signature is a verification witness, not part of the deterministic source cut. Both the actual selected HEAD and source hashes are checked during the open scope.

Contracts inspected from D75 retain their own epoch note; they do not supply reconstructed D73 type admission. The current D75 query uses the actual D75 state. Historical D73 cannot answer a current view. Exact revision labels are never silently aliased.

O05 queries separately validate the exact immutable adaptation manifest, 140 original source dispositions, source/selector witnesses and candidate carriers. A rebuilt original native executable with independently matched bytes reads the 88 semantic and 88 governance events in an owned temporary store. Exact rich carrier/event joins are verified. Fifty source-local interpretations remain separate from global Typed Relations. Nine unavailable original dependency revisions remain explicit. Original private source bodies are not exported.

Every selected subject appears exactly once as mapped, unresolved or excluded; classification does not establish domain truth. Schema/body mismatches and omitted contract nodes are returned as diagnostics with source bindings and a closing task. Query limits separately account for omitted frontier. Continuation guidance binds the same source cut; automatic cross-cut pagination is unavailable.

Profile-local edges require the selected O01 closed ordered signatures and exact qualifier keys. They are explicitly candidate profile interpretations with no canonical ontology admission. ## Freshness and deterministic reconstruction

Currentness checks source bytes, executable/profile/control closure, actual selected HEAD and scope lifetime. Missing, changed or unchecked evidence removes confirmed paths and returns a blocked current answer while retaining original historical observations. Closing/expiring a scope prohibits new consumption. Reconstruction must use a new scope and fresh process.

The three acceptance answers retain their original ceilings: D73 lifecycle is partial due to exact revision residue; D73 recorded admission is complete for its recorded effect; Capability one-hop derivation is complete while domain posture remains draft and implementation/effectiveness unassessed. Broader obligations return partial. Project semantic/governance history cursors cannot substitute for ontology cursors. Native O05 events establish only candidate-owned representation state.

The original `c1-query-contract.json` is empty. This package compiles a new candidate request/response contract from the exact written C1 source, records the empty historical binding and leaves it untouched. Rust graph acceleration is not selected. Python is normative; the existing native lifecycle library verifies original event joins only. No performance benefit is asserted.
