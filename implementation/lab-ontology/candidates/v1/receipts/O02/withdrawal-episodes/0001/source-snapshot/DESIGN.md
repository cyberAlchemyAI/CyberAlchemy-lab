Status: candidate implementation. Authority effect: none. Final exact review: S02/R08.

## Scope

The frozen D75 runtime owns signatures, source transaction effects and both Project histories. A new disposable scope permits only admission and withdrawal of the exact controlled Work in work.json. Its key is generated outside the repository and source store, mode 0600, and deleted with the owned root. Existing C11 provisioning remains admit-only. No existing store is selected.

The existing represented-subject adapter independently validates the original Work bytes, current carrier, schema, represented identity and rich Definition bindings. Its selected C12 catalog does not contain this fixture revision: that catalog posture remains candidate-unadmitted. A separate verified signed source-cut handle establishes local fixture posture. Neither posture is relabeled as repository admission.

## Mapping

Admit and withdraw require independent actual Ed25519 operator signatures and distinct Decision identities. Source cuts are independently pinned by config, baseline, executable manifest and HEAD. Full replay validates every original transaction, signature and consequence. The mapper joins source kind, carrier, exact revision, identity, original record digest, original admission transaction and source scope. Withdrawal must follow the exact mapped predecessor chain.

Each source effect appends governance on the unchanged exact native semantic tuple. Withdrawal makes current-source use ineligible, records provenance and a use constraint, and leaves the representation active and historically inspectable. It does not append a semantic retire/remove event. Representation retirement/removal is independently demonstrated by the earlier rich lifecycle episode.

Committed source retries and repeated mapping are idempotent. An uncertain native append blocks redispatch; observational original-byte reconciliation is required. This package provides cold reconstruction, not a generic automatic repair service.

## Reconstruction and boundaries

The public source archive contains original config, baseline, signed transactions, and exact HEAD bytes for both cuts. The native archive contains original semantic/governance events. A fresh process uses independently bound archive/witness/executable digests, replays both source cuts and the native cut, regenerates translation/governance joins, and compares exact views and histories. Archives contain no private key or Session memory. Cleanup is checked after both owned stores close.

New review members: exact source scope, fixture Work, source-effect reader, governance mapping and eligibility policy, implementation and validation closure. Generic API dispatch, signed Project/Product endpoint coupling, ontology adoption and actual owner authority remain downstream obligations.
