# Implementation layers

The design uses four evidence-gated layers. Each preserves earlier guarantees and unlocks a distinct decision. Implementation has not started under this design.

Boundary heuristic applied: layer value = decision unlocked + visible outcome + risk reduced; layer cost = implementation/verification/coordination burden. Stop a layer when another addition contributes less to its decision than the next layer. Shared host hardening can proceed independently, but it cannot qualify a later layer before its required evidence exists.

## Layer decision table

| Layer | After this layer, we know whether… | Minimum working unit | Visible outcome | Risk reduced |
| --- | --- | --- | --- | --- |
| **L0 — Exact local preparation** | The revised model can become a complete usable task Pack from exact explicit inputs without creating task-specific shared Definitions. | One INC-1042 source/context snapshot → strict decoder → four disposition handling → embedded application/available assessment → immutable Pack and human view. | A real executable local preview, clearly snapshot-only. | Semantic-to-wire fidelity, parameter mistakes, missing fields and one-off Definition proliferation. |
| **L1 — Repeatable live preparation** | The same kernel can use an actual selected authenticated Lab context and produce trustworthy fresh preparation across revisions. | One real host-backed capture → Pack → new input revision → recapture/refusal → fresh Session cleanup. | Current read-only preparation through the selected common runtime. | Parallel runtime drift, stale/mixed epochs, expired context, precision/transport and legacy regressions. |
| **L2 — Guarded materialization/review** | Selected reusable meanings can be faithfully materialized and independently reviewed without hidden admission. | One selected local meaning → complete Definition/v2 → host exact proposal/revalidation/checkpoint. | Revised definitions/examples and pending independent owner effects in one exact cohort. | Missing owner/profile standing, incomplete carriers, scope transfer, future hashes and unsafe partial selection. |
| **L3 — Qualified application and realization** | A separately authorized host can publish the exact selected result coherently and a new Session can reconstruct it. | Actual qualifying owner outcomes → native application/epoch commit → receipt/cold read-back → one genuine bounded Work outcome. | Durable selected knowledge and a qualified Define capability realization. | Lost/duplicated effects, mixed visibility, unrecoverable drafts, product claims without actual use. |

## L0 — Exact local preparation

- **Included:** exact public captured source/context with recorded historical freshness; strict same-byte decoding; bounded concepts and source refs; all four disposition branches; declared parameter bindings and explicit gaps; optional imported assessments; deterministic Pack/view/lineage/readiness; no-replace new output.
- **Deferred:** genuine native credentials/Sessions, current live-host readiness, complete Definition materialization, actual owner effects, governing publication, new Pack compilation, network/deployment and whole-Lab qualification.
- **Cost drivers:** executable schema closure, precise typed-value/source mapping, parameter interpretation, deterministic generation and focused controls.
- **Exit evidence to obtain:** working incident Pack with account/filter/snapshot/extraction boundaries; preserved FAIL and retry revision; open exclusivity remains explicit; malformed/stale/undeclared/duplicate/overflow controls; invalid output cannot appear conforming; no governing source/store/key changes.
- **Promotion:** continue to L1 when exact artifacts and controls show the model maps faithfully. Narrow if a contract cannot express the selected case without semantic change. Stop rather than manufacture parameter/owner/evidence declarations.

## L1 — Repeatable live preparation

- **Builds on:** unchanged L0 kernel and local contract/limits.
- **Added scope:** exact runtime profile and Host Port; current API17-protocol adapter; actual authorized Base context/session/source operations; installed byte/dependency closure; selected ontology view; freshness/expiry/recapture; old v1 protocol delegation and explicit new-Pack compile refusal.
- **Deferred:** actual shared admission and durable governing publication. Full composite is required only for the selected later operations, not inferred from a Base reader.
- **Cost drivers:** authenticated host/profile setup, source-provider compatibility, wire limits/currentness, actual lease performance and complete legacy compatibility evidence.
- **Exit evidence to obtain:** actual selected host source/profile/cut; original response bytes; permission/stale/expired/missing-operation refusals; repeated new revisions and resource cleanup; valid legacy run/chat/compile/resume results under their original scopes. Native incomplete qualification cannot be relabelled a live PASS.
- **Promotion:** proceed to L2 when current live preparation is qualified for its explicit selected scope. Fix host/provider dependencies where they actually block the operation; keep snapshot-only results inspectable without upgrading their freshness.

## L2 — Guarded materialization/review

- **Builds on:** L0/L1 source, parameter, output and session guarantees.
- **Added scope:** explicit materialization selections; complete Definition/v2 and field lineage; exact applicable schema/profile/source/fidelity/non-collapse/consumer requirements; separately scoped Source/Evidence/Work retention proposal if selected; existing change/review translation; independently revalidated one-checkpoint cohort.
- **Deferred:** actual owner selection, native application, current-State commit, stable release and domain execution.
- **Cost drivers:** complete field source/supplement mapping, profile standing and scope qualification, independent owner evidence, exact target core/postimage/recipe and privacy/retention review.
- **Exit evidence to obtain:** no selected task value leaks into reusable semantics; all full Definition fields are sourced; semantic changes are visible; wrong principal/role/scope/key and stale/changed target rejections; partial selection creates the required new cohort; actual owner outcomes remain absent in preparation.
- **Promotion:** proceed to the governing layer only when exact prerequisite owner/type/profile effects and current candidate/realization evidence permit that scope. A prepared review alone is not permission to apply.

## L3 — Qualified application and realization

- **Builds on:** all earlier exact source/protocol/semantic/evidence boundaries.
- **Added scope:** host-owned actual owner ingress, independent effect decisions, accepted representation/provider/binding changes, immutable epoch publication, Source/Evidence/Work retention where selected, recovery/read-back, final docs and genuine bounded user outcome. Complete realization binding precedes full candidate verification; documentation checks precede Product/adoption decisions as in the existing plan.
- **Deferred:** broader autonomous/domain execution, multi-host publication, universal ontology coverage, unbounded theorem claims, new Pack compiler and whole-Lab stable release.
- **Cost drivers:** shared native role/issuer/materializer/publisher dependencies, crash/uncertain-retry/recovery, source retention/cold visibility and real pilot support.
- **Exit evidence to obtain:** actual dependency-closed owner effects, exact committed epoch and receipt, independently verified cold read-back, expired old Session memory, reconstructed next Session, old history preserved, updated exact manifests/docs, qualified Product/realization/adoption evidence for this bounded capability.
- **Promotion:** adopt the exact Define successor only within its qualified scope. The whole-Lab stable release remains its own gate.

## Guarantee preservation

Every layer retains: one original byte capture per selected input; exact identity/version/digest/selector; candidate versus admitted standing; one disposition per concept; no undeclared parameter or implicit semantic change; optional assessments with independent provenance; no task-per-Definition files by default; no stale/fake owner authority; scoped evidence limits; immutable revision history; safe new output; ephemeral machine memory; existing legacy behavior.

## Recommended next layer

**L0.** It unlocks a useful executable preview with exact source input and honest gaps while shared native/session/publication work continues. Its explicit snapshot-only result must be preserved as such; L1, not L0, establishes real host integration.

## Remaining external decisions/effects

The technical design choices are proposed here. The already reviewed semantic/profile prerequisite effects, actual native owner/issuer scope, representation adoption, optional durable Pack retention targets and exact CLI adoption remain separately unselected. Naming them in the design does not appoint an owner or grant an effect.
